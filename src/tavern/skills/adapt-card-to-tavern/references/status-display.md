# 将正文状态栏迁移为独立变量

适用于要求游玩模型反复填写 HTML 面板、Markdown 表格或固定标签状态块的卡片，包括只有开场示范、没有 MVU 的卡。目标是：模型写叙事，授权变量任务用 patch_state 更新 stat_data，项目 MVU 区通过读取状态的 HTML 前端显示原面板。两种模式共用本流程，无需另选模式。先读取 references/regex-display.md，掌握正则挂载、状态读取及展示测试契约。

## 范围与识别

完整读取角色字段、世界书、全部开场、示例和相关正则/脚本。检查真正要求重复输出的来源，不只清理开场：常驻“状态栏”条目、后置要求、示例都可能继续诱导输出。诊断只识别部分表面特征，缺少警告不能证明已适配；不要为了清除警告盲目删内容。

普通 HTML 排版、一次性说明、以及由程序读取 MVU 的展示不等于正文状态栏。保留有用的叙事、宏、资源、schema、校验回调和用于隐藏旧变量块的正则。不要把整段 HTML 改标为 tracker_mvu，它仍会诱导变量任务生成界面。默认保留原卡有用的视觉设计，把静态模板改成读取 stat_data 的前端，写入展示正则；项目变量区会挂载它，不会自动生成原 HTML。只有用户明确要求去掉自定义前端、仅保留变量树时，才省略展示脚本。不能把“使用项目变量面板”理解为授权删除原前端，也不能继续让模型抄模板。

明确要求“迁移/改造正文状态栏”包含处理开场中的同类可见示范；已由正则从模型文本剥离、且能被 Runtime 正确读取的内联初始化/特殊数据必须保留，它们不是需要模型逐轮抄写的状态栏。先按 references/workflow.md 核对实际隐藏通道和初始化来源；不能仅凭原始 first_mes 中有标签就删除。普通“适配项目”仍默认保留开场，用户明确要求开场不动时遵从。

## 先建立字段语义，再编辑

为每项状态确定：含义与归属、类型、原文来源、初值、变化依据、未知值表示及清空条件。短字段用清晰业务名称，避免复制 HTML/CSS 到状态。已有变量系统以原路径、schema 和初始化顺序为准。

- 字面值、宏引用、装饰性进度条和模板占位符要分开。getvar/getglobalvar 按状态根路径读取；迁入 stat_data 后保留的模型宏需使用实际路径，例如 `{{getvar::stat_data.诊所.时间}}`。宏本身不创建或更新变量。
- 不凭“余额 0”推断总资产/本日收入，不凭“width:45%”发明生命值计算公式。可以保留有来源的数值和描述，但含义不明时记录待确认项；未知不擅自填 0。缺失初值不能靠编造补齐。
- 静态人物/世界设定留在 writer；影响剧情的营业、顾客和治疗规则也留在 writer。tracker_mvu 只描述变量定义、更新条件、范围、关联与重置，不要求正文输出结构块。
- 传闻、任务、顾客和事件由叙事引入；后台仅提取已出现内容，区分传闻与事实，不为填满面板生成新剧情。客人离开或更换时明确哪些字段清空，不能继承上位客人的伤情。
- 保留玩家与模型的角色分工；卡内的“用户身份”不授权读取或创建用户角色库。

## 拆分与迁移

1. 用 patch_draft 去掉字段/世界书中的重复输出命令与模板，保留混合条目的叙事，必要时拆成 writer 和 tracker_mvu。新条目省略 ID；保留无关条目的启停状态。
2. 根据已确认的语义写更新规则：只在已发生的剧情有依据时改变，无变化提交 []。收费与实际到账、意向与完成等不能混同。不复制工具 schema，不要求额外模型或每轮强制更新权限。
3. 先沿用有效的 `[InitVar]` 世界书初值、各开场 `<initvar>` 全量覆盖及其隐藏正则。仅存在于待迁移面板中的事实需补入有依据的初值或叙事位置；没有初始化时，共用默认值优先用 `[InitVar]` 条目，开场专属完整对象可放内联 `<initvar>` 并配隐藏规则。用 set_opening 修改 narrative 时保留有效数据块，通常省略 initialization；独立 initialization 只用于明确抽离或已确认兼容问题，不再是迁移的固定步骤。
4. 全部开场分别核对，禁止用默认开场的患者/时间覆盖其他开场。完整 `<initvar>` 替换世界书而不补缺，增量指令另有基准与执行条件；按 references/workflow.md 检查冲突、缺字段、坏格式、失效正则和重复数据来源。有歧义时保留并报告，程序管理身份、关联和指纹。模板宏保留字面形式，不在编辑时替换成临时玩家名。
5. 将原展示模板迁入 extensions.regex_scripts，使用仅 display 的助手输出规则挂载 HTML，绑定实际 stat_data 路径；不要依赖正文中的补丁块或占位符。完成挂载再核对开场清理结果；只删除 HTML 并迁入初值不算完整迁移。已删除模板可从 read_field 的 saved/round_start 或 read_history 完整取回，不凭记忆重造。
6. 清理相关示例中的重复展示要求，保留语言风格。无法可靠迁移的动态脚本和存在歧义的字段保留为明确待办，不靠禁用全部脚本完成适配。

## 验收与交付

运行 validate_draft；对每个受影响开场运行 test_draft，核对实际 stat_data 与预期语义、类型及初值一致。保留前端时必须按 references/regex-display.md 提供纯叙事样例、display_assertions 和 state_patch/after_text，检查开场、后续正文的展示及变量变化后的 DOM 值，确认 HTML 不进入 model 通道。检查变更后的完整字段，确认输出命令、模板及开场示范均在授权范围内处理，叙事资料未遗漏。只检查默认开场不能代表所有开场。

test_draft 不发起模型回合，也不验证最终模型上下文、叙事质量或完整视觉交互。不能报告这些范围已通过；实际游玩还需检查正文不再生成状态栏、授权变量更新后面板随状态变化、未授权时不写变量。卡片编辑不迁移已有故事快照，应在新故事验证。

报告字段映射、初值来源、开场改动、静态与本地运行检查结果、未决歧义；工具仅修改草稿，等待用户审阅保存。必要澄清只针对缺失语义，已经授权的迁移不重复要求确认。
