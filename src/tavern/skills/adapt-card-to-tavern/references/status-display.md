# 将正文状态栏迁移为独立变量

适用于要求游玩模型反复填写 HTML 面板、Markdown 表格或固定标签状态块的卡片，包括只有开场示范、没有 MVU 的卡。目标：模型只写叙事，授权变量任务用 `patch_state` 更新 `stat_data`，原面板改为读取状态的前端，由展示正则挂载到项目 MVU 区。开始前读取 `references/regex-display.md`。

## 识别范围

1. 完整读取角色字段、世界书、全部开场、示例和相关正则与脚本，找出真正要求重复输出的来源：常驻“状态栏”条目、后置要求和示例都可能持续诱导输出，不只开场。
2. 以下不属于正文状态栏，保持原样：普通 HTML 排版、一次性说明、由程序读取 MVU 的展示、已被正则从模型文本剥离并能被正确读取的初始化数据。
3. 诊断只识别部分表面特征，是定位线索；为清除警告而删内容不算适配。变量宏和填好数值的面板都不等于已建立变量系统。
4. 用户明确要求“迁移/改造正文状态栏”时，范围包含开场中的同类可见示范；普通“适配项目”仍保留开场，用户要求开场不动时遵从。

## 建立字段语义

先为每项状态确定含义与归属、类型、原文来源、初值、变化依据、未知值表示和清空条件，再动手编辑。已有变量系统以原路径、schema 和初始化顺序为准。

- 字面值、宏引用、装饰性进度条和模板占位符分开处理。迁入 `stat_data` 后保留的模型宏改用实际路径，例如 `{{getvar::stat_data.诊所.时间}}`。
- 含义要有来源：不凭“余额 0”推断总资产或本日收入，不凭 `width:45%` 发明生命值公式。含义不明时记录待确认项，未知值不填 0。
- 传闻、任务、顾客和事件由叙事引入；后台只提取已出现的内容，区分传闻与事实。客人离开或更换时写明哪些字段清空，避免继承上一位客人的伤情。
- 卡内的“用户身份”字段描述玩家定位，不涉及用户角色库。

## 迁移步骤

1. **拆分**：用 `patch_draft` 去掉字段和世界书中的重复输出命令与模板，混合条目保留叙事，必要时拆成 `writer` 与 `tracker_mvu` 两条。新条目省略 ID，无关条目的启停状态不变。整段 HTML 不标为 `tracker_mvu`，否则会诱导变量任务生成界面。
2. **写规则**：按已确认的语义写更新规则（写法见 `runtime-guide.md`）。
3. **补初值**：先沿用有效的 `[InitVar]` 条目、各开场 `<initvar>` 及其隐藏正则。只存在于待迁移面板中的事实，补入有依据的初值：共用默认值放 `[InitVar]` 条目，开场专属的完整对象放该开场的 `<initvar>` 并配隐藏规则。
4. **逐开场核对**：按 `references/workflow.md` 的清单检查每个开场。模板宏保留字面形式。
5. **挂载前端**：默认保留原卡的视觉设计，把静态模板改成读取 `stat_data` 的前端，按 `references/regex-display.md` 写入 `extensions.regex_scripts`。展示正则是 MVU 卡的必备要素，不因迁移而省略；“使用项目变量面板”指挂载到 MVU 区，原前端仍保留。已删除的模板用 `read_field` 的 `saved`/`round_start` 版本或 `read_history` 完整取回。
6. **清理开场与示例**：挂载完成后，用 `set_opening` 去掉开场中的可见状态示范，保留有效数据块；清理示例中的重复展示要求，保留语言风格。
7. 无法可靠迁移的动态脚本和有歧义的字段列为明确待办。

## 验收

1. `validate_draft`；对每个受影响的开场运行 `test_draft`，核对实际 `stat_data` 的语义、类型与初值。
2. 按 `references/regex-display.md` 提供纯叙事样例、`display_assertions` 与 `state_patch`/`after_text`，检查开场、后续正文和变量变化后的 DOM，确认 HTML 不进入模型通道。
3. 回读变更后的完整字段，确认输出命令、模板和开场示范已处理，叙事资料没有遗漏。

报告中列出仍需在新故事中实际游玩确认的项：正文不再生成状态栏、授权变量更新后面板随之变化、未授权时变量不变。已有故事的快照不随卡片迁移。

报告字段映射、初值来源、开场改动、检查结果和未决歧义。需要澄清时只问缺失的语义，已授权的迁移不重复确认。
