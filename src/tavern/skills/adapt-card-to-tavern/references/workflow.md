# 初始化与开场核对

适配时按本清单核对已有卡的初始化来源、开场原文和隐藏正则。各来源的语义见 `runtime-guide.md` 的“初始化”和“正则与通道”。

## 保留规则

1. **已有正常实现原位保留**。`[InitVar]` 条目、开场 `<initvar>` 完整覆盖都是合法来源，非标准来源才按 `runtime-guide.md` 的“非标准初始化”改写；合法来源不为“规范化”而搬运、改名或合并。`[InitVar]` 条目保持原启停状态，不改成常驻 `writer` 条目；需要向变量任务提供其中的变量说明和更新依据时可标记 `tracker_mvu`，已有标记保留。该标记不影响初始化，条目关闭后仍向变量任务提供完整正文。
2. **开场中的初始化数据与隐藏正则一起保留**。能被正确读取、又已从模型文本剥离的特殊数据是初始化来源，不是需要清理的脏数据；正文状态栏迁移也保留它们。
3. **按开场区分是合法差异**。多个开场有不同时间、人物或资产时，各自保留，不以默认开场统一其他开场。
4. **出问题时修根源**。正则漏匹配先修规则，数据格式错误先修数据，源数据始终保留。
5. 需要修改开场时用 `set_opening` 传完整 narrative，带回应保留的数据块。

## 核对清单

对每个开场（包括未选中的开场）逐项检查：

1. 标签成对，内容是可解析的 YAML/JSON 对象。
2. 变量路径、类型与 schema 一致。
3. 完整 `<initvar>` 覆盖没有漏掉必需字段。
4. 增量指令有明确基准，并确实由脚本执行；用 `test_draft` 看实际状态。
5. 多个初始化来源的重复路径是有意覆盖；有歧义就保留并报告，不拼成混合开局。
6. 未知值没有被擅自补成 0。
7. 隐藏正则实际命中：在 `test_draft` 中检查 `output_model` 与 `output_display`。

无法确定的动态逻辑保留原状，列为未完成项。

## 兼容边界

当前宿主不是完整的 SillyTavern：本项目使用角色卡世界书与会话作用域，ST 全局或额外世界书的加载行为不在承诺范围内。正则语义参考 [ST 正则说明](https://docs.sillytavern.app/extensions/regex/)。
