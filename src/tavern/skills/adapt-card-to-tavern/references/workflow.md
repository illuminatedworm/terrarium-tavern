# 工作流与数据契约

Half Agent 的 Writer 生成叙事和检索线索；Tracker 的独立 MVU 任务接收当前变量、最近 6 条历史、本轮输入/正文与全部启用变量规则。Full Agent 在同一循环内处理叙事与变量，当前有效上下文首次授权更新变量时追加全部启用规则，同版本不重复，换窗或重建后按需补入。两者均须勾选“本轮更新变量”才允许 patch_state；通过工具提交相对于 stat_data 的 JSON Patch，如 `[{"op":"replace","path":"/能量","value":4}]`，无变化提交 []。变量结果不进入正文，最终由 Runtime 原子提交。

世界书原始条目用途写入 `extensions.terrarium.audience`：
- `writer`：普通叙事设定，默认值；沿用常驻和检索规则。
- `tracker_mvu`：定义、更新条件与约束；授权变量任务完整加载全部启用条目，不受关键词、概率或检索排名过滤。规则和宏值在任务开始时固定，修改从后续任务起生效；保留在 Full Agent 历史中的规则不授予后续回合修改权限。
- `runtime_init`：InitVar YAML 数据，只供确定性初始化；不进入模型请求。未带 `[InitVar]` 标记时，禁用条目不初始化；传统 `[InitVar]` 条目遵循 MVU 约定，禁用也会读取。

## 初始化来源与保留规则

MVU 是社区框架，以下依据其固定上游实现与教程，不能把某份社区制卡模板当成所有卡都必须采用的唯一格式。

- 通用初值优先沿用世界书名称含 `[InitVar]` 的条目（大小写不敏感）；内容是 YAML/JSON 对象，允许支持的标签或代码块包裹。关闭条目只关闭常规提示注入，MVU 仍会读取。不要为初始化把它改成常驻 Writer 条目，也不要误标为 tracker_mvu。项目额外支持 runtime_init，已有此类条目保留，不为改名机械搬运。
- 各开场可保留自己的 `<initvar>...</initvar>` **完整对象**。它整体替换角色卡世界书初值，缺少的字段不会递归从世界书补齐。这正是上游支持不同开局的机制，不因开场包含结构化数据就视为脏数据或删掉。
- 同一来源的多个初始化块按顺序合并，同名后值覆盖，数组整体替换。多个条目/块可能是有意拆分，不自动判错、排序或合并。核对重复路径是否有意覆盖；有歧义就保留并报告，禁止擅自拼成混合开局。
- 上游还支持在基准初值之后应用开场 `<UpdateVariable>` 指令（或支持的 JSON Patch）。它是**增量修改**，与 `<initvar>` 的全量替换不同。本项目内置路径目前只自动读取原文 `<initvar>`；原文中的增量指令不会因此自动执行，只有卡片脚本明确处理时才生效。必须用 test_draft 核对实际状态；确需适配时按已知语义修复标准初值或脚本，保留原文和隐藏正则，不宣称已完整兼容任意上游脚本。

已初始化的故事不会因改卡重演初值。新卡的共用默认值可用 `[InitVar]` 世界书条目；不同开场的完整初值用内联 `<initvar>` 加正确隐藏正则。已有正常实现优先原位保留，不为了“规范化”引入项目独有元数据。

## 开场原文与模型/展示文本

卡内 `extensions.regex_scripts` 的 `placement:[2]` 作用于助手文本（含开场）。`promptOnly:true,markdownOnly:false` 只改模型提示；`markdownOnly:true,promptOnly:false` 只改界面；两者均 true 时两条通道都处理。还要检查 enabled/disabled、匹配表达式、规则顺序及深度条件；名称叫“隐藏变量”并不等于实际命中。

本项目先从保留的原始开场读取初始化，再应用正则生成 model/display，原文不被清空。**能被正确读取、又已从模型文本剥离的特殊数据和对应正则必须保留**，正文状态栏迁移也不例外。仅 UI 隐藏不能证明模型看不到；请在 test_draft 中检查 output_model 与 output_display 的实际结果。正则漏匹配优先修规则，数据格式错误优先修数据；不能用删源数据的方法让检查“干净”。

普通适配默认不修改开场。明确迁移正文状态栏时，只处理要求模型抄写的可见模板及相应叙事要求，按 `references/status-display.md` 保留其事实与视觉设计；这不授权删除有效内联初始化。用 set_opening 修改 narrative 时带回完整且应保留的数据块。不要另建开场关联记录、初值副本或覆盖元数据。

## 异常检查

完整读取所有初值来源、全部开场、隐藏/展示正则和相关脚本，逐开场核对：标签成对、YAML/JSON 可解析且为对象、变量路径/类型/schema 一致、全量覆盖是否漏掉必需字段、增量是否有基准并确实执行、重复初始化来源是否冲突、未知值是否被擅自补成 0。未选中的开场也可能损坏，不因当前开场通过就略过。多个完整开场有不同时间、角色或资产是合法差异；不按默认开场统一它们。无法确定的动态逻辑保留并列为未完成项。

当前宿主不等于完整 ST：本项目依赖角色卡世界书与会话作用域，不据此承诺 ST 全局/额外世界书的全部加载行为。引用版本与兼容边界见 [上游初始化实现](https://github.com/MagicalAstrogy/MagVarUpdate/blob/4a3645f19705e9e73bb4df3a8e731d5ff994ce80/src/function/initvar/variable_init.ts)、[上游教程](https://github.com/MagicalAstrogy/MagVarUpdate/blob/4a3645f19705e9e73bb4df3a8e731d5ff994ce80/doc/tutorial.md)、[ST 正则说明](https://docs.sillytavern.app/extensions/regex/)。

JSON Patch 工具路径相对于角色卡完整文档；有 spec 的卡使用 /data/...。世界书支持数组和对象，使用工具返回的 JSON Pointer，其中 @D 短编号由程序恢复为原键。保留未知扩展字段、资源引用、开场顺序；身份及隐藏的指纹由程序保留。新增世界书条目省略ID。不要禁用所有脚本来通过检查：schema 和校验回调可能仍为必需。

HTML/MVU 前端的存储、正则通道、状态读取及验证见 references/regex-display.md。正则处理正文，前端读取已提交快照；补丁记录不是正则输入。迁移保留原前端，除非用户明确只要变量树。

完成判定：展示正则及状态绑定已通过对应测试（用户明确不要前端时除外），叙事、变量规则与初始化数据已正确分流，世界书初始化数据未丢失，无待处理问题。开场及其有效 MVU 数据默认不改写，但初始化来源、实际状态与隐藏效果仍须核对；明确的正文状态栏迁移另需核对相关可见示范和前端。`validate_draft` 对两种模式采用同一检查，输出疑似状态栏及初始化/规则来源的提示；无警告也无法证明语义等价或完整适配。报告中必须区分静态检查与实际运行验证。
