# 工作流与数据契约

Half Agent 的 Writer 生成叙事和检索线索；Tracker 的独立 MVU 任务接收当前变量、最近 6 条历史、本轮输入/正文与全部启用变量规则。Full Agent 在同一循环内处理叙事与变量，当前有效上下文首次授权更新变量时追加全部启用规则，同版本不重复，换窗或重建后按需补入。两者均须勾选“本轮更新变量”才允许 patch_state；通过工具提交相对于 stat_data 的 JSON Patch，如 `[{"op":"replace","path":"/能量","value":4}]`，无变化提交 []。变量结果不进入正文，最终由 Runtime 原子提交。

世界书原始条目用途写入 `extensions.terrarium.audience`：
- `writer`：普通叙事设定，默认值；沿用常驻和检索规则。
- `tracker_mvu`：定义、更新条件与约束；授权变量任务完整加载全部启用条目，不受关键词、概率或检索排名过滤。规则和宏值在任务开始时固定，修改从后续任务起生效；保留在 Full Agent 历史中的规则不授予后续回合修改权限。
- `runtime_init`：InitVar YAML 数据，只供确定性初始化；不进入模型请求。未带 `[InitVar]` 标记时，禁用条目不初始化；传统 `[InitVar]` 条目遵循 MVU 约定，禁用也会读取。

开场 `<initvar>` 是完整初值，覆盖角色卡世界书初始化，不递归补齐遗漏字段。没有开场 `<initvar>` 时使用世界书初值；已有初始化记录不自动重演。不能为兼容迁移而开启传统 `[InitVar]` 条目的模型注入。

开场及其内联 MVU 默认保持原样，不属于本适配流程的完成条件。原卡用于从模型提示中隐藏变量块、初始化变量或渲染状态栏的正则也应保留。只有用户明确要求迁移开场时才向 `set_opening(card_ref,index,narrative,initialization)` 提供初始化参数；迁移前必须读取全部开场与已有独立初始化，并保留模板宏和初始化顺序。稳定身份和内容指纹由程序管理，不得猜测、计算或回写。

JSON Patch 工具路径相对于角色卡完整文档；有 spec 的卡使用 /data/...。世界书支持数组和对象，使用工具返回的 JSON Pointer，其中 @D 短编号由程序恢复为原键。保留未知扩展字段、资源引用、开场顺序；身份及隐藏的指纹由程序保留。新增世界书条目省略ID。不要禁用所有脚本来通过检查：schema 和校验回调可能仍为必需。

完成判定：叙事、变量规则与初始化数据已正确分流，世界书初始化数据未丢失，无待处理问题。开场及其 MVU 内容默认不纳入完成判定。`validate_draft` 对两种模式采用同一检查，无法证明任意脚本的语义等价，报告中必须区分静态检查与实际运行验证。
