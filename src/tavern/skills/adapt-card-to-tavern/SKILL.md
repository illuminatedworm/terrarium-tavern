# 适配角色卡

适配把已有卡的数据分流到本项目契约：叙事交给游玩模型，变量规则交给 `tracker_mvu`，初值交给确定性初始化，状态展示交给正则前端。两种游玩模式共用同一流程。

## 读取顺序

1. `runtime-guide.md`：世界书用途、初始化来源、规则写法、正则通道。
2. `references/workflow.md`：初始化与开场的保留规则和核对清单。
3. `references/status-display.md`：卡片要求模型逐轮输出 HTML、Markdown 表格或固定标签状态块，或用户要求迁移这类展示时读取。
4. `references/regex-display.md`：制作、保留或迁移状态前端时读取。

## 步骤

1. **读取**：先 `overview`，再完整读取角色字段、世界书、全部开场、示例、正则与脚本。资料很多时逐个读完必要字段，先完成一个一致的子集，未完成项留到下一轮。
2. **分流世界书**：用 `patch_draft` 为每个条目标记用途。混合条目拆分：原条目保留叙事，新规则条目省略 ID；需要 `split_from` 时只用读取工具给出的短编号，程序恢复真实关联。初始化条目保留原数据与 schema。存在初始化时按 `runtime-guide.md` 的“规则条目要求”确保有有效的 `tracker_mvu` 条目。
3. **改写输出要求**：检查角色字段、`system_prompt`、`post_history_instructions`、示例和常驻条目，删除或改写要求游玩模型在正文中输出变量块或状态栏的指令。规则条目按 `runtime-guide.md` 只保留变量语义。
4. **保留运行部件**：隐藏既有变量块的正则、开场展示正则、schema 注册、校验与更新回调、宏和资源原样保留。
5. **开场**：普通适配不修改 `first_mes`、候选开场及其中的初始化或更新块，不调用 `set_opening`。用户明确要求迁移正文状态栏时，按 `references/status-display.md` 处理开场中的可见示范。
6. **脚本**：不猜测复杂动态脚本产生的初值，也不把 arbitrary JavaScript 改写为初始化数据。无法可靠迁移的逻辑保留原状，列为人工核对项。
7. **验证**：`validate_draft` 并修复可确定的问题；新增初值或机制时运行 `test_draft`；涉及前端时按 `references/regex-display.md` 提供 `display_assertions` 与 `state_patch`。核对返回的实际状态，工具无异常不等于语义正确。
8. **报告**：逐项列出改动、涉及条目、开场是否修改、静态检查与本地运行结果、未覆盖范围和待处理项。

## 完成判定

同时满足以下各项才报告适配完成，否则报告为部分适配并列出剩余项：

- 叙事、变量规则与初始化数据已正确分流，世界书初始化数据完整；有初始化即有有效的 `tracker_mvu` 规则条目。
- 每个开场的初始化来源、实际状态与隐藏效果已核对（见 `references/workflow.md`）。
- 展示正则与状态绑定已通过对应测试；用户明确只要变量树时除外。
- 无待处理问题。

工具只编辑草稿，原卡由用户在差异页审阅保存。
