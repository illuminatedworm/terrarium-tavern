# 变量、正则与脚本

新增或修改变量、状态展示、正则或脚本时读取本指引；适配已有卡时由 `SKILL.md` 引导至此。HTML/MVU 前端的可执行配方与测试见 `references/regex-display.md`；两种游玩模式如何执行这些机制见 `half-agent.md`、`full-agent.md`。

## 与 SillyTavern 的异同

本项目 Runtime 兼容 SillyTavern（ST）的角色卡格式、世界书、MVU 初始化、`regex_scripts`、变量宏、Tavern Helper/MVU 脚本接口和 HTML 前端，但变量机制不同。网上的卡片和教程按 ST 编写，照搬前先对照以下差异：

| 方面 | ST 常见做法 | 本项目 |
|---|---|---|
| 变量更新 | 模型在正文中输出 `<UpdateVariable>`、`_.set` 或状态栏，再由脚本或正则解析 | 正文只写叙事；授权的变量任务用 `patch_state` 提交相对 `stat_data` 的 JSON Patch，正文和正则都不解析变量 |
| 更新范围 | 几乎每轮无条件全量重写 | 只改有剧情依据变化的路径，其余保持旧值；变量任务在用户勾选“本轮更新变量”时才运行 |
| 规则来源 | 写在预设、常驻条目或正文要求里 | 只有 `tracker_mvu` 条目交给变量任务（本项目约定） |
| 正则 | 兼顾解析变量、清理正文、生成界面 | 不解析变量；用于从模型文本剥离数据块和生成最终展示 |
| 渲染 | 酒馆与插件各自处理 | 正则后的展示文本按纯文本、Markdown、HTML 原样渲染，不兜底或降级，错误直接暴露 |

模式差异（如脚本额外模型请求只在 Half Agent 可用）见各模式文档。

## MVU 卡的三项要素

卡片只要涉及 MVU（存在初值、变量规则、MVU 脚本、读取 `stat_data` 的宏或前端，或要求模型输出变量块、状态栏），无论原来如何实现，完成时都必须同时具备：

1. **标准初始化**：初值来自上游标准形式（见“初始化”）。
2. **变量规则**：变量含义与更新规则写在变量任务会读取的 `tracker_mvu` 条目中（见“变量规则”）。
3. **展示正则**：生成最终渲染文本的正则，可以有多条（见“正则与展示”）。

缺任何一项都不能报告完成，要列为剩余项。

## 设计顺序

1. **列变量**：每项写明含义与归属、类型、初值及来源、变化依据、能否保持旧值、取值范围、未知值表示和清空条件。
2. **写初值**：共用初值放 `[InitVar]` 世界书条目；不同开场需要不同初值时，在该开场原文写完整 `<initvar>`，并加隐藏正则。
3. **写规则**：新建启用的 `tracker_mvu` 条目，写变量含义、触发条件、范围、关系和校验要求。
4. **写叙事设定**：影响剧情的世界机制（营业规则、战斗规则等）留在 `writer` 条目或角色字段。
5. **做展示**：按 `references/regex-display.md` 写展示正则。
6. **验证**：运行 `validate_draft`，再对每个受影响的开场运行 `test_draft`。

## 世界书用途

用途写在条目的 `extensions.terrarium.audience`：

| 用途 | 内容 | 运行时行为 |
|---|---|---|
| `writer`（默认） | 人物、世界和叙事设定 | 按常驻与检索规则注入游玩请求 |
| `tracker_mvu` | 变量含义、变化条件、范围、关系和约束 | 授权变量任务完整提供全部启用条目及关闭的 `[InitVar]` 条目，不经关键词、概率或检索排名；规则和宏值在任务开始时固定，修改从后续任务生效 |

## 初始化

MVU 是社区框架，以下依据其固定上游实现与教程（[初始化实现](https://github.com/MagicalAstrogy/MagVarUpdate/blob/4a3645f19705e9e73bb4df3a8e731d5ff994ce80/src/function/initvar/variable_init.ts)、[教程](https://github.com/MagicalAstrogy/MagVarUpdate/blob/4a3645f19705e9e73bb4df3a8e731d5ff994ce80/doc/tutorial.md)）。社区模板各有写法，以下各种合法形式都要识别。

- **世界书初值**：条目标题含 `[InitVar]`（不区分大小写），正文是 YAML/JSON 对象，可用支持的标签或代码块包裹。初始化只看该标记，不受条目启停或用途限制。
- **开场初值**：开场原文中的 `<initvar>…</initvar>` 是该开场的**完整对象**，整体替换世界书初值，缺少的字段不会从世界书补齐。
- **合并**：同一来源的多个初始化块按顺序合并，同名时后者覆盖，数组整体替换。
- **增量指令**：上游支持在初值之后执行开场中的 `<UpdateVariable>` 或 JSON Patch 增量。本项目只自动读取 `<initvar>`；增量只在卡片脚本处理时生效，用 `test_draft` 核对实际状态，无脚本处理时与用户商定。
- 已开始的故事不会因改卡重演初值，修改初值后在新故事中验证。

示例：共用初值写在一个关闭的条目里，标题为 `[InitVar] 初始状态`：

```yaml
旅店:
  余额: 120
  客房: 3
林默:
  好感: 0
```

“旅店遭砸”开场需要不同初值，在该开场原文末尾写完整对象（两个顶层键都要写全）：

```text
……门板在你身后哐当倒下。
<initvar>
旅店: {余额: 40, 客房: 0}
林默: {好感: 0}
</initvar>
```

并在 `extensions.regex_scripts` 追加一条同时作用于模型与界面的隐藏正则：

```json
{"scriptName": "隐藏开场初值", "findRegex": "/<initvar>[\\s\\S]*?<\\/initvar>/gi", "replaceString": "", "placement": [2], "disabled": false, "markdownOnly": true, "promptOnly": true}
```

### 非标准初始化

社区卡的初始化常常不标准。以下做法发现时要提醒用户，并改成上述标准形式：

- 初值只出现在开场、示例或状态栏模板的展示值里；
- 开场用 `<UpdateVariable>`、`_.set` 或 JSON Patch 从空状态“设置”全部初值；
- 用 `{{setvar::}}` 等宏写初值；
- `[InitVar]` 标记不在标题、正文不是对象，或初值写在角色字段、`creator_notes`、扩展字段里。

改写时保留原值和路径，值有歧义的不擅自补齐，未知值不填 0。改写后去掉原处的初始化作用，叙事和展示内容保留，避免两处初值。脚本动态生成的初值不猜测：保留脚本，用 `test_draft` 观察实际状态，无法确定的列为待确认项。

## 变量规则

### 规则条目要求

只要存在初始化，就必须有变量任务会读取的非空 `tracker_mvu` 条目（启用，或关闭但标题含 `[InitVar]`）。只带 `[InitVar]` 而未标记的条目只参与初始化；只有数值的初值不算规则。按现状处理：

1. **新建变量**：写初值的同时新建启用的 `tracker_mvu` 条目。
2. **已有有效规则条目**：沿用，只为新增或改动的变量补规则。
3. **有规则但未标记**：条目只含变量说明与更新规则时，只补标记；与叙事混写时拆出规则条目；`[InitVar]` 条目含变量说明或 `[值, 描述]` 时可直接标记，启停不变。
4. **已标记但不被读取**：关闭且标题无 `[InitVar]` 的条目不提供给变量任务，按作者意图启用，不明确时询问用户。
5. **没有可用规则**：新建启用的 `tracker_mvu` 条目并写全规则；依据不足的变量写明已知部分，列为待确认项。

### 局部更新语义

补丁只写有剧情依据变化的路径，没写的值保持原样，所以规则要为每个值讲清：

- 什么事件改变它，什么情况下保持旧值不变；
- 是否会清空或重置（如客人离开后清空伤情、换天后重置当日收入）；
- 随时间变化的值按剧情时间推进写条件，不写“每轮 +1”。变量任务不是每轮都运行，规则不能依赖逐轮执行。

ST 卡里“每次回复都更新全部变量”“末尾输出完整状态”之类的要求，改写成上述按事件更新的条件。

### 写法

规则只写业务语义。示例（`tracker_mvu` 条目正文）：

```text
旅店.余额：整数，单位铜币。客人实际付款后增加，采购或修缮实际支出后减少；报价、赊账不改变余额。
林默.好感：0–100 的整数。{{user}} 的言行明显触动林默时增减 1～5，同一事件只计一次；无相关互动时保持不变。
```

- 区分意向与完成、收费与到账；只在已发生的剧情有依据时改变变量。
- 工具 schema、独立助手身份和纯 JSON 回复格式由运行时协议决定，社区卡规则里的这类内容删去即可。
- 旧式 `[值, 描述]` 变量保留原结构：宏取值写 `stat_data.hp.0`，补丁指向 `/hp/0`。普通数组保持完整结构，不把两项数组一律当作值与描述。

## 正则与展示

### 通道

卡内 `extensions.regex_scripts` 的 `placement` 中，1 作用于用户输入，2 作用于助手文本（含开场）。

| `promptOnly` | `markdownOnly` | 作用 |
|---|---|---|
| true | false | 只改模型上下文 |
| false | true | 只改界面 |
| true | true | 两条通道都改 |

Runtime 先从原始开场读取初始化，再按顺序执行全部启用的正则，生成模型文本与展示文本，原文保持不变。界面上看不到不代表模型看不到，用 `test_draft` 的 `output_model` 与 `output_display` 检查实际结果。还要核对 `disabled`、匹配表达式、规则顺序和深度条件；名称不能证明规则实际命中。正则语法与前端写法见 `references/regex-display.md`。

### 展示正则

- 生成最终展示文本的正则可能有多条：分别挂载不同面板、区分开场与后续回复、按深度显示等。已有规则全部保留，逐条核对命中与先后顺序。
- 展示文本可以是纯文本、Markdown 或 HTML。Runtime 不改写正则输出：助手消息中脚本读取 `stat_data`、`getMvuData` 或 `getAllVariables` 的 HTML 片段放到 MVU 区，其余内容留在消息原位置。
- 输出不兜底、不降级：标签错误、脚本异常、变量路径错误都会原样暴露在界面上，所以要用 `test_draft` 逐开场验证。

### 变量宏

MVU 是变量系统，展示形式可选，已有的文字、Markdown 或纯 HTML/CSS 展示可以继续使用。

- 文字和 Markdown：`{{format_message_variable::stat_data.旅店.余额}}`（字符串原文，其他值 YAML）或 `{{get_message_variable::stat_data.旅店.余额}}`（其他值 JSON）；作用域还支持 chat、character、preset、global。宏递归省略 `$` 前缀字段，缺失值显示 null。
- 模型文本：`{{getvar::stat_data.旅店.余额}}`，路径从变量根开始。宏只读取已有变量，变量须有初值。
- 固定资料区（角色字段、常驻条目）里的变量宏每次取值变化都会改变请求前缀、降低缓存命中；常变的数值交给展示面板或各模式的状态通道（见模式文档）。
- EJS 的 `<% … %>` 不是这些宏，需要另行适配。

## 脚本

- 保留 schema 注册、校验回调、宏和资源；这些可能是变量系统运行所必需的，禁用全部脚本不能作为通过检查的手段。
- 脚本额外发起模型请求（generate/generateRaw）和 HTML 交互生成只在 Half Agent 可用。方案依赖它们时读取 `full-agent.md` 的能力边界，与用户确认兼容性目标并用 `configure_card` 记录；遇到不支持的能力，说明具体依赖并讨论替代交互。
- 脚本权限按对话保存，由用户在 MVU 页或会话设置中开启；`test_draft` 在隔离沙盒中执行。

## 验证

- `validate_draft` 输出结构错误、完整性提示和静态兼容性提示。无警告只表示通过了已实现的静态检查。
- `test_draft` 检查所选开场的初始化、脚本启动、正则样例和 DOM 断言，不发起模型请求。
- 报告分开写三项要素各自的状态、静态检查、本地运行检查和未覆盖范围；真实叙事、变量判断、其他开场和完整视觉交互需在新故事中验收。
