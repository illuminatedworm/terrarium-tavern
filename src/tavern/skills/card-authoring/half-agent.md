# Half Agent 如何使用角色卡

Half Agent 每轮由三方协作：Writer 无工具生成正文；Tracker 用独立上下文维护记忆、变量和授权的设定修改；Runtime 负责检索、组装请求和提交。写卡时据此判断每段内容会被谁看到、何时生效。

## 一轮的顺序

1. Runtime 执行输入正则和脚本，检索世界书，规划窗口。
2. Tracker 前置任务（需要时）：窗口裁剪前整理记忆；用户本轮允许修改设定时，先处理输入中的明确修改。
3. Writer 组装请求并生成正文。正文末尾的检索线索由 Runtime 剥离，用于下一轮检索。
4. Tracker 后置任务：记忆周期到期、用户勾选“本轮更新变量”或授权设定维护时运行。
5. MVU 应用变量补丁，执行消息回调和输出正则，整轮原子提交。

## 谁看到什么

| 内容 | Writer | Tracker |
|---|---|---|
| system_prompt、post_history_instructions、mes_example | 按配方注入 | 不作为指令注入，需要时通过工具读取 |
| name、description、personality、scenario | 按配方注入 | 作为结构化角色资料 |
| 选中的开场 | 第一条 assistant 剧情 | 作为剧情历史 |
| `writer` 世界书 | 常驻条目与检索准入的条目 | 通过工具检索、读取 |
| `tracker_mvu` 世界书 | 不可见 | 变量任务中完整提供 |
| 当前变量 `stat_data` | 每轮以 `<tavern_state>` 完整提供 | 变量任务中提供 |
| 记忆 | 每轮以 `<tavern_memory>` 提供 | 维护者 |
| 最近剧情 | 窗口内全部 | 最近 6 条及本轮输入、正文 |

## 对写卡的影响

- **位置**：字段默认顺序见 `card-format.md`。会话配方可以调整字段块的位置、深度和条件，新会话复制全局配方。
- **世界书位置**：新对话的注入方案有两种，默认“随对话滚动”。“按角色卡位置注入”遵循条目的 `position`：0 在角色资料前，1 在角色资料后，2/3 并入作者注，4 按 `depth` 和 `role` 插入剧情中，5/6 在示例前后，7 写入 `outletName` 指定的出口。“随对话滚动”忽略非常驻条目的位置，把它们放在触发处附近。正文语义不要依赖特定位置。
- **变量**：Writer 每轮都能看到完整的当前变量，叙事设定可以直接引用变量含义（如“余额不足时林默拒绝赊账”），不必在固定字段里写变量宏。变量只在用户勾选“本轮更新变量”时更新；勾选在成功保存后保留，直到用户取消。
- **记忆**：剧情中发生的变化由 Tracker 写入记忆，卡片只写稳定设定，不需要“记住某事”之类的指令。
- **剧情中的修改**：用户授权后，Tracker 可修改该对话自己的角色卡与世界书副本，书架原卡不变。
- **脚本**：支持脚本额外发起模型请求（generate/generateRaw）和 HTML 交互生成，请求使用本项目的模型配置。
- **缓存**：固定资料区（角色字段、常驻条目）内容变化会重建请求前缀；状态、记忆、后置要求和作者注在请求尾部按变化追加。
