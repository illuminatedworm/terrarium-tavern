# Full Agent 如何使用角色卡

Full Agent 由一个模型在工具循环中完成叙事、世界书检索、笔记维护和授权的变量与设定修改；不含工具调用的最终回复成为正文。它不使用 Half Agent 的配方和 Tracker。

## 请求结构

1. 固定前缀：主系统规则、工具协议、窗口机制说明、对话偏好、常驻世界书（条目顺序）、`system_prompt`、`description`、`personality`、`scenario`、用户角色、`mes_example`，各自为独立消息。
2. 当前窗口的剧情，以及锚定在其中的世界书与完整工具交换。
3. 本次输入锚定的世界书、当前输入、本轮授权、按需追加的 `<mvu_rules>`、`post_history_instructions`。
4. 交接笔记（handoff）、窗口状态和预算提醒。

换窗后固定资料与有效的后置要求完整恢复。

## 模型看到什么

| 内容 | 自动进入上下文 | 按需取得 |
|---|---|---|
| 角色字段、用户角色、常驻世界书 | 是 | 可读取七个角色字段 |
| 选中的开场 | 作为第一条剧情 | — |
| 非常驻 `writer` 世界书 | 每轮首次请求前自动检索，准入条目贴近触发处 | `recall_lore` 用模型自拟的查询检索，完整返回正文 |
| `tracker_mvu` 世界书 | 用户授权变量更新后，首次请求前以 `<mvu_rules>` 完整追加，同一窗口同一版本不重复 | — |
| 当前变量 `stat_data` | 否 | `read_state` 按路径读取 |
| 长期记忆 | handoff；从第二个窗口起列出笔记名称 | 搜索、读取笔记 |

## 对写卡的影响

- **位置**：字段顺序固定为上表，世界书条目的 `position`、`depth` 不改变位置，检索准入的条目一律贴近触发处。
- **检索**：模型会用自己的措辞主动查询世界书，条目标题、关键词和正文第一行写清主体，才容易被找到。
- **变量**：变量不自动进入上下文。剧情依赖变量时（如“余额不足时林默拒绝赊账”），在叙事设定里写清这层关系，模型会按需读取。变量只在用户勾选“本轮更新变量”时更新，每轮须成功提交一次补丁，无变化提交 `[]`；勾选在成功保存后保留，直到用户取消。
- **记忆**：剧情变化由模型写入 handoff 和长期笔记，卡片只写稳定设定。
- **世界书库**：用户新建对话时可挂载世界书库中的书；挂载把条目复制进该对话的角色卡副本，之后与卡内条目同等对待，库中的书不变。
- **剧情中的修改**：用户本轮允许修改设定时，模型可改写七个角色字段（name、description、personality、scenario、mes_example、system_prompt、post_history_instructions），并增删改普通 `writer` 条目，只影响该对话。开场、扩展、`tracker_mvu`、初始化条目和含脚本的条目受保护。
- **脚本能力边界**：正则、MVU 初始化与校验、脚本正文变换和消息回调照常参与每轮处理。脚本额外发起模型请求（generate/generateRaw）和 HTML 交互生成不受支持；方案依赖它们时说明具体依赖，与用户讨论替代交互，例如改由变量加展示面板实现，或把目标模式定为 Half Agent。
- **缓存**：固定前缀内容变化会重建请求基线；后置要求在动态区首次注入、变化时追加、清空时撤销。
