## 标签与历史说明

`v0.1.0`～`v0.4.0` 于 2026-10-17 根据已有 Git 历史补标，以下日期是各里程碑原提交的日期，不表示当日曾公开发行。补标时同步修正该节点及后续提交中的应用版本、锁文件本项目版本和 API 版本，保留原功能内容、作者、提交日期、提交说明及合并关系。因此从 `v0.2.0` 节点起的提交哈希已改变。

`v0.5.0` 标记 2026-10-17 版本整理完成后的源码。标签均为带注释的 Git 标签；标签本身不表示已完成发行验收、真实模型评测或提供安装包。旧标签中的文档描述其当时行为，当前文档以 v0.7.0 为准。

## 未发布

- 新增独立的[世界书库](guides/worldbooks.md)：左侧栏“世界书”页可新建、导入、编辑、导出和删除世界书；角色卡的“导入世界书”改为下拉菜单，可从文件或书库导入。
- 新建故事增加第 3 步“挂载世界书”；对话可在“场景 → 编辑对话世界书 → 挂载世界书”中随时挂载、卸载或重新载入。挂载按副本复制进对话级角色卡，书库后续修改不影响已有对话。
- 书架角色卡可设置“新建对话默认项”（一个用户角色和若干世界书），仅用于新建故事时预选，不写入角色卡文件。
- 制卡 agent 可引用世界书库中的世界书：输入 `@` 选择，Agent 与表单可修改书名和条目，审阅后覆盖保存回书库或另存副本；书库 ID 不进入模型输入。系统提示与内置指引补充独立世界书说明。
- 世界书条目编辑弹窗更紧凑：条目 ID、名称、用途同排，触发词并排，参数网格改为 4 列，常见屏幕下一屏即可看全。
- 数据库升级为 schema 11（在 schema 10 的世界书库与默认项表、剧情快照挂载记录之外，制卡草稿项增加世界书标记），schema 9、10 的数据照常升级并先备份；个人数据包升级为版本 4，可携带世界书与角色卡默认项，仍可导入版本 1–3。

## v0.7.0 — 2026-10-20

- 新增可选的 Kemini 式实验兼容改写层，按对话启用；普通对话的请求、缓存与数据不受影响。
- 制卡 agent 重写内置指引：按 MVU 三项要素说明变量写法，补充 ST-Prompt-Template 语法改写指引与定位诊断，移除非标准初始化用途，并恢复关闭的 `[InitVar]` 条目参与初始化。
- 世界书条目标题统一按 `comment` 优先、`name` 兜底取值；新增“注入时携带条目标题”（默认关闭）与“条目标题参与检索”（默认开启）开关。世界书字段别名兼容读取，导出统一格式。
- 模型选单可获取模型列表，模型连接按供应商独立保存；通用设置合并为“联网与代理”“数据与存储”，重做本地模型页并统一预热通知。
- 修复流式空收尾包、缓存命中率口径、服务端失败原因保留、动态图片加载、Tracker 用户角色等问题；统一桌面阅读布局与错误映射。
- 数据库升级为 schema 8，设置文档升级为 version 7：消息增加独立的实验辅助记录，会话增加 Kemini 对话标记（已有对话均为普通对话）；设置 version 5 增加默认关闭的 Kemini 式实验功能，version 6 补全绝对前缀与可编辑传输提示，version 7 补齐角色扮演追加要求、正文约束和末尾输出提示。
- 升级时只生成一份 `before-upgrade-schema<旧版本>-settings<旧版本>-*.sqlite3` 备份，取代此前按迁移步骤分别生成的多份备份。
- 角色卡“脚本与兼容”页可导入 SillyTavern 正则 JSON，追加到现有正则脚本之后。
- 编辑对话世界书时可从书架角色卡同步角色设定、世界书条目、正则脚本与 Tavern Helper 脚本，支持逐项、分组、仅书架更新与全部覆盖。

升级注意：

- 前端资源有变化，请重新运行对应系统的安装脚本或构建脚本。
- 从 v0.6.0 升级涉及 schema 6→8 和设置文档 3→7，迁移前自动备份；回退旧程序时从升级前备份恢复。
- 世界书检索的标题口径改变（BM25 不再同时计入 `name` 与 `comment`），启用向量通道时升级后首次检索会重建向量索引；只填 `name` 且含 `[InitVar]` 的条目现在也按初始化条目处理。
- 设置 version 7 只将完全匹配旧默认值的 Kemini 边界标签与 Interleaving 包装改为 Markdown 分隔符，自定义文本与开关保留。

## 升级与版本规则

升级前备份完整数据目录，安装新版依赖和前端资源。数据库 schema、设置文档版本与应用版本是不同概念；旧程序回退应恢复对应版本的备份，不直接打开已升级数据库。具体步骤见[备份、升级与回退](guides/maintenance.md#备份升级与回退)。

后续 `0.6.x` 用于无需额外升级注意的修复和小幅完善，下一轮新能力、持久格式或核心行为调整使用 `0.7.0`。版本号不表示固定完成百分比；在核心行为与升级兼容约定稳定、完成发行验证后再进入 `1.0.0`。
