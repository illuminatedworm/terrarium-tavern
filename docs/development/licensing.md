## 原创部分与第三方部分

本项目原创代码和资料使用自定义非商业许可，包元数据使用 `LicenseRef-Terrarium-Tavern-NonCommercial-1.1`。它保留署名、修改声明、专利、商标和免责等授权结构，并将商业使用排除在授权范围外；不能标为 `Apache-2.0`，也不是两套可任选的许可。

| 内容 | 维护要求 |
|---|---|
| 原创代码、文档、测试、示例和资源 | 使用项目许可，保留相应版权与修改声明 |
| Kohaku Terrarium 部分 | 保留独立许可及命名、署名要求 |
| 其他第三方组件和混合文件 | 按来源保留各自许可，不用项目非商业条款覆盖第三方授权 |
| 模型权重和外部资源 | 分别记录来源、版本和使用条件 |

项目许可允许非商业修改和免费再分发，不额外要求公开源码；第三方义务仍独立适用。购买模型 API 用于个人娱乐的说明、用户输入输出边界及其他授权条件，应直接查阅许可正文。

仓库的[第三方声明](../../LICENSE/THIRD_PARTY_NOTICES.md)记录了以下尚未解决的发行风险：

| 依赖 | 锁定版本 | 仓库记录的许可与使用情况 |
|---|---|---|
| Kohaku Terrarium | 2.1.3 | 直接依赖下列组件，版本见 [uv.lock](../../uv.lock) |
| html2text | 2025.4.15 | GPL-3.0-or-later；上游网页读取工具直接调用 |

当前仓库没有足以确认完整依赖组合可按项目非商业限制合规分发的结论，也没有可确认 PyMuPDF 商业授权的材料。仅将依赖改为可选、让安装器另行下载或保留许可文本，不能作为这些事项已经关闭的依据。

发行维护应记录实际依赖链和交付方式，并针对未决组件取得明确处理结论，例如实际替换／移除相关依赖、取得适用授权或完成隔离方案审查。依赖变化后同步更新锁文件、声明与发行内容；不能只删除声明文件。

这份清单是仓库中已记录的问题，不代表全部依赖、模型、资源和逐文件来源审计已经完成。整体发行的法律兼容性不能由构建通过推导。

## 发行检查

1. 保持项目许可、包元数据、README、构建产物和分发副本的许可版本一致。
2. 随发行包提供 `LICENSE/` 和源码旁需要保留的第三方许可；前端静态包、Python 包及源码包分别检查。
3. 按 [Kohaku Terrarium 许可](../../LICENSE/KohakuTerrarium.txt)保留产品命名和可发现的上游署名信息。
4. 核对锁文件与实际随附、下载或调用的依赖，记录仍未解决的兼容性与权属事项。
5. 将文件齐备、代码来源核验和发行授权判断分别记录；打包工具只验证其负责的产物内容。

发行命令见[验证与发行](validation.md#打包与产物)，完整适用范围见[许可目录](../../LICENSE/README.md)。
