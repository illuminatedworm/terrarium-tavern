# 制卡、编辑角色卡与适配工作流

书架角色卡是创建新故事的模板；已有故事保存自己的角色资料。编辑页的“新建对话默认项”可预设新故事的用户角色和[世界书库](worldbooks.md#新建对话默认项)中的世界书。书架卡片与已有故事分别保存。当前故事的世界书可从“场景 → 编辑对话世界书”修改，并可选择性地[从书架角色卡同步](#从书架角色卡同步)；采用“审核后保存”时，接受修改后生效。

## 手工编辑与复制

左侧栏“角色卡”页的“新建”创建一张空白 V2 角色卡，名称为“新角色”，重名时追加编号，随后进入编辑页填写；“导入”读取 JSON、PNG 或 CHARX 文件。角色卡列表可以复制已保存角色。副本有新的身份和独立文档，名称添加“（副本）”及编号；头像、CHARX 资源、脚本权限和已缓存依赖保留。共享底层文件不会让副本跟随原卡变化，删除原卡也不会删除仍被引用的资源。

角色卡编辑页的表单占满内容区；“导出角色卡”位于右上角，与“恢复原稿状态”和“保存角色”并列。导出的是已保存版本，表单修改需要先保存。

PNG 角色卡的图片和 CHARX 中声明的内嵌头像会显示在角色卡列表、编辑页、新故事的角色选择与开场设置、会话列表及对话头像中。没有图片或图片加载失败时显示角色名字首字。已有会话使用创建时保留的图片，修改或删除角色库中的原卡不会改变该会话的头像。

手工编辑的未保存修改会保留在当前浏览器标签页中，重新打开编辑页时自动恢复，并显示“有未保存修改”。点击保存按钮旁的“恢复原稿状态”，会在按钮附近打开悬浮确认框；点击外部、继续编辑或按 Esc 可取消。确认后放弃全部表单修改并清除这份本地草稿；角色卡从书架读取最新保存版本，对话世界书恢复进入编辑页时的内容。原始 JSON 即使格式无效也能放弃。制卡对话中，此按钮恢复打开表单时的草稿，不撤销 Agent 对话中已完成的修改。

世界书可搜索名称、注释、ID、主／副关键词和正文。空格分词后同时匹配，不区分大小写；启用状态、触发方式和条目用途可以组合筛选。筛选保留原始顺序，并显示匹配数与总数。

书架角色卡与制卡表单的“导入世界书”是下拉菜单：“从文件导入 JSON”读取文件，“从世界书库导入…”选择[世界书库](worldbooks.md)中的一本。两者都将条目添加到当前草稿，保留已有条目和世界书设置，保存后生效。支持数组与对象形式的 entries；重复 ID 会为新条目重新分配，重复导入仍作为新增处理。从书库导入是一次性复制，之后修改书库不影响这张卡。对话世界书编辑页只提供“导入世界书 JSON”，书库世界书通过挂载加入对话。

“脚本与兼容”页列出全部正则脚本与 Tavern Helper 的顶层、分组及旧版角色脚本，包括停用项。可以编辑匹配表达式、替换内容、脚本正文和原始参数；世界书初始化内容仍在对应条目中查看。

“导入正则 JSON”接受 SillyTavern 导出的单个正则脚本对象或脚本数组，可一次选择多个文件。脚本追加在现有正则之后，不改动已有脚本；缺少 ID 或 ID 与现有脚本重复时分配新 ID。任一文件无效或缺少 `findRegex` 时整批不导入；导入结果写入草稿，保存后生效。

## 从书架角色卡同步

“场景 → 编辑对话世界书”页的“从书架卡同步”会对比书架角色卡与当前对话使用的角色卡，列出可同步的差异：

- 角色设定：角色名称、昵称、角色描述、性格、场景、角色系统提示、历史后提示和示例对话，逐字段选择。
- 世界书条目：按条目 ID 对应，逐条新增、覆盖或删除对话中多出的条目。
- 正则脚本：按脚本 ID 对应，逐个新增、覆盖或删除；执行顺序不同时单独列为一项。
- 角色脚本：Tavern Helper 脚本与旧版脚本字段整体同步。

开场白、作者备注、标签、创作者信息和世界书整体设置只在开局或展示时使用，不参与同步。从[世界书库](worldbooks.md)挂载的条目不是书架卡内容，不参与比较，全部覆盖时也保留。每项差异以对话开局时复制的角色卡为基准标明来源：“书架卡更新”表示只有书架卡改过，默认勾选；“对话内改动”表示 Tracker、卡片脚本或手工编辑改过对话中的内容，同步会还原为书架卡内容；“双方都改过”会以书架卡为准。后两类默认不勾选。同步过一次后，书架卡再修改同一项会显示为“双方都改过”。

可按名称筛选，逐项或按分组勾选，也可用“仅书架卡更新”“全部覆盖”“全部取消”快速选择；展开一项可对比当前对话与书架卡的完整内容。某一组全部勾选时，该组完全采用书架卡内容和顺序；部分勾选时，新增的条目和脚本追加在末尾。

同步作为一次对话内容修改提交，与保存对话世界书相同：采用“审核后保存”时，接受修改后生效；之前已生成的消息显示不随正则变化重算。编辑页有未保存修改时需先保存或恢复原稿状态。书架角色卡已删除或在同步期间被修改时，同步会失败并提示重新打开。

## 独立制卡对话

在“设置 → 通用 → 制卡 agent”配置模型、创作与上下文、联网和系统提示词。提示词保存后用于下一次发送或继续；“恢复默认文本”先填入编辑框，再保存生效。

从左侧“制卡”新建或恢复独立对话。角色卡页面的“Agent 编辑”会创建一个带入当前表单内容的制卡对话，包括尚未保存的修改。

引用资料有两种入口：点击“引用角色”，或在输入框输入 `@` 后搜索名称。候选列表支持 ↑↓ 选择、Tab／Enter 确认、Esc 关闭；普通输入默认使用 Enter 发送、Shift+Enter 换行，可在“设置 → 通用 → 杂项”切换发送和换行方案，与剧情和参谋 agent 共用。

确认引用后，角色卡或用户角色显示为输入框上方的名称标签，并随对话保留。角色卡标签打开对应草稿；同一卡再次引用时沿用当前草稿。书架引用使用已保存版本，源卡更新后可重新载入，并通过撤销恢复之前的草稿。

制卡 agent 按需读取已引用卡片的完整字段、世界书和脚本。用户角色提供名称与介绍快照，刷新资料需移除后重新引用。取消角色卡引用会删除该对话中对应的草稿与撤销记录，书架原卡保留；操作前需处理正在运行或待续的任务。

聊天保留中间回复、最终答复及按顺序排列的“工具与过程”。本次处理最后写出的一段文字作为最终答复，即使它与工具调用写在同一次回复中。过程可展开查看参数和结果，失败或停止的内容会标记未完成。模型请求直接显示请求序号与实际模型名称，不再单独折叠；只有模型请求、没有工具活动的阶段显示为简洁记录。重新打开对话后仍可查看已保存记录。

角色卡和用户角色可在对话开始前或中途引用。引用变化、手工修改草稿时，只在下一次请求末尾追加最新资料状态，保留已有对话前缀；资料未变化则不重复追加。取消引用后以最新列表为准，历史已发送内容仍保留。手工改过的字段需重新读取，未改字段的有效读取记录继续沿用。

第一次发送时会固定本对话的时间与系统环境，作为高级系统规则之后、引用资料之前的独立 system 消息：包括运行酒馆后端的操作系统版本、本地时间（精确到秒）和 `UTC+8` 一类数字时区偏移。后续对话、换窗及重启都不更新时间，可在消息预览中查看。首次发送前的预览值尚未固定；旧对话补录会明确标注历史环境信息的限制。

“内置技能”提供项目工作流适配和正文状态栏迁移入口。选定卡片后，“填入请求”将可编辑的要求加入输入框，确认后发送。

制卡 agent 按任务读取随项目提供的指引：从零制卡的步骤与字段格式、变量与正则、适配流程，以及 Half Agent、Full Agent 分别如何使用卡片。更新程序后，已保存过的系统提示词保持原文；需要采用新的默认规则时，在设置中点“恢复默认文本”并保存。

联网可选择关闭、自动或本地实现。自动模式下，ChatGPT 官方渠道优先云端搜索，普通 API 使用共享服务；配置入口为“通用 → 联网与代理”。操作说明见[参谋 agent 联网说明](advisor.md#外部资料与数据保存)，返回格式见[联网工具协议](../reference/web-tools.md)。查阅结果用于创作参考，修改先进入草稿。

## 从零制作

1. 描述想制作的人物、世界或互动情境。
2. Agent 先提出定位、用户角色与互动、风格、开场和必要机制的方案。
3. 在聊天中确认或修改方案，再生成草稿。明确要求直接制作时可以直接开始。
4. 从右侧选择卡片，在资料、修改和诊断页审阅；可打开原有表单手工编辑。
5. 需要头像时，引用一张图片并说明用作头像，或在“数据”页的“头像”下拉中选择已引用的图片；“移除头像”可撤销。
6. 使用“保存新卡”加入书架。之后可覆盖保存或另存副本。

头像保存为标准 PNG 角色卡：JPEG 和 WebP 会转换为 PNG，导出时角色数据写入这张图片。覆盖保存会同时替换书架原卡的图片；CHARX 卡的头像来自卡内资源声明，暂不支持在制卡对话中更换。仅作参考的图片不会被设为头像。

仅更换或移除头像也会显示未保存修改，“修改”页的计数和提示会标明头像与书架已保存版本的差异。Agent 完成一次头像修改后，可用“撤销上次修改”恢复该轮之前的头像，保留更早的正文修改；保存后提示与书架同步。

已确认方案和用户要求原文随卡片保留。普通文本卡默认使用项目支持的 V2 JSON；变量、正则和脚本按需求加入。普通制卡和 MVU 设计共用一套契约，无需先选择模式。只有脚本额外模型调用、HTML 交互生成等能力影响方案时才确认 Half Agent 或 Full Agent；资料页的兼容性目标为可选项，选择本身不迁移内容。

## 读取本地资料

点击输入区的“引用本地文件”，可一起选择图片和文档，补充要求再发送。支持 TXT、MD、CSV、JSON 等文本、DOCX/XLSX，以及 PNG、JPEG（JPG）、静态 WebP 图片。附件绑定到本条用户消息：请求被应用接受后从输入区清空，显示在对应历史消息下；提交被拒绝时保留待发送附件，模型运行失败时附件随原消息保留，可继续本轮。副本随对话保存，删除对话时清理；发送前可取消引用，不影响原文件。每个附件最多 32 MiB，每个对话最多 20 个附件、合计 128 MiB。文本和 Office 资料也可直接提供运行后端电脑上的绝对路径。

图片随所属用户消息直接发送原图，使用支持图片输入的模型；不需要 agent 调用图片读取工具。原消息仍在上下文中时，图片会随历史参加后续请求，不会被绑定到新消息。换窗后可通过 `read_history` 恢复旧消息的图片。普通文档保持按需读取。动图、损坏图片、实际格式与扩展名不符或像素过多的图片会被拒绝；服务商额外的图片或请求大小限制也可能导致失败，此时保留进度并反馈错误，不自动压缩或省略图片。界面的本地 token 估算不包含图片用量，有图时会明确标注；实际用量以服务商返回为准。

| 类型 | 默认读取量 | 上限与说明 |
|---|---|---|
| 文本 | 200 行 | 每次最多 1000 行、20,000 字符，保留完整行；可指定 GB18030 等编码 |
| DOCX/XLSX | 12,000 字符 | 每次最多 30,000 字符，按转换后的 Markdown 字符位置续读 |
| PNG/JPEG/静态 WebP | 随所属用户消息直接发送 | 保留原图，不分页、不自动压缩；受所选模型图片能力和服务商限制约束 |

文件最多 32 MiB；Office 解压最多 128 MiB、4096 个条目，转换最长 30 秒，产物最多 800 万字符。超限时先拆分，损坏或加密文件先修复或另存。Excel 公式结果取自文件中保存的缓存值；不执行宏、重算公式或识别 Office 内嵌图片文字。单独引用的图片由所选模型理解。

Android 版同样支持 DOCX/XLSX：DOCX 使用 mammoth 与 markdownify，XLSX 使用 openpyxl，按工作表顺序提取文字与表格；复杂排版、嵌入对象和公式排版可能无法保留。Android 的读取结果会注明实际转换器与限制，分页位置只适用于该转换结果。桌面版继续使用 MarkItDown。Android 在独立的文档解析进程中工作，超时、取消或完成后结束该进程，不影响故事后端；连续文档读取会依次处理。

读取结果带续读位置，连续读取期间应保持源文件稳定。外部文件只读，联网关闭时仍可使用；当前角色卡字段另通过卡片工具读取。详细参数见[外部文件读取](../reference/card-author-tools.md#外部文件读取)。

## 用户角色

用户角色单独保存名称和介绍，可通过明确请求查看、新增或修改，例如“列出用户角色”或“新建用户角色林澈，介绍是离开军队的航海士”。这些操作可独立于角色卡进行。

查看与修改分别授权。Agent 定位并完整读取已有角色后，修改要求涉及的字段；同名角色由工具引用区分。讨论 `{{user}}` 或玩家定位作为创作背景处理。

新增和修改在制卡任务正常完成后保存到用户角色库，可供新故事选择；已有故事继续使用自己的身份快照。停止、失败或断网会保留待保存内容，可继续，或补充“撤销本轮用户角色修改”。其他编辑引起版本冲突时，需重新读取并合并。

## 多卡编辑与保存

一个对话可引用多张卡，每张卡有独立草稿、差异、撤销记录和保存基准。未知字段、宏、资源和原容器随草稿保留。

右侧默认显示“预览”，可查看角色设定、切换开场、展开和搜索世界书。字段名称、开场编号和世界书用途与角色卡编辑界面一致，默认开场为“开场 1（默认）”。预览展示静态内容；实际脚本效果在新故事中查看。“数据”提供完整字段树、兼容性设置和表单入口，“修改”提供差异、撤销和重新载入，“诊断”显示检查结果。窄屏通过“卡片与修改”进入。

Agent 修改草稿后，由用户审阅并保存。右侧底部的“保存角色卡”写回引用的书架卡，新草稿显示“保存新卡”；“另存副本”创建独立角色。覆盖保存要求原卡版本匹配，冲突时可核对新版、重新载入或另存。

## 引用世界书库中的世界书

在输入框输入 `@` 可以引用[世界书库](worldbooks.md)中的一本世界书。它与角色卡一样显示为输入框上方的引用标签，可以查看、让 Agent 搜索和修改；右侧预览只显示世界书条目，没有开场、头像和兼容性目标，也没有“本地验证默认开场”。Agent 与表单只能修改书名和条目；开场、头像、目标模式等角色卡内容请写进角色卡草稿。修改后在“修改”页审阅差异，“保存世界书”写回原书，“另存副本”新建一本“（副本）”。书库中的版本在此期间被改动时，覆盖保存会因版本冲突失败，草稿保留，可重新载入原书或另存。书库是模板：保存不会改变已经挂载它的对话。Agent 不能新建世界书，也不能设置角色卡的新建对话默认项。

运行中或有待续进度时，先完成或丢弃当前任务再保存。勾选右侧“查看本轮未完成版本”可检查临时版本，该版本会明确标记为待完成。书架保存影响以后创建的故事，已有故事保留自己的角色资料。

## 停止、继续和补充要求

每次发送或显式继续默认最多 **24 次模型请求**，可在通用设置调整。停止、断网、服务重启、服务商报错或额度耗尽会保留待续进度和上次完成的草稿。失败原因显示在对话中出错的那次请求下方，服务商返回的错误说明会一并显示；“第 N 次模型请求”在整轮内连续编号，包括失败后继续的尝试。

- **继续本轮**：从最后一次成功的模型回复和工具结果接着处理剩余任务。失败后可先更换供应商或模型再继续，重建的上下文仍包含本轮已完成的工具交换（最近一次换窗之后的部分）。
- **补充要求并继续**：例如“保留 A 的修改，B 恢复原状，再处理 C”；撤销尚未执行的旧调用，按新要求继续。
- **丢弃本轮**：位于“继续本轮”旁，恢复上次完成的草稿，保留聊天记录。

手工编辑、保存、刷新引用或删除对话前，先处理运行和待续进度。切换对话或关闭页面后，后端任务继续运行；刷新页面可恢复观察。未发送输入按对话分别保存。

## 长对话与验证

上下文默认达到容量的 **70%** 时提醒准备换窗，达到上限后要求换窗。交接笔记默认最多 **2048 tokens**，确认方案、当前卡片、最近两轮交流和当前输入继续保留；旧历史可完整回读。换窗计入当前运行额度，资料超长时完整发送，由服务商接受或拒绝。

输入框下方显示“当前 token / 配置的上下文上限”和当前制卡对话累计的缓存命中率。缓存命中率为所有请求的缓存读取总量除以输入 token 总量（含缓存命中部分），包含工具续答，仅使用接口真实数据；缺项或旧逐次记录不完整时显示“暂无”。当前上下文用量包括输入、工具定义与未完成进度，悬停可查看估算口径；工具调用在对应回复的“工具与过程”中查看。

输入区可选择同渠道供应商、模型和思考强度。供应商与模型随对话保存，接口、路径和预算沿用制卡 agent 配置；思考强度按对话保存在当前浏览器，“跟随设置”使用通用值。运行期间保持选择，停止或失败后可调整并继续，程序会重建所需上下文。旧对话首次使用时需确认渠道归属。

诊断分为结构、创作完整性和运行范围检查。本地验证工具可测试指定开场的初始化、正则样例和脚本启动，界面按钮检查默认开场。沙盒使用内嵌或已缓存资源；缺少依赖、超时和超出支持范围时会显示原因。实际叙事、其他开场和完整视觉交互在新故事中另行确认。

## 世界书用途与初始化

| 用途 | 行为 |
|---|---|
| `writer` | 两种模式可见的叙事与规则资料，沿常驻及检索规则注入 |
| `tracker_mvu` | 两种模式的变量规则；读取全部启用条目及关闭的 `[InitVar]` 条目。Half Agent 提供给 Tracker，Full Agent 在当前上下文首次授权更新时追加，同版本不重复，换窗后按需补入 |

开场 `<initvar>` 提供该开场的完整初值，覆盖角色卡世界书初始化，不从条目补齐遗漏字段。无开场 `<initvar>` 时使用世界书初值；传统 `[InitVar]` 标记条目即使禁用或标记 `tracker_mvu` 也会被读取。`[InitVar]` 决定初始化，`tracker_mvu` 决定是否向变量任务提供正文，两者可以同时使用。已有对话的初始化记录不会自动重演。

两种模式共用 `writer`、`tracker_mvu` 和 `[InitVar]` 的分工。变量更新通过相对 `stat_data` 的 JSON Patch 完成，无变化时提交空数组；规则和宏值在任务开始时固定，修改用于后续任务。普通编辑保留原工作流，明确要求适配时再调整相关内容。

需要迁移逐轮 HTML 状态栏、Markdown 表格或固定标签块时，可要求“将正文状态栏迁移为独立变量，使用项目变量面板”。Agent 按适配指南分离叙事、初值与更新规则，默认保留原开场和面板设计，并通过读取 `stat_data` 的展示正则挂载到 MVU 区。

有效的内联初值及隐藏正则原位保留；公共初值放在世界书，开场专属初值放在对应开场。涉及 MVU 的卡适配后须同时具备标准初始化、`tracker_mvu` 变量规则和展示正则；社区卡中的非标准初始化会被提示并改写为标准形式。余额、进度等含义需要先确认，再建立计算规则。

迁移结果先保存在草稿，用初始化检查、纯叙事样例、DOM 断言和临时变量补丁分别验证。保存后在新故事中确认实际效果，已有故事继续使用其原状态。

诊断会标出疑似重复模板、静态状态栏、宏路径及缺失的初值或更新规则。这些提示用于定位需要审阅的内容，普通 HTML 排版和程序读取变量的展示可以保留。适配效果结合完整卡片、初始化结果和实际游玩确认。

## 删除、备份与旧版本

取消卡片引用会删除当前制卡对话内的对应草稿和撤销记录，保留书架卡。删除整个制卡对话会清除其聊天与全部草稿，操作前先保存需要保留的成果，并处理运行或待续进度。

制卡列表和对话顶部都提供删除入口。已保存的角色卡、用户角色与故事分别保留；源卡删除后，现有草稿仍可恢复并另存。

制卡对话、确认方案、草稿和待续进度随完整备份保存。完成或停止任务后即可备份，恢复后可继续。升级和回退步骤见[安装与维护](maintenance.md#备份升级与回退)。

实现与接口见[工作区设计](../design/card-author.md)和[工具协议](../reference/card-author-tools.md)。
