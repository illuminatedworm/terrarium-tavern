# 配置模型与应用设置

设置分为 Full Agent、Half Agent 和通用三组。游玩模型按“普通 API”和“ChatGPT 官方”两个渠道分别配置；故事在创建时确定渠道，之后可在同渠道内更换提供商和模型。

## 完成首次配置

1. 在“通用 → 提供商”添加普通 API 的域名和 API Key，或连接 ChatGPT 账号。
2. 在目标运行模式的“模型与生成”选择渠道、提供商、模型和协议。Half Agent 的“正文生成”与“后台整理”分别对应 Writer 和 Tracker。
3. 核对页面显示的完整请求地址。API 路径留空时，Gemini 使用 `v1beta`，其他协议使用 `v1`；填写后按填写值使用。
4. 设置模型上下文容量、输出预算及采样／思考选项，再检查连接。Full Agent 和 Tracker 需要模型支持工具调用。
5. 按需在“通用 → 制卡 agent”或“通用 → 参谋 agent”配置各自的独立模型。

**新配置的默认值**：上下文容量 131072 tokens；输出上限方面，Writer、Full Agent 和制卡 agent 为 16384 tokens，Tracker 非记忆任务与参谋 agent 为 8192 tokens，Tracker 记忆整理及疑难复核使用独立的整理输出上限，默认 16384 tokens。温度等可选采样参数默认留空，沿用服务商默认值；思考强度保持默认。已保存的配置保持原值。

上下文容量需要与实际接入模型的规格相符；接小模型时，应同时调小输出预算和 Half Agent 日常输入预算。提高输出上限不要求模型写满；保留更多历史会增加输入用量。

### 选择模型

- 模型选单可搜索候选项，也可输入模型 ID 后选“使用此模型 ID”。方向键选择、Enter 确认、Esc 关闭。
- 普通 API 的“更新模型列表”向提供商请求并保存目录；游玩对话、参谋 agent 和制卡 agent 的选单顶部的“获取模型列表”作用相同。ChatGPT 连接先读取已保存的目录，再自动刷新。
- 同一提供商的所有 agent 共用一份模型列表缓存（协议与 API 路径不同也可复用）：任一处更新成功，其他选单同步使用；更新失败时保留原列表。刷新请求沿用发起处的协议和路径。

每处模型设置都按提供商分别记住 API 路径、接口方式和模型名称，切换提供商时恢复该处上次保存的三项。Full Agent、Half Agent 的 Writer／Tracker、制卡 agent、参谋 agent 的记录相互独立，重开设置、重启及设置导入导出都会保留。首次选择没有记录的普通 API 提供商时，接口为 Chat Completions，API 路径和模型留空，请按该提供商要求填写；ChatGPT 官方固定使用 Responses 接口。

### 在对话中切换模型

- 游玩和制卡的输入区可选择同渠道的提供商与模型，选择随当前对话保存，分支继承。新提供商尚未选模型时，发送按钮不可用。
- 参谋 agent 的选择在点击“应用”后保存到当前故事的咨询。
- 各对话记住每个提供商上次选用的模型名；接口和 API 路径取自对应角色设置中该提供商的记录，模型菜单会显示当前连接参数和编辑位置。
- Half Agent 输入框只切换 Writer，Tracker 在设置中单独配置。预算、采样等参数仍由对应角色的设置统一控制。
- 运行、待审核和上下文整理期间保持当前选择。设置页与输入区共用思考档位，已保存但当前模型不适用的档位会提示重选。具体映射见[模型接入参考](../reference/model-api.md)。

## 使用 ChatGPT 订阅

1. 在“通用 → 提供商 → ChatGPT 官方”点击“连接 ChatGPT 账号”，进入账号管理并选择 **Continue with ChatGPT**。
2. 在系统浏览器选择账号和工作区，授权应用使用订阅额度。返回后确认显示“已连接 · 已启用 ChatGPT 订阅使用”；如果只完成了身份登录，点击“启用订阅使用”补充授权。
3. 在各运行模式、制卡 agent 或参谋 agent 的设置中，分别选择该提供商及账号目录中的模型。
4. 点击“检查连接”执行一次最小推理检查（会消耗账号额度）。“管理用量”打开 [ChatGPT 用量设置](https://chatgpt.com/settings/usage)。

- 可管理多个账号和工作区；资格、模型和服务地区以官方返回为准。应用通过 Sign in with ChatGPT 获取独立授权，恢复备份或换机后需重新连接并选择账号。
- 官方渠道的两种游玩模式都可选择云端 compact：Full Agent 在“窗口与笔记”切换，Half Agent 在“场景 → 上下文方式”切换。新故事默认使用本地上下文；Half Agent 的 Tracker 周期记忆照常独立运行。
- 思考档位来自账号模型目录，`xhigh` 与 `max` 分别发送；当前接口拒绝的档位显示为不可选。“模型默认”使用目录声明的默认值，未知能力交由服务端处理。
- 登录回调监听本机临时端口，有效期十分钟，可取消后重试。凭据保存在数据目录的 `.chatgpt/`：Windows 用当前用户的 DPAPI 加密，Unix 设为仅所有者可读写。账号凭据、注册信息和安装标识绑定当前安装，数据导出与完整备份都不包含它们。
- 退出账号会停止其请求并尝试撤销远程会话。显示“未确认远程撤销”时，本地凭据已清除，可到 ChatGPT 的“Security and login → Sign in with ChatGPT”断开应用。额度与 credits 按 ChatGPT 设置使用。

## 联网与本地资源

**代理**：应用的代理地址默认为空，模型接口、本地资源下载、角色卡外部资源及新提供商的代理开关都默认关闭。需要代理时，在“设置 → 通用 → 联网与代理”填写完整的 HTTP(S) 地址，打开所需请求的代理开关；模型请求还需在对应提供商开启“使用接口代理”。“本地资源下载使用代理（模型与日文词典）”沿用原有的模型下载开关。地址为空即直连，应用请求不继承系统环境代理。制卡评测工具也遵循这些配置。

**模型请求方式**：同一页可统一选择普通 API 的流式或非流式传输，覆盖游玩、后台、制卡和辅助的模型生成。默认“由各任务决定”。ChatGPT 官方渠道始终流式；目录、向量、缓存管理和 compact 使用各自的请求方式。

**日文词典**：桌面版“通用 → 本地资源”可管理日文词典，显示固定版本、来源、实际路径、大小与 SHA-256，可提前下载、取消、失败重试或离线导入。首次实际进行日文分词时自动准备，纯中英文无需下载；离线游玩含日文的故事前应提前准备，详见[日文词典](retrieval.md#日文词典)。Android 使用 APK 内置词典。

## 设置影响范围

| 配置 | 范围与生效方式 |
|---|---|
| 模型、预算、采样、提示词和检索参数 | 各模式独立，下一次操作使用新值 |
| Full Agent 工具与记忆参数 | Full Agent 后续运行 |
| 提供商、API 代理、本地模型和存储限额 | 共用资源，后续操作使用新值 |
| 会话中的模型选择、偏好和保存方式 | 当前对话，分支继承 |
| 游玩和制卡的消息适配默认值 | 创建对话时复制；已有对话在自己的入口调整 |
| 阅读与布局 | 当前浏览器 |

运行中的回合使用开始时的配置快照。共享提供商的修改影响所有引用它的模型；删除提供商前需先解除引用。

游玩输入框的“更新变量”勾选后立即保存到当前对话，后续回合沿用，切换界面、重开对话或刷新页面后都会恢复；分支继承后可独立调整。新对话默认不勾选。Full Agent 停用变量更新工具时开关不可用，重新启用后恢复保存的选择。“允许修改设定”只授权本轮。

## 生成过程与错误提示

Full Agent 的流式正文先显示为“正文预览 · 未保存”，完整响应、工具要求和脚本处理都通过后才提交或进入审核。含工具调用的中间文字转入过程记录；断流、失败或取消时保留已校验的进度供重试。每轮正文最多三段，详见 [Full Agent 使用指南](full-agent.md)。

应用读完整个 HTTP 响应后才判断是否完成：服务商中途报告的完成或未完成状态（如 `finish_reason`、`stop_reason`、Responses 的 `incomplete`）不会提前截断接收，截断或过滤也不会被之后的正常结束标记掩盖。HTTP 200、流中收到 `[DONE]` 都不代表正文完整——例如 Chat Completions 的 `length` 表示长度截断，`content_filter` 表示内容过滤，这样的回合不会提交。协议细节见[模型接入参考](../reference/model-api.md#连接与协议)。

出错时，如果上游给出了有意义的说明，优先显示其中的关键原文、错误码或结束原因（包括 Responses 的 `incomplete_details.reason`、Gemini 的结束说明和提示拦截原因），再附上本地的“未提交／进度已保留”等说明；上游没有有效说明或只返回 HTML 错误页时，显示本地提示。这适用于模型 HTTP／流内错误、未完成回复、模型列表、ChatGPT 登录与用量、联网搜索和缓存创建。错误说明会先脱敏密钥、Bearer 和 JWT，最多显示 4000 字符，超出时标明“仅显示错误片段”；不显示整个 JSON 响应、请求头或模型上下文。实验输出的本地格式检查不会覆盖服务商已报告的未完成原因。

## 保存与撤回

普通输入在短暂停顿后自动保存，开关与选择项立即进入保存队列。页面显示保存中、已保存或错误；关联条件有误时保留草稿供修正。

提示词等大文本通过绿色勾或 Ctrl+Enter 保存，放大编辑与恢复默认文本也一样。离开未保存的文本时，可选择继续编辑或放弃草稿。

“撤回本页修改”恢复打开本次设置时的值，包括修改过的密钥；已完成的生成、下载、预热和清理任务保留结果。撤回快照闲置两小时后过期，服务重启后失效。多个窗口发生版本冲突时，重新打开设置核对最新值后再修改。

## 提示词与输出格式

两种模式各自的“提示词”页列出适用项目。

- 默认写作规则把角色卡与世界书当作叙事背景，通过人物言行自然呈现设定。两种模式的人物原则相同：从各人物自身的愿望、所知与能力出发演绎，人物只知道自己经历、听闻或推断得来的事。用户对结果有多大决定权，由用户在本轮偏好中自行约定。
- Half Agent 的 Tracker 使用独立提示词处理记忆、变量和授权的设定维护。Full Agent 的系统提示词侧重叙事与判断，操作协议随工具提供；它按需查证重要旧事实或相互冲突的记录，维护交接笔记与长期笔记时保留仍有效的经历和关系。自定义提示词可调整写作倾向，工具权限与提交校验由运行时执行。
- Half Agent Writer 的检索线索使用 `<tavern_retrieval>` 区块，运行时分离保存；修改相关提示词时，需让输出协议与检索设置保持一致。Full Agent 通过工具保存检索线索。
- Tracker 记忆使用 `write_memory` 的增量操作与来源编号，见[记忆协议](../design/memory-consistency.md#短编号输出协议)。本地重排使用 yes/no token 概率评分，接口检查使用 `TAVERN_MID_42` 标记；编辑对应提示词时须保留这些程序解析约定。
- “本轮偏好”和重生成“补充要求”的系统引导词在提示词页配置，具体创作要求在输入框中保存。消息角色与标签设置见[消息类型与适配](message-adapter.md)。

重新生成选项在生成期间收起，正常完成后保持收起；回合报错且可重试时自动展开，便于调整要求后重试。

## 常用偏好

“设置 → 通用 → 常用偏好”（位于“制卡 agent”之后）可新增、改名、修改或删除条目，点击“保存常用偏好”提交；该页支持撤回。

在会话设置中填写“本轮偏好”后，点击“保存为常用偏好”并命名即可复用。常用偏好由两种模式共用，保存具体内容；各模式的系统引导词分别配置。选择偏好后可“替换”或“追加”到当前输入，再点会话设置的“保存”生效。之后修改偏好库，不影响已保存的会话偏好。

## 杂项

“设置 → 通用”最后一页为“杂项”。该页支持撤回修改。

**输入时发送和换行**：统一控制剧情、参谋 agent 和制卡 agent 的聊天输入框，自动保存后立即生效，随个人设置导入导出。

| 方案 | 发送 | 换行 |
| --- | --- | --- |
| Enter | Enter | Shift+Enter |
| 默认：Ctrl+Enter | Ctrl+Enter（macOS 也支持 Command+Enter） | Enter 或 Shift+Enter |
| Shift+Enter | Shift+Enter | Enter |
| 仅按钮 | 点击发送按钮 | Enter 或 Shift+Enter |

所有方案都可点按钮发送。输入法组合输入期间的 Enter 不触发发送；角色卡引用候选仍优先用 Enter／Tab 确认。放大编辑与历史编辑的快捷键保持各自规则。

**回复完成后定位到正文开头**（“阅读”组）：默认开启。页面跟随最新内容时，回复完成后跳到本条正文开头；关闭后停留在末尾。未跟随时始终保持当前阅读位置。自动保存后立即生效，随个人设置导入导出，详见[阅读、编辑与分支](story-history.md#定位历史)。

**界面操作**：再次点击左侧导航中当前所在的“会话”“角色卡”或“制卡”，会折叠或展开列表面板；点击其他分类则切换并展开。会话列表中的游玩对话单击打开，双击或点行内按钮重命名；进入编辑后自动选中标题，Enter 保存、Esc 取消。

### Full Agent 前缀消息稳定性测试

位于“调试”组，默认关闭，从下一次 Full Agent 操作生效，用于检查请求前缀是否稳定（影响提示缓存命中）。

- 开启后，运行时只在内存中暂存最近两次模型生成的真实 HTTP 请求正文，捕获点在 SDK 序列化之后，包括工具续答、失败请求和缓存拒绝后的重试；切换会话或模型后仍按最近两次请求比较。
- 首次请求只通知已建立基线；之后每次比较都通过通知报告，结果也可在本轮工作记录中查看。
- 比较按每个实际顶层 JSON 参数的 UTF-8 原始字节进行，分别报告 `messages`／`input`／`contents`、`tools`、`system`／`instructions`／`systemInstruction` 和其他实际参数；不拼接、不重排、不重新序列化。
- 消息参数一致，或数组只在末尾追加且旧内容逐字节不变时，显示“公共前缀与首个差异未错位”；否则显示“公共前缀或首个差异发生错位”。其他参数只显示“一致”或“不一致”，新增和移除的参数单独标出。通知不显示字节数或差异位置，也不含正文原文；HTTP 头和认证信息不参与比较。
- 不额外落盘原始请求，不修改发往模型的数据。关闭后，在下一次 Full Agent 操作或退出应用时清除暂存。支持自动保存、页面撤回和个人设置导入导出。

### 保留失败请求原始数据

位于“调试”组，默认关闭，保存后从下一次操作生效。覆盖普通 API 与 ChatGPT 官方渠道的模型生成请求，包括正文、Tracker、MVU、参谋 agent、制卡 agent、上下文整理和连接检查。

- 开启后，遇到 HTTP 错误、响应解析失败、流中错误、连接中断或取消时，保存实际发送的请求正文、失败前已收到的原始响应字节和 HTTP 信息；成功的请求不落盘。重发后成功的请求，仍保留此前失败的 HTTP 尝试。
- 在本页“失败请求记录”中刷新列表（每页 100 条）、查看 HTTP 信息并下载 ZIP。“清空”经确认后只删除失败请求记录，运行中或可恢复任务的记录保留，剧情、工作记录和其他日志不受影响。
- ZIP 内容：`metadata.json` 记录来源、HTTP 状态、异常类型、正文接收、截取和脱敏后的保存字节数、截断和读取结束状态；`request.bin`、`response.bin` 保留正文与原始事件分隔；没有收到 HTTP 响应时没有 `response.bin`。响应正文标为 `representation=transport` 时是未压缩的 HTTP 传输字节；带压缩编码的响应由 HTTP 客户端先解码再截取与脱敏，标为 `decoded`，无需再解压。旧记录若标为 `transport` 且带 `content-encoding`，仍需按原编码解压。
- 认证头、Cookie、URL 中的认证参数和正文中出现的实际认证密钥都会脱敏，截取边界处的不完整密钥也会隐藏；其余内容仍可能包含完整的角色资料、剧情和思考内容。
- 文件保存在当前数据目录的 `runs/request-debug/`，只用于本地诊断，不回送模型，不参与剧情恢复。请求和响应各最多保留 8 MiB，且各不超过详细日志容量上限的四分之一，超出时明确标记；失败后不再额外等待或读取剩余响应。
- 空闲维护和“数据与存储”的清理沿用详细日志的保留天数与容量，目标保留最近 100 条；运行中、待审核和可恢复的记录受保护，可能暂时超出限额。关闭开关不删除已有记录。这些文件随本机完整备份保存，不随个人设置导出。

## 个人数据导入导出

在“设置 → 通用 → 数据与存储”选择设置、用户角色、角色卡或对话，导出为 ZIP 数据包。个人设置包括模型参数、提示词、常用偏好、共用配置，以及当前浏览器的阅读布局（字号、行距、宽度、字体、侧栏折叠与“毛玻璃效果”开关）。API Key 默认不导出；主动勾选后以明文写入，应作为私有文件保存。

对话包携带对话自己的角色资料、附件、已缓存依赖、消息分支、变量、记忆、运行模式和上下文记录，恢复后可继续游玩。参谋部分只携带故事级设置；咨询聊天和待续进度需通过完整备份保留。

导入先显示预览，确认后执行。用户角色、角色卡和对话都作为独立副本新增（重复导入也会再新增一份），原有数据保留。要恢复设置，另勾选“恢复包内个人设置”，并先结束相关的运行任务。恢复设置会替换当前配置：包内没有 API Key 时，只为标识和地址都相同的提供商保留本地已有密钥；模型能力需重新检查，ChatGPT 账号需重新连接。

数据包上传上限 256 MiB，解压后上限 512 MiB，较大的资料库可分批导出。单张 SillyTavern 角色卡从侧栏角色库导入；完整目录迁移以及制卡 agent 的对话与草稿使用[完整备份](maintenance.md#备份升级与回退)。

## Kemini 式实验功能

“全局设置 → 杂项”中的“启用 Kemini 式实验功能”主开关默认关闭。开启后，在普通 API 渠道新建对话时可勾选“Kemini 实验对话”；只有勾选创建的对话会应用正文函数参数传输、创作身份与显式自检、小说填充，其他对话完全不受影响。

**对话类型**

- 与普通 API／ChatGPT 官方渠道一样，对话类型在创建时固定，不能互相转换，分支和数据包继承原类型。ChatGPT 官方渠道不能创建 Kemini 实验对话；已有对话均为普通对话。
- Kemini 实验对话在会话列表、最近对话和游玩标题中以梅紫色头像描边区分。
- 关闭主开关后，已有 Kemini 实验对话暂停生成并提示重新启用，不会改用普通请求继续；场景记忆重建只运行 Tracker，不受影响。
- “普通免责声明”默认关闭，只在主开关开启时可操作，作用于全部 Kemini 实验对话；关闭主开关时保留其选中状态。

**作用范围**：只作用于 Kemini 实验对话中 Half Agent Writer 和 Full Agent 的剧情生成，覆盖普通 API 渠道现有的四种接口；不用于 Tracker、参谋 agent、制卡 agent 或脚本嵌套请求。不改变实际工具授权或模型思考档位，也不保证改变服务商的审核结果。

**提示与填充文本**：开关自动保存；提示与填充文本须显式保存，从下一次生成生效。“编辑实验提示与填充文本”开放全部十三项：小说填充、CLEAR、创作身份与文风、资料起始、角色扮演追加要求、助手确认、自检、正文约束、免责声明、正文传输指令、末尾输出提示、正文传输工具说明和正文参数说明。

- 各项的保存值是唯一生效来源，包括工具 schema 的两项 description，发送时不替换或追加隐藏文本。实验消息、函数定义及其 token 开销显示在上下文预览中。函数名 `kemini_emit_story`、参数名 `content` 和字符串必填结构由协议固定。
- 小说填充默认空白，未填写时该项不生效；不设 token 门槛，填写后完整发送。
- 默认文本参考 ST 的 Kemini v3.1 实际预览，采用用户审阅后的提示正文、首尾空白与换行：
  - 身份块中的写作规则与视觉小说文风展开为可编辑正文。
  - 独立边界 `</clear>`、`<info>`、`</interaction_history>` 用 Markdown 分隔符。
  - 输出区恢复原版完整的 `<Interleaving>...</Interleaving>` 三段式示例，全部自检段落保留原文；成对示例集中在同一条 `kemini_control` 消息中，CLEAR 和末尾输出提示只按名称引用 Interleaving，不放孤立开标签。
  - 显式自检去掉 `setvar/getvar` 宏，保留 `{{思考内容}}` 等格式示意和成对的 `<thinking>` 输出标签。
  - 正文约束默认要求简体中文、第三人称、正文不少于 1000 字，以非用户所扮演角色的言行或环境描写收尾，不绑定具体角色名。
  - 剧情与人物指导块不引入，只保留其最后一句“你会在</think>后直接以<thinking>进行首次思考”到末尾输出提示。
  - 助手确认使用本项目文本；免责声明、传输指令与工具描述沿用原文本。

**消息顺序**

- 小说填充 → CLEAR → 创作身份与文风 → 资料起始构成绝对前缀，整体位于所有应用消息之前，不参与配方、世界书或脚本的深度与位置计算，应用规则与检索协议也不能插入其中。空白项省略，非空文本完整保留。
- 前缀之后依次组装应用规则、资料、历史和本次输入。
- 尾部依次为：角色扮演追加要求 → 助手确认 → 自检 → 正文约束 → 可选免责声明 → 传输指令 → 末尾输出提示。前两项各自成条，后五项按顺序组成 `kemini_control`；传输指令位于末尾格式要求之前，与原脚本顺序一致。每次剧情请求和工具续答只附加当前一组临时提示，不回放旧副本。
- 实验请求不按角色把 system 前置：普通消息适配完成后，把中途的 system 转为 user，开头连续的 system 和真实工具交换保留，不合并不同来源的文本块；原生接口也不额外前置通用说明。实验对话的剧情消息适配页和上下文预览会显示这一规则；普通对话使用普通适配，已保存的角色映射不变。

**回复处理**

- 模型通过 `kemini_emit_story` 的 `content` 参数传回完整回复。此函数不执行业务操作，Full Agent 须先完成必要的工具任务。只收到普通正文时仍正常接收，并在工作记录中注明本轮未采用参数传输。渠道拒绝、参数错误、混合调用和不完整响应直接报错，不会自动关闭设置或付费重试。
- 代码围栏外的 `<Interleaving>`、`</Interleaving>` 外壳会被清除——只删标签，其内外正文全部保留；标签缺失或只有一边时照常接收，不报格式错误、不自动重试。同时分离 `<thinking>...</thinking>`，开启“普通免责声明”时还分离 `<disclaimer>...</disclaimer>`。代码围栏中的文字保持原样。
- 分离出的文本显示在每条回复下方默认折叠的“实验辅助记录”中，不执行脚本，也不进入后续剧情、Tracker、MVU 或卡片消息回调。辅助记录随对应回复版本保存；修改用户输入后的新尝试生成自己的辅助记录。修改设置不会重新处理历史回复。
- 正文与辅助记录原子保存，随回复版本、分支和个人数据包继承。原始响应保留在工作记录中，按既有日志策略清理；改写后的最终回复不会用旧原生附件覆盖已清理的正文。

升级到设置 version 13 时自动备份，并迁移 CLEAR、显式自检和末尾输出三项的保存文本（包括自定义值）：只替换可定位的旧格式段落与引用，保留首尾空白、换行和其他自定义要求；自定义值找不到可识别的格式段时，把完整的对应原文模块追加到同一字段。其他十项文本和已有回复不变。
