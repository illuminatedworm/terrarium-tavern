# 配置模型与应用设置

设置分为 full agent、half agent 和通用三组。游玩模型按“普通 API”和“ChatGPT 官方”两个渠道分别配置，故事在创建时确定渠道，之后可在同渠道内更换提供商和模型。

## 完成首次配置

1. 在“通用 → 提供商”添加普通 API 的域名和 API Key，或连接 ChatGPT 账号。
2. 在目标运行模式的“模型与生成”选择渠道、提供商、模型和协议。Half Agent 的“正文生成”与“后台整理”分别对应 Writer 和 Tracker。
3. 核对页面显示的完整请求地址。API 路径留空时，Gemini 使用 `v1beta`，其他协议使用 `v1`；填写后按指定值使用。
4. 设置模型上下文容量、输出预算及采样／思考选项，再检查连接。Full Agent 和 Tracker 的相关能力需要模型支持工具调用。
5. 按需在“通用 → 制卡 agent”或“通用 → 参谋 agent”配置各自的独立模型。

模型选单支持搜索候选项，也可输入模型 ID 后选择“使用此模型 ID”。方向键选择、Enter 确认、Esc 关闭。普通 API 的“更新模型列表”请求提供商并保存目录；游玩对话、参谋 agent 和制卡 agent 的模型选单顶部另有“获取模型列表”，行为相同；ChatGPT 连接先读取已保存目录，再自动刷新。各提供商分别保存目录，更新失败时保留原列表。

每处模型连接设置都按提供商分别保存 API 路径、接口方式和模型名称；切换提供商会恢复该处上次保存的三个值。Full Agent、Half Agent 的 Writer／Tracker、制卡 agent、参谋 agent 的记录相互独立，重开设置、重启及设置导入导出都会保留。首次选择尚无记录的普通 API 提供商时，接口为 Chat Completions、API 路径留空、模型留空；ChatGPT 官方使用固定的 Responses 接口。请按该提供商要求填写后再使用。

游玩和制卡输入区也可选择同渠道提供商与模型，选择随当前对话保存，分支继承。参谋 agent 的选择在点击“应用”后保存到当前故事的咨询。各对话会记住每个提供商上次选用的模型名称；接口与 API 路径读取对应角色设置中该提供商的记录，模型菜单中显示当前连接参数及编辑位置。Half Agent 输入框只切换 Writer，Tracker 在设置中单独配置。预算、采样等其他参数仍由对应角色设置统一控制。新提供商尚未选择模型时，游玩和制卡发送按钮不可用。

运行、待审核和上下文整理期间保持当前选择。设置页与输入区共用思考档位，已保存但当前模型不适用的档位会提示重选。具体映射见[模型接入参考](../reference/model-api.md)。

## 使用 ChatGPT 订阅

1. 在“通用 → 提供商 → ChatGPT 官方”点击“连接 ChatGPT 账号”，进入账号管理并选择 **Continue with ChatGPT**。
2. 在系统浏览器选择账号和工作区，授权应用使用订阅额度。返回后确认显示“已连接 · 已启用 ChatGPT 订阅使用”；若只完成身份登录，可点击“启用订阅使用”补充授权。
3. 在各运行模式、制卡 agent 或参谋 agent 设置中，分别选择该提供商及账号目录中的模型。
4. 点击“检查连接”执行一次最小推理检查，这会使用账号额度。“管理用量”打开 [ChatGPT 用量设置](https://chatgpt.com/settings/usage)。

支持管理多个账号和工作区，资格、模型及服务地区以官方返回为准。应用通过 Sign in with ChatGPT 获取独立授权，恢复备份或换机后需重新连接并选择账号。

官方渠道的两种游玩模式都可选择云端 compact：Full Agent 在“窗口与笔记”切换，Half Agent 在“场景 → 上下文方式”切换。新故事默认使用本地上下文，Half Agent 的 Tracker 周期记忆继续独立运行。

官方思考档位来自账号模型目录，`xhigh` 与 `max` 分别发送；当前接口拒绝的档位显示为不可选。“模型默认”使用目录声明的默认值，未知能力交由服务端处理。

登录回调监听本机临时端口，有效期十分钟，可取消后重试。凭据保存在数据目录的 `.chatgpt/`：Windows 使用当前用户 DPAPI 加密，Unix 使用仅所有者可读写的权限。账号凭据、注册信息和安装标识绑定当前安装，数据导出与完整备份均排除这些内容。

退出账号会停止其请求并尝试撤销远程会话。显示“未确认远程撤销”时，本地凭据已清除，可到 ChatGPT 的“Security and login → Sign in with ChatGPT”断开应用。账号额度与 credits 按 ChatGPT 设置使用；认证或额度问题按对应错误处理。

## 设置影响范围

应用的代理地址默认为空，空地址按直连处理；需要代理时在“设置 → 通用 → 网络与代理”填写完整 HTTP(S) 地址，再打开模型接口、本地模型下载和角色卡外部资源的代理开关。应用请求不自动继承系统环境代理。已有保存的代理地址和开关保持原值；制卡评测工具也遵循这些配置。

| 配置 | 范围与生效方式 |
|---|---|
| 模型、预算、采样、提示词和检索参数 | 各模式独立，下一次操作使用新值 |
| Full Agent 工具与记忆参数 | Full Agent 后续运行 |
| 提供商、API 代理、本地模型和存储限额 | 共用资源，后续操作使用新值 |
| 会话中的模型选择、偏好和保存方式 | 当前对话，分支继承 |
| 游玩和制卡的消息适配默认值 | 创建对话时复制；已有对话在自己的入口调整 |
| 阅读与布局 | 当前浏览器 |

游玩输入框的“更新变量”会立即保存到当前对话，后续回合沿用；切换界面、重开对话或刷新页面都会恢复，分支继承后可独立调整。新对话及尚未保存此选项的旧对话默认不勾选。Full Agent 停用变量更新工具时，开关不可用，重新启用工具后恢复保存的选择。“允许修改设定”仍只授权本轮。

左侧导航的“会话”“角色卡”“制卡”再次点击当前分类时切换列表面板的折叠状态；点击其他分类会切换并展开列表。

会话列表中的游玩对话可单击打开、双击重命名，也可使用行内重命名按钮；进入编辑后自动选中标题，按 Enter 保存、Esc 取消。

运行中的回合使用开始时的配置快照。共享提供商变更影响所有引用该提供商的模型，删除前需解除引用。

“通用 → 网络与代理 → 模型请求方式”可统一选择普通 API 的流式或非流式传输，覆盖游玩、后台、制卡和辅助模型生成。默认“由各任务决定”，沿用各调用方方式；ChatGPT 官方渠道始终流式，目录、向量、缓存管理和 compact 使用各自请求。

Full Agent 流式正文先显示为“正文预览 · 未保存”，完整响应、工具要求和脚本处理通过后提交，或进入审核。包含工具调用的中间文字转入过程记录；断流、失败或取消时保留已校验进度供重试。

## 保存与撤回

普通输入在短暂停顿后自动保存，开关与选择项立即进入保存队列。页面显示保存中、已保存或错误；关联条件有误时保留草稿供修正。

提示词等大文本通过绿色勾或 Ctrl+Enter 保存，放大编辑与恢复默认文本使用同一规则。离开未保存文本时可继续编辑或放弃该草稿。

“撤回本页修改”恢复打开本次设置时的值，包括修改过的密钥；已完成的生成、下载、预热和清理任务保留其结果。撤回快照闲置两小时后过期，服务重启后失效。多窗口发生版本冲突时，重新打开设置核对最新值，再继续修改。

## Kemini 式实验功能

“全局设置 → 杂项”提供默认关闭的“启用 Kemini 式实验功能”主开关。开启后，新建对话时可在普通 API 渠道勾选“Kemini 实验对话”；只有勾选创建的对话应用正文函数参数传输、创作身份与显式自检、小说填充，其他对话完全不受影响。与普通 API 和 ChatGPT 官方渠道一样，两种对话在创建时固定，不能互相转换，分支和数据包继承原类型；ChatGPT 官方渠道不能创建 Kemini 实验对话。Kemini 实验对话在会话列表、最近对话和游玩标题中以梅紫色头像描边区分，不另加文字标签。已有对话均为普通对话。

关闭主开关后，已有 Kemini 实验对话暂停生成并提示重新启用，不会以普通请求继续；场景记忆重建只运行 Tracker，不受影响。“普通免责声明”默认关闭，仅在主开关开启时可操作，作用于全部 Kemini 实验对话；关闭主开关时保留其选中状态。

实验仅作用于 Kemini 实验对话中 Half Agent Writer 和 Full Agent 的剧情生成，覆盖普通 API 渠道的现有四种接口；不应用于 Tracker、参谋 agent、制卡 agent 或脚本嵌套请求。开关自动保存，所有提示与填充文本须显式保存，从下一次生成生效。填充默认空白，未填写时该项不生效；不强制 token 门槛，填写后完整发送。

“编辑实验提示与填充文本”开放全部十三项：小说填充、CLEAR、创作身份与文风、资料起始、角色扮演追加要求、助手确认、自检、正文约束、免责声明、正文传输指令、末尾输出提示、正文传输工具说明和正文参数说明。各项保存值是唯一生效来源，包括工具 schema 的两项 description；没有另行追加的只读 Kemini 提示。实验消息、函数定义及其 token 开销进入上下文预览。函数名 `kemini_emit_story`、参数名 `content` 与字符串必填结构由协议固定。

默认文本参考 ST 的 Kemini v3.1 实际预览，身份块中的写作规则与视觉小说文风已展开为可编辑正文。独立边界的 `</clear>`、`<info>`、`</interaction_history>` 与输出区的 `Interleaving` 包装改用 Markdown 分隔符，相关引用同步改写；不要求输出 `Interleaving` 标签。显式自检移除 `setvar/getvar` 宏，`{{思考内容}}` 等格式示意及成对的 `<thinking>` 输出标签保留。正文约束默认要求简体中文、第三人称、正文不少于 1000 字，以非用户所扮演角色的言行或环境描写收尾；不绑定具体角色名。剧情与人物指导块不引入，仅保留其最后一句“你会在</think>后直接以<thinking>进行首次思考”到末尾输出提示。助手确认沿用本项目文本，小说填充默认留空。免责声明、传输指令与工具描述沿用原文本，传输函数名为 `kemini_emit_story`；请求组装直接读取保存值，不在发送时替换或追加隐藏文本。

启用时，小说填充 → CLEAR → 创作身份与文风 → 资料起始构成绝对前缀，四条整体位于所有应用消息之前，不参与配方、世界书或脚本的深度与位置计算，应用规则与检索协议不能插入其中。空白文本按用户保存值省略，所有非空文本完整保留。前缀之后才组装应用规则、资料、历史及本次输入；尾部依次为角色扮演追加要求 → 助手确认 → 自检 → 正文约束 → 可选免责声明 → 传输指令 → 末尾输出提示。角色扮演追加要求和助手确认各自成条，后五项按顺序组成 `kemini_control`；传输指令仍在末尾格式要求之前，与原脚本顺序一致。每次剧情请求及工具续答只附加当前一组临时提示，不回放旧副本。实验请求不再按角色将 system 前置；普通消息适配完成后，将中途 system 转为 user，开头连续的 system 和真实工具交换保留，不合并不同来源的文本块。原生接口也不再额外前置通用说明。Kemini 实验对话的剧情消息适配页和上下文预览显示此规则；普通对话使用普通适配，不改写已保存的角色映射。

模型通过 `kemini_emit_story` 的 `content` 参数传回完整回复。此函数不执行业务操作，Full Agent 须先完成必要工具任务；只收到普通正文时仍正常接收，并在工作记录中注明本轮未采用参数传输。渠道拒绝、参数错误、混合调用和不完整响应直接报错，不自动关闭设置或付费重试。

Kemini 实验对话分离 `<thinking>...</thinking>`，“普通免责声明”开启时还分离 `<disclaimer>...</disclaimer>`；代码围栏中的文字保持原样。分离后的文本显示在每条回复下方默认折叠的“实验辅助记录”，不执行脚本，也不进入后续剧情、Tracker、MVU 或卡片消息回调。正文编辑不修改生成时的辅助记录。历史回复不因修改设置而重新处理。

正文及辅助记录原子保存，随回复版本、分支和个人数据包继承。原始响应在工作记录中保留，按既有日志策略清理；经改写的最终回复不使用旧原生附件覆盖已清理正文。此实验不改变实际工具授权或模型思考档位，不保证改变服务商审核结果。

## 提示词与输出格式

两种模式各自的“提示词”页列出适用项目。默认写作规则将角色卡与世界书作为叙事背景，通过人物言行自然呈现设定；两种模式使用相同的叙事与阻力原则：用户描述的行动结果不自动决定其他人物的反应，戏外的明确创作要求按其实际范围处理。Half Agent 的 Tracker 使用独立提示词处理记忆、变量和授权设定维护；Full Agent 的系统提示词侧重叙事与判断，操作协议随工具提供。

Full Agent 对重要旧事实或相互冲突的记录按需查证，维护交接笔记与长期笔记时保留仍有效的经历和关系。自定义提示词可调整写作倾向，工具权限与提交校验由运行时执行。

Half Agent Writer 的检索线索使用 `<tavern_retrieval>` 区块，运行时分离保存。修改相关提示词时，需让输出协议与检索设置保持一致。Full Agent 通过工具保存检索线索。

Tracker 记忆使用 `write_memory` 的增量操作与来源编号，见[记忆协议](../design/memory-consistency.md#短编号输出协议)。本地重排使用 yes/no token 概率评分，接口检查使用 `TAVERN_MID_42` 标记；编辑对应提示词时保留这些程序解析约定。

“本轮偏好”和重生成“补充要求”的系统引导词在提示词页配置，输入框保存具体创作要求。消息角色与标签设置见[消息类型与适配](message-adapter.md)。

重新生成选项在生成期间收起，正常完成后保持收起；回合报错且可重试时自动展开，便于调整要求后重试。

## 常用偏好

该页位于“通用 → 制卡 agent”之后。

在会话设置中填写“本轮偏好”，点击“保存为常用偏好”并命名即可复用。常用偏好由两种模式共用，保存具体内容；各模式的系统引导词分别配置。

选择偏好后，可“替换”或“追加”到当前输入，再点击会话设置的“保存”使其生效。修改偏好库后，已保存的会话偏好保持原值。

在“设置 → 通用 → 常用偏好”可新增、改名、修改或删除条目，点击“保存常用偏好”提交；该页支持撤回修改。

## 杂项

“调试 → Full Agent 前缀消息稳定性测试”默认关闭，从下一次 Full Agent 操作生效。开启后，运行时只在内存暂存最近两次模型生成的真实 HTTP 请求正文，捕获点位于 SDK 序列化之后，包括工具续答、失败请求及缓存拒绝后的重试；切换会话或模型仍按运行时最近两次请求比较。首次请求通知已建立基线，此后每次比较均通过现有通知组件报告，结果也可在本轮工作记录中查看。

比较保留每个实际顶层 JSON 参数值的 UTF-8 原始字节，分别报告 `messages`／`input`／`contents`、`tools`、`system`／`instructions`／`systemInstruction` 和其他实际参数，不拼接参数、不重排或重新序列化，也不猜测服务商内部如何组成提示词。消息参数（`messages`／`input`／`contents`）一致或数组追加且旧内容逐字节保留时，通知显示“公共前缀与首个差异未错位”；不一致时显示“公共前缀或首个差异发生错位”。其他参数只显示“一致”或“不一致”，新增及移除参数单独标记。通知不显示字节数、差异位置或计数口径说明。HTTP 头和认证信息不参与比较，通知与比较结果不包含正文原文。此功能不额外落盘原始请求，不修改发往模型的任何数据；关闭后在下一次 Full Agent 操作或退出应用时清除暂存。支持自动保存、页面撤回及个人设置导入导出。

“调试 → 保留失败请求原始数据”默认关闭，保存后从下一次操作生效，覆盖普通 API 与 ChatGPT 官方渠道的模型生成请求，包括正文、Tracker、MVU、参谋 agent、制卡 agent、上下文整理和连接检查。开启后，HTTP 错误、响应解析失败、流中错误、连接中断及取消会保存实际发送的请求正文、失败前已接收的原始响应字节和 HTTP 信息；成功请求不落盘。重发后成功的请求仍保留此前失败的 HTTP 尝试。

在本页“失败请求记录”刷新列表、查看 HTTP 信息并下载 ZIP；“清空”经确认后只删除失败请求记录，运行中或可恢复任务的记录保留，剧情、工作记录和其他日志不受影响。包内 `metadata.json` 记录来源、HTTP 状态、异常类型、正文接收、截取和脱敏保存字节数、截断和读取结束状态；`request.bin`、`response.bin` 保留正文与原始事件分隔。响应正文的 `representation=transport` 表示按 HTTP 传输字节保留，可能需按响应头 `content-encoding` 解压；`decoded` 表示 HTTP 客户端已解码的正文，无需再次解压。没有收到 HTTP 响应时无 `response.bin`。认证头、Cookie、URL 中的认证参数和正文中出现的实际认证密钥会脱敏，其余数据仍可能包含完整角色资料、剧情及思考内容。

原始数据保存在当前数据目录的 `runs/request-debug/`，只用于本地诊断，不回送模型，不参与剧情恢复。请求和响应各保留最多 8 MiB，并各自不超过详细日志容量上限的四分之一，超过时明确标记；失败后不额外等待或读取剩余响应。空闲维护和“存储与维护”的清理沿用详细日志保留天数与容量，目标保留最近 100 条；运行中、待审核和可恢复记录受保护，可能暂时超过限额。列表每页 100 条。关闭开关不删除已有记录；这些文件随本机完整备份保存，不随个人设置导出。

“设置 → 通用”最后一页为“杂项”。“输入时发送和换行”统一控制剧情、参谋 agent 和制卡 agent 的聊天输入框，自动保存后立即生效，并随个人设置导入导出。

| 方案 | 发送 | 换行 |
| --- | --- | --- |
| 默认 | Enter | Shift+Enter |
| Ctrl+Enter | Ctrl+Enter（macOS 也支持 Command+Enter） | Enter 或 Shift+Enter |
| Shift+Enter | Shift+Enter | Enter |
| 仅按钮 | 点击发送按钮 | Enter 或 Shift+Enter |

所有方案均可点击按钮发送。输入法组合输入期间的 Enter 不触发发送；角色卡引用候选仍优先使用 Enter／Tab 确认。放大编辑与历史编辑的应用、保存快捷键保持各自原有规则。该页支持撤回修改。

## 个人数据导入导出

在“设置 → 通用 → 数据导入导出”选择设置、用户角色、角色卡或对话，导出为 ZIP 数据包。个人设置包括模型参数、提示词、常用偏好、共用配置和当前浏览器的阅读布局（字号、行距、宽度、字体、侧栏折叠与“毛玻璃效果”开关）。API Key 默认排除，主动勾选后以明文写入，应作为私有文件保存。

对话包携带自己的角色资料、附件、已缓存依赖、消息分支、变量、记忆、运行模式及上下文记录，恢复后可继续游玩。参谋部分携带故事级设置，咨询聊天和待续进度通过完整备份保留。

导入先显示预览，再确认执行。用户角色、角色卡和对话均新增为独立副本，重复导入也会新增，原有数据保留。需要恢复设置时，另勾选“恢复包内个人设置”，并先结束相关运行任务。

数据包上传上限为 256 MiB，解压后上限为 512 MiB，较大的资料库可分批导出。单张 SillyTavern 角色卡从侧栏角色库导入，完整目录迁移使用备份恢复。

恢复设置会替换当前配置。数据包省略 API Key 时，仅为相同标识、相同地址的提供商保留本地已有密钥；模型能力需重新检查，ChatGPT 账号需重新连接。制卡 agent 的对话与草稿通过[完整备份](maintenance.md#备份升级与回退)迁移。
