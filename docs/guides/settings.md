# 配置模型与应用设置

设置分为 full agent、half agent 和通用三组。游玩模型在每种模式下再分“普通 API”和“ChatGPT 官方”两类，分别保存连接；创建对话时固定渠道归属，之后只能更换同一渠道内的供应商或模型。角色卡编辑 agent 模型单独保存。

## 完成首次配置

1. 在“通用 → 提供商”选择渠道。“普通 API”添加域名和 API Key 连接；“ChatGPT 官方”连接订阅账号。供应商创建后不能跨渠道修改认证类型。
2. 在对应模式的“模型与生成”选择同一渠道，再选择提供商、模型名和接口协议。Half Agent 的“正文生成”和“后台整理”分别对应 Writer 和 Tracker，始终使用对话所属渠道的一组配置。
3. 核对模型页显示的完整请求地址。API 路径留空时，Gemini 使用 `v1beta`，其余协议使用 `v1`；显式填写后按原值使用。
4. 设置上下文容量、输出预算和需要的采样／思考选项，执行连接检查。Full Agent 和 Tracker 的相关能力需要模型支持工具调用。
5. 如需 Agent 编辑角色卡，在“通用 → 角色卡编辑 agent”另行配置模型。

模型名称通过按钮打开选单，搜索框每次打开均为空，不继承当前模型 ID；可搜索候选项，或输入未收录的 ID 后选择“使用此模型 ID”。仅输入搜索词不会修改配置。全局设置、游玩和制卡使用同一套选单，支持方向键选择、Enter 确认和 Esc 关闭。

“更新模型列表”会向提供商请求列表并替换数据库缓存。普通 API 和 ChatGPT 官方都按每个供应商独立持久保存，重启后读取；同域名或同密钥的两个供应商也不共用目录。同一供应商的 Chat Completions 与 Responses 在模型接口地址和凭据相同时共用目录，旧缓存可直接恢复。地址、凭据或官方账号授权改变后重新获取目录。API Key 连接仅在明确更新时联网；ChatGPT 订阅连接先读取已保存目录，再自动刷新。更新失败保留同一连接的原列表。

Full Agent、Half Agent 和制卡输入框均可选择同渠道供应商与模型；普通 API 和官方渠道不能互换，后端也会校验归属。选择保存在当前对话，不改写全局模型配置；Half Agent 仅切换 Writer，Tracker 保持独立配置。协议、API 路径、采样和预算继续沿用对应模式配置。发送、重新生成、失败继续和只读上下文预览使用当前对话选择；剧情分支继承源对话的选择。正在生成、待审核或整理上下文时不能切换。

改变模型名称不会自动改变接口协议。服务商同一模型可能有多个接入路径，应同时核对协议和地址。字段映射、思考强度及缓存时效见[模型接入参考](../reference/model-api.md)。

普通 API 的思考强度按当前接口及已知模型能力展示，设置页和输入框使用同一套规则。例如 Gemini 3.8 Flash 只提供低、中、高与模型默认；Gemini 2.5 原生档位显示对应思考 token 预算。切换接口或模型后，已选但不适用的档位会提示重选，不自动修改配置。未知中转能力以服务商实际支持为准。

## 使用 ChatGPT 订阅

1. 在“通用 → 提供商 → ChatGPT 官方”点击“连接 ChatGPT 账号”，展开账号管理并点击 **Continue with ChatGPT**。
2. 在系统浏览器中选择符合资格的 ChatGPT 付费账号和工作区，并明确授权应用使用订阅额度。返回应用后，确认账号显示“已连接 · 已启用 ChatGPT 订阅使用”。只完成身份登录时，点击“启用订阅使用”补充授权。
3. 在 Full Agent、Half Agent 的正文／后台或“通用 → 角色卡编辑 agent”中，分别选择这个提供商和账号目录中的模型。登录不会自动更换各 Agent 的提供商或模型；更改一个共享提供商会影响所有引用它的 Agent。
4. 点击“检查连接”完成一次最小推理检查，此检查也使用该账号的订阅额度。输入区和模型页的“管理用量”会打开 [ChatGPT 用量设置](https://chatgpt.com/settings/usage)。

该模式使用官方 Sign in with ChatGPT 动态注册及公开 Responses 接口，不读取 Codex CLI 的登录文件。支持多个账号／工作区，邮箱相同的注册也分别显示；恢复备份或换到另一台机器后，需要重新连接并选择该安装中的账号。

普通 API（包括直连 OpenAI 的 API Key）不能进入官方渠道对话，也不能启用云端 compact。官方渠道的两种 Agent 模式都可选择云端 compact，新对话默认本地上下文。Full Agent 在“窗口与笔记”切换；Half Agent 在“场景 → 上下文方式”切换，compact 代替 Writer 滚动裁剪，Tracker 周期记忆、变量和设定维护继续运行。旧对话若无法确定渠道，会要求一次性确认归属，不会按当前全局连接自动改类。

“输出预留预算”只参与本地上下文计算，不限制服务端实际输出。当前订阅通道不支持温度、top-p、服务端输出 token 上限和显式缓存控制，界面会隐藏这些控件；原参数保留，切回 API Key 模式后继续使用。超长原文仍完整发送，服务商拒绝时显示真实失败。

思考强度按当前账号模型目录中的支持档位展示，设置页和输入框保持一致。“超高（xhigh）”原样发送为 `reasoning.effort=xhigh`，不映射为 high 或 max；目录中的 max 单独显示。目录声明但当前订阅直连接口不接受的 ultra 显示为不可选，并说明原因。切换模型后，已保存但不支持的档位会提示重选，不静默降档。

登录回调仅监听本机临时端口，十分钟内有效；可以取消后重试。令牌由后端保存在数据目录的 `.chatgpt/` 中：Windows 使用当前用户 DPAPI 加密，Unix 使用仅所有者可读写的权限。账号凭据、注册信息和安装标识不包含在数据导出、完整备份或发行包中，也不受设置页撤回影响。不要手动复制凭据文件迁移账号。

退出账号会停止其运行中的请求并尝试撤销远程会话。如果显示“未确认远程撤销”，本地令牌已清除，可在 ChatGPT 的“Security and login → Sign in with ChatGPT”中断开应用。额度或权限不足时不会自动换账号或使用 API Key 计费；额度和 credits 的实际使用遵循用户在 ChatGPT 中的设置。

本功能面向本地使用；资格、模型和服务地区以 OpenAI 返回的结果为准。官方契约见[注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[当前限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

## 设置影响范围

在“通用 → 网络与代理 → 模型请求方式”中可统一切换普通 API 的流式／非流式传输，覆盖 Full Agent、Half Agent Writer、Tracker、制卡和辅助模型生成请求。选择后自动保存，从下一次操作生效，已开始的任务继续使用原快照。

默认“保持现有行为”：Full Agent 和多数后台任务一次性接收回复，Half Agent Writer 与制卡助手流式接收。选择“流式”后，一次性返回接口也通过 SSE 接收并汇总完整回复；选择“非流式”后，流式调用入口等待完整 JSON 回复。工具调用、用量和完成状态仍按完整响应校验，断流不视为成功。

开启流式后，Full Agent 边接收边显示“正文预览 · 未保存”，完整响应、本轮规则、脚本和变量处理全部通过后才正式保存；需要审核时继续等待确认。同一回复最终包含工具调用时，临时文字转入过程记录；被规则否决的正文预览清除。断流、接口报错或取消只留下未提交草稿，不写入剧情或执行残缺工具调用。重试从已校验的工具进度续接，不把残缺正文当作上下文。页面刷新或 SSE 重连按事件序号恢复预览，不重复追加文本。

页面进度 SSE 始终保留。ChatGPT 订阅通道要求流式，始终使用流式，也支持 Full Agent 正文预览；模型目录、向量、缓存管理和云端 compact 等独立端点不受此选项影响。

新建故事的临时用户名称默认是“用户”；选择已保存的用户角色时使用该角色的名称。已有会话和用户角色保留原名，包括旧默认名称“旅人”，不会自动迁移或改写；如需改名，可在会话设置或用户角色编辑中主动修改。

| 设置 | 保存范围 | 生效时间 |
|---|---|---|
| 模型、预算、采样、提示词、检索参数 | 各模式独立 | 保存后的下一次操作 |
| Full Agent 工具与记忆参数 | Full Agent | 下一回合 |
| 历史裁剪、周期记忆和分类记忆参数 | Half Agent | 下一次相关操作 |
| 提供商、密钥、API 代理、本地模型文件、日志和索引容量 | 两种模式共用 | 后续使用这些资源的操作 |
| 默认对话权限 | 各模式独立 | 未单独设置权限的会话从下一轮继承 |
| Half Agent 上下文配方和注入方案 | 创建会话时复制 | 仅新建会话；已有会话保留自己的设置 |

已开始的回合使用开始时的配置快照。修改共享提供商影响所有引用它的模型；删除提供商前必须解除引用。检索任务提示词、重排开关、重排提示词和片段数量属于各模式运行参数，模型文件本身属于共享资源。

## 保存与撤回

普通输入短暂停顿后自动保存，开关与选择项立即排队保存。页面显示保存中、已保存或错误状态；关联约束不满足时保留草稿，等待修正。

提示词等大文本使用独立保存：

- 点击绿色勾，或按 `Ctrl+Enter` 保存该文本。
- 放大编辑窗口使用相同规则；恢复默认文本后也需要保存。
- 离开未保存文本时，可以继续编辑或放弃修改。放弃只清除未保存文本，不撤回已经保存的普通参数。

“撤回本页修改”将该页恢复到本次打开设置时的值，已修改密钥也可以恢复。生成、下载、预热和清理等已执行任务不随设置撤回。

刷新或退出不保证保留未保存草稿；撤回快照闲置两小时后过期。多个窗口同时编辑发生修订冲突时，关闭并重新打开设置，核对最新值后再修改。

## 提示词与输出格式

需要调整中途应用消息的角色或标签时，参阅[消息类型与适配](message-adapter.md)。全局默认值只影响新对话，对话内的修改从下一次模型调用生效。

两种模式各自的“提示词”页提供适用项目。两种模式的默认顶级规则都将世界书和角色资料视为叙事背景，要求设定通过人物言行自然流露，在情境需要时才出现。Half Agent 使用统一的 Tracker 系统提示词，覆盖文本记忆、授权设定维护和变量任务；具体工具权限由本轮任务决定。Full Agent 的操作协议在工具说明中，系统提示词负责叙事与信息判断原则。

Full Agent 默认系统提示词要求：重要既有事实、约定或机制不明确，或记录互相冲突时，先查阅相关笔记、历史或设定再续写；更新交接笔记或长期笔记前先查看已有版本，保留仍然有效的经历与来龙去脉。提示词设置中的“恢复默认”使用同一版本。

编辑提示词时保留程序需要解析的格式：

| 内容 | 约定 |
|---|---|
| Half Agent 检索线索 | `<tavern_retrieval>` 标签 |
| Tracker 记忆写入 | `write_memory` 工具的增量操作与来源编号，见[记忆协议](../design/memory-consistency.md#短编号输出协议) |
| 本地重排判断 | yes/no token 概率评分 |
| 接口检查 | `TAVERN_MID_42` 标记 |

对话中的“本轮偏好”和重生成的“补充要求”显示当前模式的系统预制头，预制头只读。要改变它，在提示词设置中修改“对话偏好引导词”或“重新生成引导词”；输入框只保存用户填写的部分。

## 常用偏好

在会话设置中填写“本轮偏好”，点击“保存为常用偏好”并填写名称，即可保存可复用的创作偏好。常用偏好由两种模式共用，保存在应用配置中；系统预制头不会保存到常用偏好里。

选择常用偏好后，点击“替换”将内容填入本轮偏好，或点击“追加”保留已有内容并加入该偏好。填入后仍需点击会话设置的“保存”才会生效；保存成功提示显示 2 秒后自动消失，重复保存会重新计时。修改或删除常用偏好不会改变已经保存的会话偏好。

在“设置 → 通用 → 常用偏好”添加、修改名称和内容，或删除不再使用的常用偏好。点击“保存常用偏好”提交这一页的修改；离开未保存草稿时会提醒，也支持“撤回本页修改”。

## 个人数据导入导出

在“设置 → 通用 → 数据导入导出”选择个人设置、用户角色、角色卡和对话，下载 ZIP 数据包。用户角色、角色卡和对话可展开“选择条目”后按名称搜索、全选或单独勾选。

个人设置包含两种模式的模型与参数、提示词、常用偏好、共享配置，以及当前浏览器的阅读与布局偏好。API Key 默认排除；勾选“包含 API Key”后密钥会以明文写入数据包。

对话包会自动携带该对话独立保存的角色卡和附件、已缓存的脚本与远程资源、全部消息分支、变量、记忆、模式和上下文轨迹。即使原角色卡已从角色库删除，导入的对话也能继续游玩。若仅导出对话，关联角色卡不会作为新条目加入角色库。导出前需完成或取消所选对话正在运行或等待审核的回合。

点击“选择数据包”，先检查预览中的类别、条目和消息数量，再点击“确认导入”。用户角色、角色卡和对话始终新增为独立副本，重复导入也会新增副本；原有数据保留。导入后可点击“打开导入的对话，继续故事”，或从会话列表打开任一副本。

恢复个人设置需要主动勾选“恢复包内个人设置”。恢复会替换当前配置，需先结束运行中的故事或角色卡编辑 agent 任务。不含 API Key 的包会保留当前相同标识、相同地址提供商的本地密钥，其他连接需重新填写。恢复后模型能力检查需重新执行。

导入失败不会留下部分角色或对话。数据包上传上限为 256 MiB，解压后上限为 512 MiB，较大的资料库可分批导出。这是应用个人数据格式；单张 SillyTavern 角色卡仍从角色库原入口导入，完整数据库备份仍使用[安装与维护](maintenance.md)中的备份/恢复命令。
