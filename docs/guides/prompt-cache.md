# 配置与排查提示缓存

提示缓存复用模型请求中已处理的前缀。应用控制请求内容和断点，命中及费用取决于实际接入链路。黄色标记显示计划位置，实际读取与写入量从服务商响应查看。

## 选择控制方式

在相应模型的高级设置中选择：

| 方式 | 应用行为 | 默认用途 |
|---|---|---|
| 云端默认 | 完整发送请求，不注入本地断点或 Gemini 对象引用；部分协议仍发送独立时效字段 | Half Agent 后台、角色卡编辑 agent |
| 本地运行时控制 | 按会话选择稳定前缀的结束位置，编译对应缓存标记或对象引用 | Half Agent 正文、Full Agent |

自动预设按模型名与接入协议匹配。服务商需要不同字段时，可配置自定义字段名、JSON 值和附加请求参数；这些参数不能覆盖消息、模型、工具或采样等核心字段。字段映射见[模型接入参考](../reference/model-api.md#缓存时效)。

## 设置自动跟进

打开对话右侧“缓存”页。本地运行时控制下有两个参数：

- **每新增几轮跟进**：记为 M，只统计成功提交的新增 AI 正文，工具续答和重生成不计轮次。
- **倒数第几个 AI 回复**：记为 K，推进时定位到该回复末尾，在两次推进之间保持同一锚点。

新会话默认 M=2、K=2，已有会话保留已保存的策略。目标回复不足或尚未首次跟进时使用固定前缀。修改策略并保存后会立即重新定位，随后重新计数。

例如，默认策略下，第 2 个新增回复成功提交后，断点定位到当时倒数第 2 个回复；之后保持位置，直到又新增 2 轮。重生成任意一次候选回复不会推进这个计数。

对于已经确认能够稳定增量复用、且会继续使用当前历史的链路，可以考虑 M=1、K=2：每轮推进一次，并让最新回复留在断点之后，便于编辑或重试。程序默认仍为 M=2、K=2；整对象重建路线需另计成本。推导和适用条件见[缓存成本模型](../design/cache-cost.md)。

## 手动位置与时效

悬停已完成 AI 回复末尾，点击黄点可手动固定整条回复。开场白和工具交换不能作为目标。“定位断点”跳转到当前计划位置；恢复自动模式后按已保存策略重新定位。

断点不在当前分支或实际工作窗口内时，应用回退到固定资料前缀。修改固定设定、切换模型、编辑历史或换窗都可能改变可复用内容。OpenAI 路线还可能携带此前实际发送且仍匹配的标记，所以手动前移计划位置不会撤销所有较后的历史标记。

“缓存时效”按当前正文模型及协议显示可选档位，保存到该模式的模型设置，影响该模式所有会话，从下一次请求生效；跟进参数和手动位置只属于当前会话。切换模型名不会自动切换协议，应核对缓存页显示的接入方式。

更长时效可能增加写入或存储费用，应结合实际请求间隔和服务商账单选择。Gemini 对象 ID 由应用管理，不需要手工填写。

## 排查顺序

1. **核对接入。** 检查模型名、协议、实际请求地址、缓存模式和时效；同一模型的 Chat 与原生接口分别检查。
2. **核对位置。** 查看计划断点是否仍在当前窗口，是否刚发生编辑、换窗或策略推进。
3. **核对最终请求。** 工作记录中的状态会说明断点已发送、采用云端策略或因何降级。检查前缀与工具定义的摘要是否变化。
4. **核对用量。** 比较缓存读取、写入与输入合计。缺少字段时保持未知。
5. **核对账单。** 参数已发送或前缀哈希相同，都不足以证明服务商计费采用了缓存优惠。

| 现象 | 解释与下一步 |
|---|---|
| 一直停留在固定前缀 | 检查目标回复数量和跟进计数；新会话需先完成首次跟进间隔 |
| 显示已降级云端 | 查看具体原因，可能是参数不支持、对象创建失败或前缀条件不足 |
| Gemini 能生成但对象创建失败 | 生成和创建缓存对象是不同接口；检查服务商是否支持两者 |
| 推进后写入增加 | 检查是否只写入新增部分，以及随后的请求是否读取；结合连续请求判断是否持续重写 |
| 连续请求没有缓存字段 | 应用无法从缺失数据判断命中；使用原始 usage 和账单核对 |

对象失效或缓存字段明确被拒绝时，应用最多重新发送一次完整请求。普通超时、断流和服务端错误不会因此自动重发生成。

开发者可使用[运行记录审计](../development/validation.md#缓存链路评估)核对实际会话。协议与持久化细节见[缓存控制设计](../design/cache-control.md)。
