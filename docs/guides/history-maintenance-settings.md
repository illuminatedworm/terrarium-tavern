# 历史窗口与记忆维护设置

| 设置 | 默认值 | 作用 |
|---|---:|---|
| 窗口模式 | 按消息批次 | 也可按历史预算或关闭 |
| 历史消息 cap | 40 条 | 仅计用户和 AI 消息及本次输入，开场白算一条；不计中途世界书 |
| 每批移除量 | 10 条 | 仅计用户和 AI 消息，不计中途世界书；达标后对齐完整交流，实际量可更大，不要求偶数 |
| 记忆周期 | 5 轮 | 1–100，正文后检查，可与变量任务合并；裁剪前始终检查覆盖 |
| 当前进展条数上限 | 5 条 | 1–100，仅计算自动条目，超出后退出来源最旧者 |
| 经历冷却 | 20 轮 | 0–10000，0关闭时间准出；容量超限仍按旧到新退出经历 |
| 日常上下文预算（tokens） | 98,304 tokens | 与模型可用容量取较小值；本地 BPE token 估算 |
| 压力触发 / 目标 | 85% / 70% | 目标必须低于触发值 |
| 历史预算 | 6,000 tokens | 历史预算模式额外检查剧情与中途条目的容量 |
| Tracker 任务调用上限 | 8 次 | 2–100，分批、复核与工具续答共用；手动重建按批使用 |
| 维护超时 | 120 秒 | 每次 Tracker 请求独立计时，不自动重试 |

一轮是一次已提交的用户发言和回复。重生成不增加剧情轮数。
窗口条数与剧情轮数不是同一个单位，不能用批次除二来限制维护周期。

例如四次交流有八条剧情和二十条中途世界书，历史消息计数为八条；本次用户输入另计一条。世界书仅占用 token 预算。
触发裁剪后先整理将退出的剧情，再把交流与对应条目一同滚出。任何用户或 AI 消息退出时，紧贴其前的全部世界书条目一同退出，不占批次移除量。
最近两次完整交流受保护；固定设定加受保护内容本身过大时明确报错，不能靠持续裁剪解决。

关闭窗口会保留全部原文与已有条目，周期记忆仍运行，模型硬容量仍生效。
记忆失败但无需裁剪时继续正文并提示；需要裁剪而覆盖不足时阻止正文。
Writer 与 Tracker 的提供商、模型、容量与输出预算各自独立。模型名称应核对列表或拼写。

手动整理重建自动记忆，不改变窗口；启动前显示批次估算，可取消，全部成功后替换。分类条目支持手工编辑及来源定位，手工内容和删除标记受保护。旧整段编辑接口转换为手工条目，不再重复注入旧分类。
所有状态随回合事务提交，取消和审核拒绝不会提前消耗条目或推进窗口。

## 记忆专用预算

整理输入默认32768 tokens，辅助资料4096（0关闭，正数启用且不截断已选资料），输出4096，活跃记忆4096。含记忆的合并任务使用记忆输出额度，其他后台任务使用后台模型输出额度。当前进展和经历的准出由程序执行；未完成事项、待确认、手工和来源失效条目不自动退出。

自动记忆最多两批和一次可选复核，复核失败保留待确认结论。分批、复核和工具续答计入同一 Tracker 任务默认8次调用额度；历史补查另固定整次操作最多3次，前后置任务和手动重建的所有批次共享。Writer仍为零工具。

“本轮允许修改设定”要求先处理输入中的明确修改，再生成正文；正文后也允许沉淀长期变化。即使全局已经允许改设定，也可用此勾选要求前置处理。全局权限本身不增加每轮调用。只勾选更新变量且未到周期时，Tracker 不能顺带写文本记忆。

设置中使用一份“Tracker 系统提示词”。旧默认自动迁移，新版本不会重写自定义原则；旧自定义记忆/设定提示按适用范围合并到同一字段。模型只选 S/H 原文、R 旧记录和 E 设定编号，程序补齐真实来源。工具写入仍须遵守格式和权限。
