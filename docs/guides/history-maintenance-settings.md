# Half Agent 历史窗口与记忆设置

适用于“设置 → half agent → 历史与记忆”。Full Agent 使用[工作窗口与笔记](full-agent.md)，不消费本页参数。

## 窗口设置

窗口决定哪些原文进入下一次 Writer 请求，记忆周期决定何时整理已发生剧情，两者独立。退出窗口不会删除存档原文。

以下窗口参数只在“本地滚动窗口”生效。官方渠道可在“场景 → 上下文方式”切换“云端 compact”，默认开启自动压缩：每次发起生成时检查一次，超过 Writer 的上下文 token 上限则先整理已完成交流。云端模式不消费以下裁剪阈值，但仍执行 Tracker 周期记忆；可关闭自动压缩或点击“立即压缩”。本地 token 估算不含加密状态，服务端实际用量独立显示。

| 设置／字段 | 默认值 | 范围与作用 |
|---|---:|---|
| 窗口模式 `chunk_mode` | `messages` | 按消息批次、历史预算 `tokens`，或关闭 `off` |
| 历史消息 cap `history_message_cap` | 40 | 8–1000；计剧情与本次输入，开场白算一条 |
| 每批移除量 `chunk_size` | 10 | 2–100；按剧情消息计数，向完整交流边界对齐 |
| 日常预算 `daily_context_budget` | 98304 tokens | 2048–2000000；与模型可用输入容量取较小值 |
| 压力触发 `context_pressure_trigger` | 85% | 10%–99%；达到压力后继续裁剪到目标 |
| 压力目标 `context_pressure_target` | 70% | 5%–98%；必须小于触发比例 |
| 历史预算 `chunk_max_tokens` | 6000 tokens | 512–2000000；仅历史预算模式额外使用 |

历史条数不包含中途世界书，但世界书占用 token 容量。例如四次交流有八条剧情和二十条中途条目，剧情计数是八条，本次输入另计一条。

触发退出后，先检查将退出剧情是否已整理，再让完整交流及其锚定条目一起退出。最近两次完整交流和新输入受保护，实际移除量可能超过批次目标。固定资料加受保护内容仍过大时，程序提示后完整发送，服务商可能拒绝；继续裁剪无法解决固定内容过大的问题。

关闭窗口保留全部原文与已有条目，周期记忆仍运行。输出预算和本地估算的关系见[Token 计数](token-counting.md)。

切到云端从完整可回放历史建立上下文；切回本地按当前配置重新规划，先补齐必要记忆覆盖，再原子替换窗口。`chunk_mode=off` 时恢复全部原文。转换期间保持原模式，可取消或恢复；取消、失败不会部分保存记忆或冷却状态。压缩后的世界书开始冷却，相关时可重新注入。详细规则见[上下文生命周期](../design/context-lifecycle.md#官方渠道的云端-compact)。

## 记忆与任务限额

一轮是一次成功提交的用户发言与回复，重生成不增加轮数。消息条数、剧情轮数、模型请求数是三个不同单位。

| 字段 | 默认值 | 范围与作用 |
|---|---:|---|
| `memory_interval_turns` | 5 | 1–100；正文后检查，裁剪前另行检查来源覆盖 |
| `tracker_max_steps` | 8 | 2–100；每个前置／后置任务的模型请求上限 |
| `memory_timeout` | 120 秒 | 5–180；每次 Tracker 请求单独计时 |
| `memory_input_tokens` | 32768 | 2048–2000000；按完整交流分批的输入目标，单条超量仍完整发送 |
| `memory_evidence_tokens` | 4096 | 0–32768；兼容字段，0 关闭辅助资料，正数启用，不截断已选资料 |
| `memory_output_tokens` | 4096 | 256–65536；含记忆任务的输出额度 |
| `memory_capacity_tokens` | 4096 | 512–65536；交给 Writer 的活跃记忆容量 |
| `memory_current_max_records` | 5 | 1–100；自动当前进展数量，超量先退出来源最旧者 |
| `memory_episode_cooldown_rounds` | 20 | 0–10000；自动经历自最新来源后满指定轮数退出，0 关闭时间准出 |
| `memory_review_enabled` | 开启 | 关键疑问有新增资料时最多复核一次 |

自动整理最多两批和一次可选复核，与工具续答共用该 Tracker 任务的调用上限。前置和后置任务分别计数。历史补查搜索、读取及失败尝试另共享整次 Runtime 操作最多 3 次额度；手动重建的各批次也共享这 3 次。

手动重建不限总批数，每批使用独立上下文和调用额度，携带累计记忆。未含记忆的后台任务使用后台模型输出预算。已安装配置可能保留迁移前值，应以设置中的实际数值为准。

## 容量与手工保护

自动当前进展与经历按来源时间退出；超过活跃容量时继续退出旧经历。手工条目、未完成事项、待确认和来源失效条目不自动退出，也仍占容量。可退出内容用尽后仍超量会报错，应合并受保护条目或提高容量。这是记忆内容约束，与“输入估算超量后完整发送”不同。

手工编辑受到保护；手工删除保存屏蔽标记。Tracker 再次提出被删除内容时，该操作及其依赖被忽略，同批其他有效记忆仍可保存。

## 操作与失败处理

| 操作或情形 | 行为 |
|---|---|
| 手动整理 | 显示批次估算，可取消；全部成功后替换自动记忆，不推进窗口 |
| 纯周期任务失败 | 保留旧记忆与覆盖，提示失败，正文可提交 |
| 裁剪前覆盖不足 | 阻止正文，等待必要整理成功 |
| 合并任务包含变量或明确设定修改且失败 | 整轮不提交 |
| 取消或拒绝审核 | 不提交记忆、窗口和世界书状态 |
| 编辑旧来源 | 保留旧记忆并提示来源变化；手动重建才重新核对全部可见原文 |

勾选“本轮允许修改设定”会要求正文前处理输入中的明确修改；正文后可以沉淀长期变化。全局与对话级“修改保存方式”只决定实际变量和设定修改是否审核，不授予修改权限；记忆自动保存。规则与 Full Agent 相同，见[工具与变量授权](full-agent.md#工具与变量授权)。只勾选变量更新且未到记忆周期时，Tracker 不顺带写文本记忆。

Tracker 使用独立系统提示词。工具的 S/H、R、E 短编号和增量操作格式见[记忆设计](../design/memory-consistency.md)，完整任务顺序见[Half Agent 工作流](../design/agent-workflow.md)。
