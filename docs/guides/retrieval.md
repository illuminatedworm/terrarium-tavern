# 世界书检索与注入

两种模式共享关键词、BM25 和可选的本地向量／重排能力，各自保存参数。默认关键词与 BM25 可在 CPU 上运行，神经检索需先手动下载、预热模型。

## 查询从哪里来

Half Agent 从有界的当前输入和最近回复线索构造查询，线索使用 `<tavern_retrieval>` 区块，由服务端从正文和 MVU 中分离保存。空输入或“继续”采用有界本地回退，不扫描全部历史。

Half Agent 还用同一查询召回已归档的经历：BM25 加可选向量与重排，沿用本页的准入门槛，不走关键词通道。世界书与归档共用向量缓存，但分别判断索引是否就绪；一方新增或编辑条目不会停用另一方已就绪的向量通道。归档召回数量设为 0 时，不召回或准备归档向量。详见[归档与召回](../design/memory-consistency.md#归档与召回)。

Full Agent 在每轮首次模型请求前自动检索，也可通过 `recall_lore` 自拟查询；它可以用 `set_retrieval_query` 保存下一轮线索，不要求最终正文附带标签。主动查询通过工具结果返回完整条目，自动检索维护中途注入记录。

## 候选如何进入上下文

| 阶段 | 规则 |
|---|---|
| 关键词 | 检查大小写、全词、正则、次级条件、词长及主体证据；单字或泛词不能独立放行 |
| BM25 | 中文／英文／日文分词与二元组排序；有效词汇交集、查询覆盖默认至少 0.25、相对分数默认至少 0.35 |
| 向量 | 默认最低余弦相似度 0.5，片段聚合为条目 |
| 融合 | 加权 RRF；每通道默认最多 30 个候选，融合最多 20 个 |
| 重排 | 全部普通候选以原查询评分，默认阈值 0.5 |
| 最终准入 | 检查启用状态、时间线、次级条件、概率、冷却与数量 |

各阶段分数用于排序和准入，数值含义随通道而异。重排不可用时，候选仍需满足独立词法证据；未达门槛时返回零命中。常驻条目按作者设置处理。

递归默认一层，以本轮直接准入且允许递归的条目为起点，沿原查询的相关性继续筛选。常驻条目、旧冻结条目和已拒绝候选保持原处理结果；编译器使用最终准入清单。

角色卡与独立世界书的全词匹配、排除递归、阻止递归和大小写开关同时支持 camelCase（`matchWholeWords`、`excludeRecursion`、`preventRecursion`、`caseSensitive`）及 SillyTavern 导出的 snake_case（`match_whole_words`、`exclude_recursion`、`prevent_recursion`、`case_sensitive`），可位于条目顶层或 `extensions`。已有 camelCase 字段优先，同一拼写以 `extensions` 为先；明确的 `false` 或 `null` 不会被另一拼写覆盖，`null` 按默认关闭处理。读取不改写原始 JSON，也无需重新导入已有卡片。编辑器开关旁的说明展示生效字段与同义字段冲突；操作开关会写回并同步已有同义字段，没有字段时写入标准 snake_case 扩展。

导出角色卡时，这四个开关按相同优先级取当前生效值，统一写入 `extensions` 下的 snake_case 字段，并删除顶层及扩展中的其余同义字段。JSON、PNG、CHARX 一致适用；未配置的开关不补默认值，导出不修改本地已保存原稿。

## 条目标题

条目标题统一取 `comment`（SillyTavern 存放标题的字段），为空时取 V2/V3 规范的可选字段 `name`，两者皆空则视为无标题。列表、上下文预览、工具结果、`[InitVar]` 判定和模板诊断都使用这一取值；编辑器“条目名称”写入 `comment`，留空时以占位文字提示正在生效的 `name`。

两个开关在各模式的“检索”设置页分别保存：

| 开关 | 默认 | 作用 |
|---|---|---|
| 注入时携带条目标题 | 关闭 | 正文请求中每条世界书正文前加一行 `【标题】`，覆盖常驻、按位置和随对话滚动的注入；无标题条目不加。中途记录冻结正文，标题取当前条目。切换后请求前缀变化一次。`recall_lore` 工具结果是否附标题由工具页的“返回标题”单独控制，参谋 agent 与 Tracker 的资料不受影响 |
| 条目标题参与检索 | 开启 | 作用于非常驻的常规条目：标题计入 BM25 与向量切片、重排回退文本，以及关键词通道的条目主体判断。关闭后只用关键词与正文；关键词本身的匹配不受影响 |

每次默认最多新增五条，选中正文完整注入，没有单条字符或 token 截断。超长内容会提示。条目证据、命中词、递归来源与可用分数保存在快照中。

## 滚动与冷却

中途条目冻结在剧情锚点附近，重复命中不移动、不复制、不重新抽签。条目与交流一起退出窗口后才开始冷却，退出当轮不立即重注入；它占 token 容量，不占剧情条数。

Half Agent 的具体位置受会话注入方案和配方影响；Full Agent 固定按对话锚点注入。手工移除行为见[移除说明](lore-removal.md)，窗口规则分别见[Half Agent 设置](history-maintenance-settings.md)与[Full Agent](full-agent.md)。

## 本地模型与索引

1. 使用 `setup.ps1 -LocalRetrieval`（Windows）或 `./setup.sh --local-retrieval`（Linux）安装 GPU 依赖；安装代理按[安装指南](maintenance.md#安装与启动)配置。
2. 在“设置 → 通用 → 本地模型”分别选择 Qwen3 Embedding／Reranker 的 0.6B 或 4B 模型，以及 BF16 或 INT8，完成下载并预热。
3. 在目标模式的检索设置中启用需要的通道和重排。
4. 进入故事后检查模型及索引状态，再用具体查询验证结果。

启动时选择预热后可以关闭预热弹窗，任务会在后台继续；每个模型完成或失败时会通过统一通知条提醒，通知在 8 秒后自动消失。同时完成的模型合并显示。弹窗保持打开时直接显示进度。在“本地模型”页点击“预热”走同一流程，离开设置后仍会收到通知。

CUDA 推理由隔离进程运行。查询默认超时 1 秒，重排默认 1.5 秒；繁忙时跳过，不排队。失败会终止工作进程，需要重新预热。API、模型下载和角色资源下载的代理选项分别配置。

INT8 使用 bitsandbytes 的 LLM.int8()，异常值阈值为 6，异常特征与未量化层保留高精度计算。
它复用同一份原始权重，在预热时量化并直接放到指定 CUDA 设备，不自动转到 CPU。
更改量化选项后需要重新预热；向量索引按新配置重新生成，不会混用 BF16 与 INT8 向量。
4B 建议从批量大小 1 开始，并根据实测延迟调整查询和重排超时。显存预检只检查加载余量，实际推理峰值还取决于文本长度与批量大小。

索引身份包括实际内容、切片参数、标题参与检索开关、模型配置与下载 revision，内容变化后派生索引失效。SQLite 保存索引和向量，空闲清理先移除旧集合再按容量淘汰可重建缓存。模型权重单独管理，不随日志或索引清理，也不进入普通备份。

## 排查未命中与误注入

1. 检查条目启用状态、用途、时间线、次级条件与冷却。先排除规则过滤。
2. 在上下文预览或工作记录检查候选及拒绝原因，区分没有召回与召回后未准入。
3. 检查查询是否包含实际主体和场景；“继续”等简短输入主要依赖近期线索。
4. 启用神经通道时检查下载、预热、超时和降级原因。只读预览不运行神经召回，其结果可能少于实际发送。
5. 使用独立测试故事调整阈值，观察无关查询是否误注入，避免只看正例数量。

例如，查询“进入港口”命中了包含“钟塔”的港口条目，递归仍需判断钟塔与港口行动是否相关，只有符合原查询相关性的设定才进入上下文。

## 开发入口

- [search/retrieval.py](../../src/tavern/search/retrieval.py)、[lore_admission.py](../../src/tavern/search/lore_admission.py)：召回、融合与准入。
- [retrieval_config.py](../../src/tavern/search/retrieval_config.py)：默认值和配置校验。
- `GET /api/local-models` 与 `POST /api/local-models/{embedding|reranker}/{download|warmup}`：资源状态与任务。
- `POST /api/sessions/{id}/retrieval/rebuild`：准备有效世界书索引，Half Agent 同时准备当前分支归档经历的向量索引；不执行查询。
- `POST /api/sessions/{id}/preview`：只读上下文预览，不加载或推理神经模型。

设置读写使用[分范围设置 API](../reference/settings-api.md)。检索质量评估和只读回放见[验证说明](../development/validation.md#检索与模型质量评估)。
