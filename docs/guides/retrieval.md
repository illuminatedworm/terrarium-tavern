# 世界书检索与注入

检索支持关键词、BM25 和可选的本地向量／重排。默认关键词与 BM25 可在 CPU 上运行，神经检索需先手动下载或导入并预热模型。

## 日文词典

桌面版使用 Jieba 中文分词和 SudachiPy 0.6.11 日文分词（SplitMode.B 及其归一化行为），按实际文本分别加载。Android 直接使用 APK 内置词典。

**何时需要下载**：纯中英文检索不需要日文资源。含假名的文本首次需要分词时，自动准备固定版本 **Sudachi core 20260723**；日文世界书建立索引、日文归档检索也可能触发。只读上下文预览不发起下载，缺少词典时明确报错。

**下载与等待**

- 约下载 68.9 MiB，占用磁盘 207.4 MiB。下载遵循“设置 → 通用 → 联网与代理”中“本地资源下载使用代理（模型与日文词典）”的开关与代理地址，不继承环境代理。
- 进行中的检索等待同一个准备任务；准备失败或取消时，该次检索被阻止（既有剧情不变），不会降级分词或丢弃世界书候选。
- “设置 → 通用 → 本地资源”显示进度和具体失败原因，可取消、重试或提前准备。同步工具遇到未就绪的词典会明确报错并启动准备，完成后重试该操作；失败或取消后不自动循环重试。

**离线导入与存放**

- 离线导入只接受指定版本的 `sudachidict_core-20260723-py3-none-any.whl` 或其中的 `system.dic`，不执行安装脚本，不接受其他版本。资源页显示固定下载链接、两种文件的 SHA-256 和实际生效路径。来源为 [PyPI 的固定发行文件](https://pypi.org/project/sudachidict-core/20260723/#files)。
- 每次导入／下载都完整校验大小与 SHA-256 后原子落盘，应用重启后首次使用时再校验一次。取消、断线、错误文件和遗留的 `.part` 都不算就绪。
- 词典保存在所选数据目录的 `resources/sudachi-core/20260723/system.dic`，重启和更新程序后复用，日志／缓存清理不会删除。剧情备份不含词典；迁移数据目录时可另外复制该目录，或重新离线导入。

## 查询从哪里来

剧情模型在每轮首次模型请求前自动检索，也可通过 `recall_lore` 自拟查询；它可以用 `set_retrieval_query` 保存下一轮线索，不要求最终正文附带标签。主动查询通过工具结果返回短编号和条目开头，自动检索维护中途注入记录；两者共用在场排除与退出后的冷却状态，正文仍在上下文时不会重复召回。

## 候选如何进入上下文

| 阶段 | 规则 |
|---|---|
| 关键词 | 检查大小写、全词、正则、次级条件、词长及主体证据；单字或泛词不能独立放行 |
| BM25 | 中文／英文／日文分词与二元组排序；有效词汇交集、查询覆盖默认至少 0.25、相对分数默认至少 0.35 |
| 向量 | 默认最低余弦相似度 0.5，片段聚合为条目 |
| 融合 | 加权 RRF；每通道默认最多 30 个候选，融合最多 20 个 |
| 重排 | 全部普通候选以原查询评分，默认阈值 0.5 |
| 最终准入 | 检查启用状态、时间线、次级条件、概率、冷却与数量 |

各阶段分数用于排序和准入，数值含义随通道而异。重排不可用时，候选仍需满足独立词法证据；未达门槛时返回零命中。常驻条目按作者设置处理。

递归默认一层，以本轮直接准入且允许递归的条目为起点，沿原查询的相关性继续筛选。常驻条目、旧冻结条目和已拒绝候选保持原处理结果；编译器使用最终准入清单。

### 条目字段的兼容读取

**四个匹配开关**：全词匹配、排除递归、阻止递归和大小写敏感，同时支持 camelCase（`matchWholeWords`、`excludeRecursion`、`preventRecursion`、`caseSensitive`）和 SillyTavern 导出的 snake_case（`match_whole_words`、`exclude_recursion`、`prevent_recursion`、`case_sensitive`），可位于条目顶层或 `extensions`。

- 优先级：已有的 camelCase 字段优先；同一拼写中 `extensions` 优先。明确的 `false` 或 `null` 不会被另一种拼写覆盖，`null` 按默认关闭处理。
- 读取不改写原始 JSON，已有卡片无需重新导入。编辑器开关旁的说明显示生效字段和同义字段冲突；操作开关会同步写回已有的同义字段，没有字段时写入标准 snake_case 扩展。
- 导出角色卡（JSON、PNG、CHARX）时，按同一优先级取生效值，统一写入 `extensions` 下的 snake_case 字段，并删除顶层及扩展中的其他同义字段。未配置的开关不补默认值，导出不修改本地已保存的原稿。

**其他可选字段**

- `null` 与未设置等效，包括 `terrarium` 扩展、消息角色、位置与深度、排序、扫描深度、触发词、启用状态、概率和辅助词逻辑：沿用各字段的默认值或旧字段别名；`0`、`false` 和空列表照常有效。`extensions` 中的 `null` 不遮蔽顶层同名值。（上述四个匹配开关例外：其显式 `null` 仍按原优先级覆盖其他写法。）
- 条目 `id`、`uid`（含 `extensions` 中的同名字段）只接受字符串或数字，与 V2/V3 规范及 SillyTavern 一致；`null`、布尔值或对象在导入、保存和追加世界书时直接报错。缺省时依次取 uid 与条目位置。
- 消息角色未设置时按 system 识别来源类型，最终发送角色仍由消息适配决定。
- 以上只影响运行时视图，不修改原始 JSON。
- 编辑器中的插入顺序、深度、扫描深度、概率与使用概率、辅助词逻辑、恢复尺度、延迟、消息角色和分组显示运行时实际生效的值；帮助提示列出生效位置、被覆盖的其他位置（含 `scanDepth`、`order` 旧别名）和视为未设置的 `null`。修改时同步写入所有已有位置，都不存在时写入顶层主字段，以免隐藏副本保留旧值。

## 条目标题

条目标题统一取 `comment`（SillyTavern 存放标题的字段），为空时取 V2/V3 规范的可选字段 `name`，两者皆空则视为无标题。列表、上下文预览、工具结果、`[InitVar]` 判定和模板诊断都使用这一取值；编辑器“条目名称”写入 `comment`，留空时以占位文字提示正在生效的 `name`。

两个开关在游玩的“检索”设置页分别保存：

| 开关 | 默认 | 作用 |
|---|---|---|
| 注入时携带条目标题 | 开启 | 动态注入在 JSON 的 `title` 字段中携带当前条目展开后的标题。常驻条目在正文前单列标题，中间空一行。关闭此项或标题为空时省略标题。`recall_lore` 的标题由工具页的“返回标题”独立控制，默认开启。参谋 agent 使用独立请求 |
| 条目标题参与检索 | 开启 | 作用于非常驻的常规条目：标题计入 BM25 与向量切片、重排回退文本，以及关键词通道的条目主体判断。关闭后只用关键词与正文；关键词本身的匹配不受影响 |

剧情每次默认最多新增五条。常驻世界书始终发全文；动态命中和主动召回展示 L 编号和开头。游玩 → 检索与世界书 → 动态世界书预览长度默认 120 个 Unicode 字符，范围 1–2,000,000（含两端），按宏展开和模型投影后的正文计算。短条目直接展示全文，标题和编号不占字符额度。模型可用 `read_lore_full` 批量读取在场条目的冻结全文。条目证据、命中词、递归来源与可用分数保存在快照中。

每条动态命中在触发位置单独发送一条紧凑 JSON 消息。`source` 固定为 `runtime_lore_injection`，`ref` 是补读用的短编号。长条目使用 `preview`，完整放得下的条目使用 `text`。启用消息适配的世界书标签时，实际文本例如

```text
<lorebook>
{"source":"runtime_lore_injection","ref":"L1","title":"钟楼","preview":"起雾。\n钟响。"}
</lorebook>
```

关闭标签时只发送中间一行。正文里的换行按 JSON 字符串规则转义。展开游玩对话里的「世界书注入」，同一组字段按两空格缩进展示。短编号、展开后的标题和正文在本次入选时冻结，展示长度和标题开关取当前游玩设置。「上下文预览」可查看按当前消息适配设置编译的请求文本。主动召回和 `read_lore_full` 的工具记录展示该次实际返回的结果。

回复提交后，注入记录归属该回复版本。同轮编辑条目、条目退出窗口、重新打开待审核或失败的回合，均可在原位置查看保留的入选记录。分支和个人数据包携带已提交的记录。升级时从保留的入选事件恢复旧记录，缺少事件时可查看消息快照里仍保留的条目。旧版未冻结展开后的标题，只能用留存的条目和变量重建。无法还原的短编号显示为空。

如果字符上限落在资料短编号（如 `@D10`）中间，预览会在编号之前结束，展开全文时显示完整编号。停用或卸载条目后，下一次请求、上下文预览和云端整理均会跳过它原先的自动注入。

## 滚动与冷却

中途条目冻结在剧情锚点附近，重复命中不移动、不复制、不重新抽签。条目与交流一起退出窗口后才开始冷却，退出当轮不立即重注入；它占 token 容量，不占剧情条数。

剧情模型的 `recall_lore` 按命中条目的内部身份登记在场状态。每项均附短编号；工具页可选附带标题和已在场条目目录。工具正文随所属交流保留，退出后与自动注入使用同一冷却规则；取消或拒绝审核不会将草稿中的使用状态提交到故事。参谋 agent 的独立咨询召回不改变故事状态。

中途条目按对话锚点注入。窗口规则见 [游玩指南](story.md)，手工移除见[移除说明](lore-removal.md)。

## 本地模型与索引

### Android

Android 可分别用 CPU、OpenCL GPU 或实验性 Hexagon NPU 运行 APK 固定支持的两个 Qwen3 0.6B Q8_0 GGUF 文件，不依赖电脑后端；权重不打进 APK，也不支持其他 GGUF 或 4B 模型。已有的 CUDA 配置原样保留。设置步骤：

1. 准备 `Qwen3-Embedding-0.6B-Q8_0.gguf` 和 `Qwen3-Reranker-0.6B-Q8_0.gguf`，放到手机可选择的目录，例如 `Download`。向量文件来自 Qwen 官方仓库；重排没有官方 GGUF，需用固定转换器生成，获取方式见 [Android 模型文件](../development/android.md#模型文件)。
2. 在“设置 → 通用 → 本地资源”分别点击“使用手机 Q8_0 配置”，再选择设备。模型来源、版本、量化和设备均显示为实际保存值。
3. 为每个模型点击“导入 GGUF”，选择相应文件；通过大小与 SHA-256 校验后，点击“预热”。导入逐块写入并校验，只产生一份临时模型文件；进度显示已传入比例，完成以最终校验成功为准。可以取消，离开此页也会取消尚未完成的导入。来源或内容不符、连接中断或取消时，原已导入文件保留。
4. 在游玩的检索设置中启用向量通道或重排。新配置默认超时为查询 5 秒、重排 10 秒，已有保存值保持原样；CPU 多候选重排可能需要更长时间，应按实测调整。

GPU/NPU 需要兼容的系统与驱动，设备探测和加载都在应用权限下执行；界面显示实际设备与卸载层数，失败会报错，不自动改用 CPU。切换设备后需重新预热，权重无需再次导入。部分算子仍由 CPU 执行。

Android 的两个模型各有独立的原生进程：超时或取消只结束对应模型的计算（需重新预热），不影响另一个已加载的模型。单次输入上限 4096 tokens，超限明确报错，模型保持预热状态，查询或提示词不会被静默截断。索引沿用 token 分片，检索切片不影响剧情预览或按编号读取的全文。手机 GGUF 与桌面的向量缓存分开；切换设备、量化或模型版本后会准备对应的新索引。

### 单条索引超时

“检索 → 高级参数”提供“单条索引超时（秒）”，默认 60，允许 1–3600 的整数。时限覆盖单条世界书或归档经历的全部向量分片；手机上的长条目可以调大。超时时不保存该条的部分向量，之前完成的条目保留；重新预热后可再次准备索引。

### Windows/Linux（CUDA）

设置步骤：

1. 使用 `setup.ps1 -LocalRetrieval`（Windows）或 `./setup.sh --local-retrieval`（Linux）安装 GPU 依赖；安装代理按[安装指南](maintenance.md#安装与启动)配置。
2. 在“设置 → 通用 → 本地资源”分别选择 Qwen3 Embedding／Reranker 的 0.6B 或 4B 模型，以及 BF16 或 INT8，完成下载并预热。
3. 在游玩的检索设置中启用需要的通道和重排。
4. 进入故事后检查模型及索引状态，再用具体查询验证结果。

**预热**：启动时选择预热后可以关闭预热弹窗，任务在后台继续；每个模型完成或失败时通过通知条提醒（8 秒后自动消失，同时完成的合并显示）。弹窗保持打开时直接显示进度。在“本地模型”页点击“预热”走同一流程，离开设置后仍会收到通知。

**推理进程**

- CUDA 推理在与主服务隔离的进程中运行。Embedding 与 Reranker 共用这个进程，各用一个线程，PyTorch／CUDA 运行时约 1.2 GiB 的内存只占一份。
- 两个模型按顺序加载，避免 Transformers 加载时的进程级状态互相干扰；同时预热时，后一个等前一个加载完成，排队时间不计入加载超时。
- 新配置默认查询超时 5 秒、重排超时 10 秒，已有保存值不变。同一模型繁忙时跳过、不排队；已预热的两个模型可以并行推理。
- 模型报错（如显存不足）只卸载出错的那个，需单独重新预热；超时或进程退出会终止整个进程，两个模型都要重新预热。
- API、模型下载和角色资源下载的代理选项分别配置。

**INT8 量化**：使用 bitsandbytes 的 LLM.int8()，异常值阈值为 6，异常特征与未量化层保留高精度计算。它复用同一份原始权重，在预热时量化并直接放到指定的 CUDA 设备，不会自动转到 CPU。更改量化选项后需要重新预热，向量索引按新配置重新生成，不混用 BF16 与 INT8 向量。4B 模型建议从批量大小 1 开始，按实测延迟调整查询和重排超时。显存预检只检查加载余量，实际推理峰值还取决于文本长度与批量大小。

### 索引与缓存

索引身份包括实际内容、切片参数、标题参与检索开关、模型配置与下载 revision，内容变化后派生索引失效。SQLite 保存索引和向量，空闲清理先移除旧集合再按容量淘汰可重建缓存。模型权重单独管理，不随日志或索引清理，也不进入普通备份。

## 排查未命中与误注入

1. 检查条目启用状态、用途、时间线、次级条件与冷却。先排除规则过滤。
2. 在上下文预览或工作记录检查候选及拒绝原因，区分没有召回与召回后未准入。
3. 检查查询是否包含实际主体和场景；“继续”等简短输入主要依赖近期线索。
4. 启用神经通道时检查下载、预热、超时和降级原因。只读预览不运行神经召回，其结果可能少于实际发送。
5. 使用独立测试故事调整阈值，观察无关查询是否误注入，避免只看正例数量。

例如，查询“进入港口”命中了包含“钟塔”的港口条目，递归仍需判断钟塔与港口行动是否相关，只有符合原查询相关性的设定才进入上下文。

## 开发入口

- [search/retrieval.py](../../src/tavern/search/retrieval.py)、[lore_admission.py](../../src/tavern/search/lore_admission.py)：召回、融合与准入。
- [retrieval_config.py](../../src/tavern/search/retrieval_config.py)：默认值和配置校验。
- `GET /api/local-models` 与 `POST /api/local-models/{embedding|reranker}/{download|warmup}`：资源状态与任务。Android 另返回 `devices`（每项含 `device/label/available/reason/retry`），每个 `models` 项含 `selected_device/device_available/device_retryable/device_error`；已加载模型的 `execution` 含 `actual_device/offloaded_layers`，加速设备另有 `total_layers/model_buffer_mib/execution_note`，未加载时为 `null`。
- `POST /api/local-models/{embedding|reranker}/import`：Android 接收 `Content-Type: application/octet-stream` 的原始 GGUF 文件体，使用有界缓冲单次落盘，完整校验大小与 SHA-256 后发布。可提供 `Content-Length` 提前检查大小；未提供时仍按实际收到的字节限制。旧 multipart 请求返回 HTTP 415，调用方须改为直接发送文件。取消、断连或写入失败不会发布部分模型；同时导入或推理会被拒绝。
- `POST /api/sessions/{id}/retrieval/rebuild`：准备当前对话的世界书索引。
- `POST /api/sessions/{id}/preview`：只读上下文预览，不加载或推理神经模型。
- 游玩注入记录按需读取 `GET /api/sessions/{sid}/story/messages/{mid}/lore-previews`，其中 `mid` 是保存该次注入的回复或旧消息快照。待提交回合使用同路径下的 `turns/{tid}/lore-previews`。两者都按查询参数 `anchor_id` 选择剧情位置。默认返回条目定位、短编号、正文开头和截断标记。游玩页使用 `payload=true` 取得每项的 `id` 和 `payload`。`GET /api/turns/{tid}?include_input=true` 可恢复 `input_ready` 的输入与本轮入选目录。未提交回合的注入明细清理后，预览接口返回 HTTP 410。

设置读写使用[分范围设置 API](../reference/settings-api.md)。检索质量评估和只读回放见[验证说明](../development/validation.md#检索与模型质量评估)。
