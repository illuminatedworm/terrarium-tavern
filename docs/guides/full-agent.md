# 使用 Full Agent

Full Agent 由同一个模型生成正文、查阅资料、维护笔记和更新变量。它需要支持工具调用的模型，适合希望由模型主动管理长篇故事上下文的使用者。Half Agent 的周期记忆和历史裁剪参数不作用于此模式。

## 创建故事

1. 在“设置 → 通用 → 提供商”配置连接，再到“full agent → 模型与生成”选择模型、接口和预算。Full Agent 不继承 Half Agent 的配置。
2. 创建故事时选择渠道、Full Agent、角色卡、用户角色与开场。已有故事不能跨渠道或直接切换游玩模式；分支继承源故事的归属。两类渠道默认都使用本地换窗。
3. 发送输入。对话依次显示用户输入、可展开的 Agent 中间回复与工具过程、最终剧情正文。最终正文目前整段送达。

输入框可直接更换同渠道供应商和模型，选择随当前对话持久保存，重新生成和失败继续同样使用该选择。运行、待审核和上下文整理期间不可切换；Half Agent 的同类控件只影响 Writer。

自动世界书检索默认开启，Agent 也可以主动搜索同一索引。需要关闭自动检索时，在“工具与记忆”中修改；检索过滤与本地模型配置见[世界书检索](retrieval.md)。

“设置 → full agent → 工具与记忆”中的“单次允许多个工具调用”默认开启，模型可以一次提出多个独立操作，减少往返等待。关闭后每次只允许一个工具调用。此设置对所有 Full Agent 对话生效，保存后用于下一次运行；Half Agent 与角色卡编辑不受影响。换窗始终须单独调用。

## 查看与维护记忆和规划

右侧记忆区域提供三类内容：

| 内容 | 何时进入模型上下文 | 如何维护 |
|---|---|---|
| 交接笔记（handoff） | 本地换窗模式携带当前有效版本；云端 compact 不独立注入 | 本地模式下由 Agent 更新，或用户编辑后点击“保存交接笔记” |
| 按需笔记 | 从第二个窗口起，头部自动列出有效笔记名称；正文由 Agent 搜索或读取取得 | Agent 按稳定的笔记键更新或归档；界面可查看归档项 |
| 剧情规划（plot） | 开启时自动提供当前完整大纲，本地换窗和云端 compact 均保留 | Agent 按需修订；玩家可展开查看编辑，关闭后暂停使用 |

交接笔记适合保存当前场景、人物关系、用户约束、未决事项及重要笔记索引。按需笔记适合保存某个人物、约定或线索的完整经历。笔记区分有据事实、推测和计划，计划不表示事件已经发生。

## 剧情规划

在“场景”或“窗口与笔记”的“剧情规划”区域开启，默认关闭，仅影响当前对话。每个分支保存一份独立的阶段大纲，内容默认折叠，主动展开可查看和编辑未来剧情。

开启后，空大纲须先由 Agent 建立再回复剧情；随后在阶段完成、关键转折、玩家偏离或依据变化时按需调整，不强制每轮重写。近期具体、远期概括，玩家选择可以改变走向。玩家编辑后仍是一份可调整草稿；明确的创作要求通过对话或创作偏好传达。

`plot` 是作者对未来的构思，handoff 是继续工作的交接摘要，note 是长期记忆；note 的 `plan` 表示剧情内人物的意图。规划不等于事实或角色知识，不应复制到记忆中充当已发生的事。旧 plan 笔记保留原样，不自动迁移。

关闭后保留大纲供查看编辑，模型停止维护与使用；重新开启后结合当前进展核对。清空编辑内容需点击“保存大纲”才生效；开启时下一回合会重新建纲。规划随剧情快照、回复版本和分支保存，模型写入与正文一起提交；失败、取消或拒绝审核不会部分保存。

本地换窗和云端 compact 均支持剧情规划。当前大纲完整进入上下文，普通续答不重复发送未变化的版本，云端压缩后补入当前全文。缩小 token 上限不会截断已有大纲；后续写入须符合新上限。

## 官方渠道的云端 compact

官方渠道对话可在“窗口与笔记”选择“云端 compact”。首次启用会完整重放当前分支的剧情及工具历史，超长历史分批整理，不重复执行工具，也不使用当前 handoff 替代原文。完成前仍保留原模式；可取消或恢复整理，关闭面板不打断操作。

云端模式不向模型发送窗口管理说明，不开放本地换窗及 handoff 工具；长期 notes 的所有能力继续保留。默认达到配置窗口的 70% 时由服务端压缩，也可关闭自动压缩或点击“立即压缩”。短上下文可能不产生压缩项，界面会如实显示。云端加密状态的占用无法在本地精确估算，显示的可见文本 token 数不包含它。

“切回本地换窗”会先生成新的 handoff，成功后再切换；不会恢复过时的旧交接。更换官方账号或模型后会从历史重建云端状态。供应商失败、取消或输入无法容纳时，保存的剧情与 notes 不变，不自动转用普通渠道。

例如，希望模型记住“戒指借给了用户，离港前归还”，可以在输入中明确提出记录要求，再检查工具过程和笔记内容。成功调用写入工具后，仍须等整轮正文提交才会保存该修改。

编辑剧情原文后，相关笔记可能显示来源过时，交接笔记可能提示需要核对。程序不会根据修改后的原文自动重写这些内容；应结合来源检查，再修改交接笔记或要求 Agent 核对。

编辑时可选择是否主动提醒 AI；单击编辑在保存前询问，长按编辑可提前选择。仅选择“提醒 AI”才在下一次发送或重新生成时附带修订提醒，保存本身不调用模型；具体交互和提醒生命周期见[阅读、编辑与分支](story-history.md#编辑与重生成)。来源过时状态仍独立保留。

## 换窗

上下文接近预算时，Agent 会收到长度提醒；达到窗口上限后，运行时要求它先调用换窗工具。自动换窗由 Agent 编写新的交接笔记，并按工具参数保留最近的完整交流。调用次数继续计入当前回合额度。调用上限仅由运行时执行，不向模型发送额度、剩余次数或最后一次调用提醒；额度耗尽时报错并保留未提交进度。

需要人工恢复时：

1. 等待当前回合结束，或先取消运行中的回合并处理待审核草稿。
2. 核对交接笔记，写入继续故事所需的场景、约束、未决事项和笔记索引。
3. 点击“保存并换新窗口”。该界面操作不保留最近剧情消息，下一条输入进入新窗口。

全部剧情原文仍可由历史工具读取，长期笔记保持可用。旧工具过程保存在工作记录中供用户查看，Agent 没有搜索旧工具记录的工具。换窗后不能依赖已退出窗口的工具结果，应把必要结论写入交接笔记或长期笔记。

如果固定角色资料或单条输入本身过长，换窗仍可能无法降低占用；需要检查资料长度、输入或模型容量配置。

## 工具与变量授权

“本轮更新变量”要求模型处理本轮变量变化，勾选状态在本轮成功保存后保留，后续回合继续生效，直到手动取消；“本轮允许修改设定”允许修改对话内角色设定与世界书，每轮成功保存后自动取消。两者独立；失败重试保留该轮选择，切换对话不会带入另一对话的授权。

全局“默认修改保存方式”与对话设置中的“修改保存方式”共用两个选项：

| 保存方式 | 行为 |
|---|---|
| 自动保存 | 实际变量和设定修改随正文保存 |
| 审核后保存 | 剧情变量、MVU／脚本变量、角色设定或世界书实际改变时，展示修改前后内容，接受后整轮提交 |

保存方式不会授予设定修改权限。记忆、按需笔记、交接笔记、剧情规划、世界书检索记录、内部编号及窗口维护不触发审核；没有变量和设定改动的回合直接保存。有需要审核的改动时，正文、记忆与规划也留在同一草稿里，拒绝不会部分保存。

未单独选择保存方式的对话沿用同模式全局默认，从下一轮生效。对话内的设定修改不会覆盖书架原卡。旧 `directed`、`evolving` 转为 `automatic`；旧 `preview` 转为 `review`。旧“允许修改设定”的长期授权取消，统一使用本轮开关。升级前已经待审核的草稿仍需接受或拒绝，不自动提交。

“工具”页列出英文工具名、说明、参数和返回字段选项。除 `write_plot` 跟随“剧情规划”开关外，各工具可独立启停，修改自动保存到当前会话，从下一回合生效；运行或等待审核时不能修改。分支继承工具设置，重生成和回复版本切换不重置它们。

世界书搜索默认只返回正文，可按需开启编号和标题。历史与笔记搜索默认带摘要，读取工具默认带附加信息。返回字段影响模型输入；界面中的长结果分页只影响显示。

勾选“本轮更新变量”后，Agent 必须成功提交一次变量补丁才能提交正文，无变化时提交空数组。运行时在首次模型请求前提供全部启用的 tracker_mvu 规则，同一有效上下文中的相同版本只追加一次；换窗或重建后按需补入，规则变化在后续变量任务生效。规则留在历史中不代表下轮自动获得修改权限；设定修改只由本轮授权决定，保存方式独立控制审核。需要进一步检查工具参数时，见[工具协议](../reference/full-agent-tools.md)。

全部关闭工具且关闭剧情规划时，请求不携带原生工具定义；运行时工具协议仍保留为共同规则。关闭 `new_context` 后达到窗口上限，需要人工换窗或重新启用该工具。

## 工具与记忆设置

在“full agent → 工具与记忆”调整：

| 设置字段 | 默认值 | 范围与效果 |
|---|---:|---|
| `max_steps` | 24 | 每回合模型调用上限，2–100；工具续答和换窗均计入 |
| `auto_retrieval` | 开启 | 每轮首次模型请求前自动检索世界书 |
| `parallel_tool_calls` | 开启 | 单次允许多个工具调用；后台仍顺序执行并逐项保存进度。关闭时拒绝多调用批次，要求模型逐次调用 |
| `pressure_ratio` | 0.7（70%） | 上下文占用提醒阈值（比例），0.25–0.9；上下文估算 token 数达到窗口容量的此比例时，提醒模型准备换窗，提醒本身不强制换窗 |
| `handoff_tokens` | 2048 | 交接笔记内容上限，128–16384 tokens |
| `note_tokens` | 4096 | 单条长期笔记内容上限，128–16384 tokens |
| `plot_tokens` | 4096 | 独立剧情大纲内容上限，128–16384 tokens |

窗口容量与正文输出预算属于模型设置。增加笔记上限也可能增加后续读取和输入占用；本地估算口径见[Token 计数](token-counting.md)。

## 失败恢复与排查

| 现象 | 检查与操作 |
|---|---|
| 调用额度用尽 | 查看哪些工具反复执行；必要时调整本轮任务、手工整理 handoff 或提高调用上限 |
| 要求换窗但没有进展 | 检查 `new_context` 开关、handoff 长度，以及固定资料是否已超过容量 |
| 笔记写入被拒绝 | 已有笔记的当前全文不在上下文时先 read_note；检查正文限额及来源有效性，事实须引用当前分支有效 H 原文，但不要求预先读取来源 |
| 变量补丁被拒绝 | 启用 patch_state；当前上下文没有完整最新变量时，启用 read_state 并用默认作用域和空 path 读取；空补丁免读取，成功后本轮不能重复提交 |
| 设定补丁被拒绝 | 当前完整目标内容已在上下文时可直接修改，包括自动资料和模型自己写在工具参数里的全文；否则先 read_character／read_lore_entry。脚本、变量规则和初始化不可改；跨回合可沿用，退出上下文或版本不符时重读 |
| 工具参数不是合法 JSON | 查看原始响应；回合停止，不会不断请求模型修复损坏的协议 |
| 已有工具成功，但正文失败 | 点击“重新生成”续接可恢复进度；成功工具不重复执行，失败工具记录不复用，原错误仍可在失败回合查看。修改输入或变量授权会使进度重新开始 |
| 结果等待审核 | 审阅整个回合草稿；接受后整体生效；拒绝会清除可恢复草稿，不能续接被拒绝的修改 |

已提交的工具过程随所选回复版本和分支显示。失败、取消和待审核过程会标明未提交。调试页可查看完整请求、响应、用量和错误；缓存问题另见[提示缓存](prompt-cache.md)。

Full Agent 保留脚本初始化、正文变换和 MVU 校验，但不支持 HTML 交互生成或脚本再发模型请求。卡片的其他兼容范围见[兼容矩阵](compatibility.md)。
