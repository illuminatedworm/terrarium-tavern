# 使用 Full Agent

Full Agent 由同一个模型生成正文、查阅资料、维护笔记和更新变量，需要支持工具调用的模型。模型、检索和记忆参数在 Full Agent 设置中独立配置。

## 创建故事

1. 在“设置 → 通用 → 提供商”添加连接，再到“full agent → 模型与生成”选择模型、接口和预算。
2. 创建故事时选择渠道、角色卡、用户角色与开场；运行模式默认即为 Full Agent。渠道和运行模式在创建时确定，由分支继承；默认使用本地换窗。
3. 发送输入，在对话中查看中间回复、可展开的工具过程和最终剧情。

输入框可直接更换同渠道的供应商和模型，选择随当前对话保存，重新生成和失败继续也使用该选择；运行、待审核和上下文整理期间不可切换。

自动世界书检索默认开启，Agent 也可以主动搜索同一索引。需要关闭自动检索时在“工具与记忆”中修改；检索过滤与本地模型配置见[世界书检索](retrieval.md)。

## 正文如何生成

- Agent 用 `submit_story` 工具追加正文，每轮 1–3 段，以空行合成同一条回复。正文之前、段间和之后都可以使用其他工具；后续只能追加新段落，不能改写已接收的内容，第四段会被拒绝（已有三段保留）。
- 普通 assistant 文本只是可查看的过程备注，不进入正文。模型按原生协议自然结束，不需要结束工具或确认文字。
- 没有正文就结束，或缺少本轮必要的工作时，回合停止并保留进度，不会自动追加模型请求；由你选择是否继续。
- 脚本收尾失败后继续，只重试本地处理，正文不会撤回。
- Kemini 实验对话沿用三段上限，并从每次交付中提取显式自检和启用的免责声明。见[设置指南](settings.md#kemini-式实验功能)。

**预览**：普通 API 可在“通用 → 联网与代理 → 模型请求方式”选择流式传输，OpenAI 官方渠道始终流式。流式正文先显示为“正文预览 · 未保存”，完整响应、工具要求和脚本处理通过后才正式保存，需要审核时等待确认；非流式传输在收到完整结果后显示正文。预览的细度取决于服务商是否分片返回工具参数——当前 Google GenAI SDK 路线按完整函数参数接收，正文可能在参数收齐后一次显示全文。

## 交互图形

普通 Full Agent 对话可在右栏“工具 → 正文与图形”开启“交互图形”，默认关闭；开关自动保存，从下一回合生效。开启后，模型可以按需组合地图、关系图、结构示意、说明和按钮。Half Agent 与 Kemini 实验对话不提供此工具；关闭开关只阻止后续生成，已保存的图形仍可查看。

**显示**

- 每轮最多三份完整图形，每份可组合一至三个画布。
- 每份图形完整接收并通过校验后立即出现在本轮预览中，不必等整轮结束。正文段与图形按模型成功调用 `submit_story` / `present_ui` 的先后交错显示，同一批调用也保持顺序。
- 预览标明尚未提交；待审核、失败或取消时仍只是草稿。刷新、断线重连和继续本轮会恢复已成功生成的图形，整轮提交后才成为历史。
- 如果正则或脚本整体改写了正文、原分段记录被清空，界面保留完整处理结果，把图形列在正文之后，并提示无法还原穿插位置。
- 只有成功生成过图形的回复才加载图形组件。

**交互**：按钮可以切换本地显示、筛选或预设状态，也可以把行动追加到主输入框（保留已有的未发送草稿），由你检查、修改后发送；按钮不能直接改 MVU、推进剧情或自动请求模型。图形里的本地选择不写入故事，重新载入后回到初始状态。“放大查看”保留当前选择，按 Escape 或关闭按钮返回。

**修改与保存**：图形使用生成时的数据，之后变量变化不会改写旧图；要修改就在对话中说明，模型会在新回复中生成新版。重新生成、切换回复版本、分支、备份与个人数据包保留各自对应的图形。复制正文和分享阅读副本暂不包含交互图形。

**布局**：画布固定 768 像素宽并保持可读字号，窄屏时内容区横向滚动，宽屏时居中；放大窗口尺寸固定并适配视口。图形由受控矢量组件组成，不运行模型生成的 HTML/JavaScript。

## 查看与维护记忆和规划

右侧记忆区域提供三类内容：

| 内容 | 何时进入模型上下文 | 如何维护 |
|---|---|---|
| 交接笔记（handoff） | 本地换窗模式携带当前有效版本；云端 compact 不单独注入 | 由 Agent 维护，用户只读查看；需要纠错时在对话中要求 Agent 核对并更新 |
| 按需笔记 | 本地模式从第二个窗口起、云端模式始终提供有效笔记的名称目录；正文由 Agent 搜索或读取 | Agent 按稳定的笔记键更新或归档；界面可查看归档项 |
| 剧情规划（plot） | 开启时自动提供当前完整大纲，本地换窗和云端 compact 都保留 | Agent 按需修订；用户可展开查看和编辑，关闭后暂停使用 |

交接笔记适合保存当前场景、人物关系、用户约束、未决事项和重要笔记索引；按需笔记适合保存某个人物、约定或线索的完整经历。笔记区分有据事实、推测和计划，计划不代表事件已经发生。

交接区完整展示模型使用的章节、当前交接和来源标注，内容由 Agent 维护，用户不能直接编辑或清除来源提示。换行和字面量标记原样显示。

想让模型记住某件事（例如“戒指借给了用户，离港前归还”）时，在输入中明确提出记录要求，再检查工具过程和笔记内容。写入工具调用成功后，仍要等整轮正文提交才会保存。

同一对话的记录刷新时保留已显示内容，切换对话时才清空。最新记录读取成功前不能手动换窗；读取失败时显示错误，可点击刷新重试。

## 剧情规划

在“场景”或“窗口与笔记”的“剧情规划”区域开启，默认关闭，只影响当前对话。每个分支保存一份独立的阶段大纲，默认折叠，展开后可查看和编辑未来剧情。

- 开启剧情规划即把一部分剧情控制权交给模型：你决定自己角色的言行，行动的结果由模型依据人物动机和世界规则裁决，输入里写下的结果只算尝试。模型以作者身份确立若干**锚点**，即不随你意愿改变的世界事实（隐藏的真相、各方实力与底线、期限与必将到来的事件、世界规则）；故事内的言行只能影响锚点以何种方式、何时、以多大代价到来，不能推翻它。锚点之外的各方动向和后续走向仍随你的选择调整。
- 每条锚点标注冷酷度：**温和**只作背景压力，不造成实质损失；**严酷**可以损害局内利益，但不刻意针对你在意的情感；**冷酷**两者都可以受损。
- [场外发言](story-history.md#场外发言)无论是否开启剧情规划都视为作者指令，模型照办；开启时可以借此改动锚点或冷酷度，涉及锚点时模型可能用普通文本简短说明影响，显示在“本条回复的工具与过程”中。
- 空大纲须由 Agent 在收尾前建立（正文可以先交付为草稿）；之后锚点外的部分在阶段完成、关键转折、用户偏离或依据变化时按需调整，锚点只在兑现或场外要求时改动，不要求每轮重写。建议按核心、锚点、各方动向、人物变化、当前阶段、后续方向、伏笔和已完成组织；结构只是建议，手动编辑时可以自由组织。
- 你手动写下或改动的锚点与模型写下的同等对待；其余内容编辑后模型仍可随剧情调整。
- 关闭后大纲保留，可查看编辑，模型停止使用和维护；重新开启后会结合当前进展核对。清空内容需点“保存大纲”才生效，开启状态下下一回合会重新建纲。
- 规划随剧情快照、回复版本和分支保存，模型的写入与正文一起提交；失败、取消或拒绝审核不会部分保存。
- 本地换窗和云端 compact 都支持剧情规划：当前大纲完整进入上下文，未变化时普通续答不重复发送，云端压缩后补入全文。调小 token 上限不会截断已有大纲，之后的写入须符合新上限。

`plot` 是作者对未来的构思，handoff 是继续写作所需的交接信息，note 是长期记忆（其中 `plan` 类表示剧情内人物的意图）。三者分别维护，已有的 plan 笔记保持原用途。

## 换窗

本地上下文默认在占用达到窗口容量的 80% 时提醒模型准备换窗，达到上限后要求先换窗再继续，已接收的正文草稿完整保留。

- Agent 可以更新 handoff，也可以省略以沿用现有交接，并自行选择 `keep_recent`（保留最近 0–12 条剧情消息，默认 2，程序会扩展到完整交流，当前输入另外保留）。
- 只要求实际退出的历史已被章节覆盖，带进新窗口的最新消息不需要先归档。
- 换窗的调用次数计入当前运行的请求额度，额度耗尽时保留进度供继续。
- 普通交接要点不必填 H 编号，新增章节的覆盖范围由程序自动记录。需要精确回查的要点可附 H 引用；角色资料、文风和当前输入中的要求直接写入即可。AI 正文和 API 回放不加 H 标记，消息编号仍显示在界面和历史工具中。

需要手动换窗时：

1. 等待当前回合结束，或先取消运行中的回合并处理待审核草稿。
2. 在“场景”页的“窗口”区块查看当前交接，用加减按钮选择保留最近多少条剧情消息（0–12，默认 2，程序会扩展为完整交流）。
3. 点击“换新窗口”。这会复用已保存的交接，不调用模型，也不改写正文或解除来源提示；只退出已被章节覆盖的历史。提示缺少覆盖时，可增加保留条数，或先让 Agent 整理交接。

换窗后，全部剧情原文仍可由历史工具读取，长期笔记保留；旧工具过程可在工作记录中查看，后续写作需要的工具结论应保存在交接或长期笔记里。

如果固定角色资料或单条输入本身就很长，换窗也可能降不下占用，需要检查资料长度、输入或模型容量配置。模型暂时不可用且交接覆盖不足时，手动换窗会保留原窗口并报错，不能通过编辑摘要绕过覆盖检查。

## 官方渠道的云端 compact

官方渠道的对话可在“窗口与笔记”选择“云端 compact”。

- 首次启用时，从当前分支的完整剧情和工具记录重建上下文，长历史按完整交流分批整理。转换完成后才切换，期间可取消或恢复，关闭面板后任务继续。
- 自动压缩默认开启：发起回合时，若上次有效实测输入超过模型设置的窗口上限，或有匹配的服务端超限拒绝，先发起独立的压缩请求再继续生成。已有压缩状态失效时，在下一次实际模型请求前重建全部已完成交流（同回合的工具续答也一样），当前整轮输入和工具过程保持完整。也可关闭自动压缩，或点击“立即压缩”。
- 短上下文可能得到完整重放的结果，界面显示实际整理状态。云端加密状态的占用以服务商返回为准，整理成功后等待新的实测。打开预览或只编辑资料不会发起整理请求。
- 云端模式保留长期 notes 及其工具，工作窗口由云端状态承接；`new_context` 和 `write_handoff` 只用于本地换窗模式。
- 切回本地时，从完整可回放的历史重新规划窗口：此前云端压缩过历史时生成新的 handoff（服务端明确超限时按完整交流分批），否则保留全部原文，然后提交转换。每批都会告知模型章节用量与合并要求，交接校验失败时允许修正一次（这次请求也计入用量）；仍失败则保留已完成批次供恢复。
- 更换官方账号或模型后，云端状态从历史重建。转换失败或取消时，原有模式、剧情和 notes 保持不变。

## 修改输入与失败续接

最新一轮的用户输入可以修改，确认后立即重试；失败或取消的输入也可修改后重试。新对话的开场白在首次模型任务前也可用同样的编辑按钮单独保存，详见[开场白编辑](story-history.md#编辑与重生成)。修改输入后，handoff、长期笔记和剧情规划从本轮开始前的快照恢复，与新回复一同提交，本轮工具流程重新开始；旧输入及其结果保留为整轮版本，切换版本时一并恢复对应的记忆。

上一轮失败或停止、且输入未改时，输入框上方提供两个选择：

- **继续本轮**：保留已接收的正文和成功的工具结果，从中断处再次请求模型，适合网络中断等偶发失败。会话版本或授权已改变时不可用，并说明原因。连续两次继续仍未完成时，页面会建议重新开始，因为续接重放同一上下文，可能反复以同样方式失败。
- **重新开始本轮**：放弃本次进度，用原输入从本轮开始前的状态重新生成，与“重新生成”相同。

上一轮尚未提交时发送新发言，不会替你做选择：新发言留在输入框，你需要先选择继续或重新开始；上一轮成功提交后，再把它作为下一轮发送。

- 等待期间新发言一直显示在输入框里，不会交给上一轮的模型，也不会覆盖原输入。
- 需要审核时，接受并保存后自动发送；审核期间仍可修改新发言。
- 续接失败、停止、拒绝审核或切换对话会取消自动接发，新发言不会被消耗。
- 自动接发只在当前页面有效，刷新后需重新发送。

入口、待提交内容的展示和版本操作见[阅读、编辑与分支](story-history.md#编辑与重生成)。

## 工具与变量授权

- **本轮更新变量**：要求模型处理本轮的变量变化。勾选后，本轮成功保存时保留勾选，后续回合继续生效，直到手动取消。勾选后 Agent 每轮须成功提交一次变量补丁，无变化时提交空数组。
- **本轮允许修改设定**：允许修改对话内的角色设定与世界书，每轮成功保存后自动取消。

两者独立；失败重试保留该轮的选择，切换对话不会带入另一对话的授权。

全局“默认修改保存方式”与对话设置中的“修改保存方式”共用两个选项：

| 保存方式 | 行为 |
|---|---|
| 自动保存 | 实际变量和设定修改随正文保存 |
| 审核后保存 | 剧情变量、MVU／脚本变量、角色设定或世界书实际改变时，展示修改前后内容，接受后整轮提交 |

授权决定能改什么，保存方式决定改了之后是否审核。记忆、笔记、规划和窗口维护自动随回合保存；一轮需要审核时，正文和这些内容一起留在草稿中，接受后整体生效，拒绝则保持原正式状态。采用全局默认的对话在下一轮使用同模式的最新默认值。设定修改作用于当前故事的副本，书架上的原卡不受影响。旧保存方式的转换见[设置迁移](../reference/settings-api.md#配置范围与修订号)。

运行时提供全部启用的 `tracker_mvu` 规则，以及关闭但标题含 `[InitVar]` 的 `tracker_mvu` 条目，按有效版本复用，换窗或重建后按需补入。规则留存由上下文管理，修改权限每轮独立校验。详细参数见[工具协议](../reference/full-agent-tools.md)。

**工具页**：按用途分组列出工具，以中文名为标题并附英文工具名；展开一行可设置返回字段，并查看发给模型的英文说明和参数（中文名只用于界面）。

- 各工具可独立启停，例外是 `write_plot` 跟随“剧情规划”开关，原著工具跟随原著页的授权，`submit_story` 始终启用。
- 修改自动保存到当前会话，从下一回合生效；运行或等待审核时不能修改。分支继承工具设置，重新生成和切换回复版本不会重置。
- 世界书搜索默认返回正文和标题，可开启编号或关闭标题；历史与笔记搜索默认带摘要，读取工具默认带附加信息。返回字段影响模型输入，界面中的长结果分页只影响显示。
- 即使关闭全部可选工具、剧情规划和原著参考，普通对话仍带有 `submit_story` 和运行时工具协议。关闭 `new_context` 后达到窗口上限，需要手动换窗或重新启用该工具。

## 工具与记忆设置

在“full agent → 工具与记忆”调整，对所有 Full Agent 对话生效，保存后用于下一次运行，不影响 Half Agent 与制卡 agent：

| 设置字段 | 默认值 | 范围与效果 |
|---|---:|---|
| `max_steps` | 24 | 每次发送或继续的模型请求上限，1–100；工具续答和本地换窗都计入 |
| `max_duration_seconds` | 900 秒 | 每次发送或继续的总运行时限，30–7200 秒；持续有网络数据也不会延长，等待审核不计入 |
| `auto_retrieval` | 开启 | 每轮首次模型请求前自动检索世界书 |
| `parallel_tool_calls` | 开启 | “单次允许多个工具调用”：最多 32 个，减少往返等待，后台仍按顺序执行并逐项保存进度；关闭时要求模型逐次调用（`submit_story` 也计入）。换窗始终须单独调用 |
| `pressure_ratio` | 0.8（80%） | 上下文占用提醒阈值，0.25–0.9；上次有效实测输入达到窗口容量的此比例时提醒模型准备换窗，提醒本身不强制换窗 |
| `handoff_tokens` | 8192 | 当前交接上限，128–16384 tokens |
| `chapter_tokens` | 2048 | 交接单章上限，64–4096 tokens |
| `chapters_total_tokens` | 16384 | 交接章节总量上限，256–65536 tokens；接近上限时模型合并最旧的章节 |
| `note_tokens` | 8192 | 单条长期笔记内容上限，128–16384 tokens |
| `plot_tokens` | 8192 | 剧情大纲内容上限，128–16384 tokens |

窗口容量与正文输出预算属于模型设置。云端上下文整理使用独立请求，另行记录用量。调高笔记上限可能增加后续的输入占用；计数口径见[Token 计数](token-counting.md)。

## 失败恢复与排查

| 现象 | 检查与操作 |
|---|---|
| 总时限用尽 | 运行已停止并保留草稿；可显式继续，或在工具与记忆页调整总时限 |
| 调用额度用尽 | 查看哪些工具在反复执行；必要时显式继续，让 Agent 整理交接，或调整本轮任务与调用上限 |
| 要求换窗但没有进展 | 检查 `new_context` 开关、handoff 长度，以及固定资料是否已超过容量 |
| 笔记写入被拒绝 | 已有笔记的当前全文不在上下文时先 read_note；检查正文限额和来源——事实须引用当前分支有效的 H 原文，但不要求预先读取来源 |
| 变量补丁被拒绝 | 启用 patch_state；上下文没有完整的最新变量时，启用 read_state 并用默认作用域和空 path 读取。空补丁免读取；收尾前至少成功一次，之后可按最新变量继续修改 |
| 设定补丁被拒绝 | 目标的完整当前内容已在上下文（包括自动资料和模型自己写在工具参数里的全文）时可直接修改，否则先 read_character／read_lore_entry；跨回合可沿用，退出上下文或版本不符时重读。脚本、变量规则和初始化不可修改 |
| 工具参数 JSON 解析失败 | 查看原始响应和提供商错误，修正模型或连接配置后重试 |
| 已有工具成功，但正文失败 | 点击“继续本轮”恢复进度，或点“重新开始本轮”／“重新生成”从头生成。成功的工具不重复执行，失败的工具记录不复用，原错误仍可在失败回合查看；修改输入或变量授权会使进度重新开始 |
| 结果等待审核 | 审阅整个回合草稿；接受后整体生效，拒绝会清除可恢复草稿，被拒绝的修改不能续接 |

已提交的工具过程随所选回复版本和分支显示；失败、取消和待审核的过程标明未提交。调试页可查看完整的请求、响应、用量和错误；缓存问题见[提示缓存](prompt-cache.md)。

Full Agent 支持脚本初始化、正文变换和 MVU 校验；HTML 交互生成与脚本嵌套模型请求只适用于 Half Agent，详见[兼容矩阵](compatibility.md)。

## 原著参考

在右侧“原著”页导入一个 txt/md 文件并明确开启后，主 agent 才能委派查阅。原文副本存放在数据目录，主 agent 只接收调查报告。调查模型和独立额度在“全局设置 → Full Agent → 原著调查”中配置，默认跟随主模型。

同一文件也可单独授权[参谋 agent 查阅](advisor.md#查阅原著)。参谋 agent 在咨询内直接读取所需片段，使用自己的模型。

调查可跨轮运行，停止主生成不会停止调查。原著页可查看实际模型、用量和完整过程，可分别停止、恢复、销毁，或全部停止。已完成、等待中和暂停的调查者仍占名额，并锁定文件操作，不再需要时应销毁。存在调查者时创建分支会先提示：调查者仍属于原分支。

“原著调查消息”（报告、提问和失败通知）与“原著参考运行状态”的发送角色默认为 `system`，使用 Google GenAI 接入时默认为 `user`；可在当前对话的“消息适配”中分别调整，显式设置优先。新建对话的默认值在“全局设置 → Full Agent → 原著调查 → 消息适配”（模型“更多参数”正下方）设置：它跟随主 agent 当前渠道的接口协议并显示当前接口，与调查模型的接口选择无关；与“模型与生成 → 普通 API → 消息适配”共用同一份设置，不影响已有对话。

文件范围、压缩、备份与恢复见[设计说明](../design/novel-research.md)。
