# 编辑角色卡与适配工作流

书架角色卡是创建新故事的模板；已有故事保存自己的角色资料。修改、复制或删除书架卡片不会改变已有故事。当前故事的设定应从对话侧栏“场景 → 编辑对话世界书”修改，预览策略下需要接受后生效。

## 手工编辑与复制

角色卡列表可以复制已保存角色。副本有新的身份和独立文档，名称添加“（副本）”及编号；头像、CHARX 资源、脚本权限和已缓存依赖保留。共享底层文件不会让副本跟随原卡变化，删除原卡也不会删除仍被引用的资源。

角色卡编辑页的表单占满内容区；“导出角色卡”位于右上角，与“恢复原稿状态”和“保存角色”并列。导出的是已保存版本，表单修改需要先保存。

PNG 角色卡的图片和 CHARX 中声明的内嵌头像会显示在角色卡列表、编辑页、新故事的角色选择与开场设置、会话列表及对话头像中。没有图片或图片加载失败时显示角色名字首字。已有会话使用创建时保留的图片，修改或删除角色库中的原卡不会改变该会话的头像。

手工编辑的未保存修改会保留在当前浏览器标签页中，重新打开编辑页时自动恢复，并显示“有未保存修改”。点击保存按钮旁的“恢复原稿状态”，会在按钮附近打开悬浮确认框；点击外部、继续编辑或按 Esc 可取消。确认后放弃全部表单修改并清除这份本地草稿；角色卡从书架读取最新保存版本，对话世界书恢复进入编辑页时的内容。原始 JSON 即使格式无效也能放弃。制卡对话中，此按钮恢复打开表单时的草稿，不撤销 Agent 对话中已完成的修改。

世界书可搜索名称、注释、ID、主／副关键词和正文。空格分词后同时匹配，不区分大小写；启用状态、触发方式和条目用途可以组合筛选。筛选保留原始顺序，并显示匹配数与总数。

“导入世界书 JSON”会将文件中的条目添加到当前草稿，保留已有条目和世界书设置，保存后生效。支持数组与对象形式的 entries；重复 ID 会为新条目重新分配，重复导入仍作为新增处理。

“脚本与兼容”页列出全部正则脚本与 Tavern Helper 的顶层、分组及旧版角色脚本，包括停用项。可以编辑匹配表达式、替换内容、脚本正文和原始参数；世界书初始化内容仍在对应条目中查看。

## 独立制卡对话

在“设置 → 通用 → 角色卡编辑”配置模型。左侧“制卡”进入独立 Card Editor，可以新建、改名和恢复对话，不需要先导入角色卡。进入时不会自动新建对话；没有已有对话时显示入口提示，由用户点击“新建制卡对话”开始。角色卡页面的“Agent 编辑”会从当前表单建立一个制卡对话，未保存的表单内容也会带入。

输入框支持 Enter 发送、Shift+Enter 换行，通过“引用角色卡”或输入 `@` 选择书架资料。Agent 的角色卡访问范围限于本对话已引用资料，不搜索整座书架或读取游玩剧情。引用先提供结构概览，模型按需读取完整字段、世界书及脚本。用户角色库另按下述明确请求访问。

对话沿用 Full Agent 的阅读样式。每回合“工具与过程”位于对应 AI 回复之前，可展开查看调用参数和返回摘要；失败、停止或无新输入的续接记录保留在原来的时间位置，不集中堆在对话末尾。运行中的过程实时更新，完成后收起；展开旧记录不会把阅读位置拉回最新。

输入区的“内置技能”说明角色卡适配技能的两种用法：项目工作流适配，以及正文状态栏迁移。选择目标卡片后，“填入请求”会在现有输入之后添加可编辑的请求，不自动发送、不直接修改草稿。未引用卡片时可从技能面板进入引用选择。

同一卡保留一个 C 编号。再次引用会沿用该对话中的当前草稿；新建变体才产生新的对象。引用取加入时的快照，源卡更新会显示提示，用户可以重新载入。重新载入会替换当前内容，支持撤销。

## 从零制作

1. 描述想制作的人物、世界或互动情境。
2. Agent 先提出定位、用户角色与互动、风格、开场和必要机制的方案。
3. 在聊天中确认或修改方案，再生成草稿。明确要求直接制作时可以直接开始。
4. 从右侧选择卡片，在资料、修改和诊断页审阅；可打开原有表单手工编辑。
5. 使用“保存新卡”加入书架。之后可覆盖保存或另存副本。

已确认方案和用户要求原文随卡片保留。普通文本卡默认使用项目支持的 V2 JSON；变量、正则和脚本按需求加入。普通制卡和 MVU 设计共用一套契约，无需先选择模式。只有脚本额外模型调用、HTML 交互生成等能力影响方案时才确认 Half Agent 或 Full Agent；资料页的兼容性目标为可选项，选择本身不迁移内容。

## 用户角色

可以明确要求 Agent 查看、新增或修改用户角色，例如“列出我的用户角色”“新建用户角色林澈，介绍是离开军队的航海士”“把用户角色林澈的介绍补充为熟悉近海航线”。用户角色只有名称和介绍，与角色卡分别保存。无须先引用角色卡。

普通制卡不会自动读取或创建配套用户角色；提到卡片里的 `{{user}}` 或讨论玩家定位也不代表授权。只要求查看时不写入。Agent 先定位并完整读取已有角色，再修改用户要求的字段；同名角色用 P 编号区分。

新增和修改在本轮正常完成后保存到用户角色库，可在新故事中选择，无需再保存书架卡片。已有故事保留自己的身份快照。停止、失败或断网时暂不保存，继续任务可接着处理；补充“撤销本轮用户角色修改”可以只撤销其待保存内容。其他编辑同时修改该角色时，版本冲突会保留进度，需读取最新版并合并。

## 多卡编辑与保存

一个对话可以引用和编辑多张卡，每张卡有独立草稿、差异、撤销记录和保存基准。卡片切换只改变检查对象，模型操作始终指定 C 编号。未知字段、宏、资源和原容器保留。

Agent 修改草稿，书架保存由用户审阅执行。覆盖要求原卡版本匹配；冲突时草稿仍保留，可核对新版后重新载入或另存。新卡首次保存保留确定的卡名，另存副本采用现有副本命名规则。已有故事的角色资料不随书架修改变化。

“保存角色卡”（新建草稿为“保存新卡”）和“另存副本”固定显示在右侧底部，不随标签切换或内容滚动消失。“保存角色卡”写回当前引用的书架卡；“修改”标签用于查看差异、撤销与重新载入。运行中或存在未完成进度时，保存操作禁用。

右侧默认打开当前草稿的“预览”：显示设定、可切换的开场和可展开、搜索的世界书。较长开场可展开全文；预览不执行卡片脚本或加载外部资源，不代表实际游玩渲染。“数据”保留完整原始字段树、兼容性设置及表单入口，“修改”查看差异与撤销操作，“诊断”查看检查结果。切换卡片或查看未完成版本时，预览跟随当前选择；勾选未完成版本后，成功的草稿工具修改会刷新预览，该版本有明确标识且不能保存。窄屏通过“卡片与修改”进入侧栏。

## 停止、继续和补充要求

默认每次发送或显式继续最多 24 次模型请求，可在通用设置中调整。停止、断网、服务重启或调用额度耗尽会保留未提交进度，完成版本保持不变。

调用额度仅由运行时内部管理，禁止注入额度、剩余次数或最后一次调用提醒，也不提供相关通知设置。额度耗尽时报告错误并保留进度；旧编辑上下文中的调用提醒在重建时退出。

- **继续本轮**：接着已有进度执行，不重复已经成功的工具。
- **补充要求并继续**：例如“保留 A 的修改，B 恢复原状，再处理 C”；尚未执行的旧调用撤销，由模型按新要求继续。
- **查看未完成修改**：显示清楚标识的临时版本，仅供检查。
- **丢弃本轮**：恢复上次完成的草稿，保留聊天记录。

运行或存在待续进度时，手工编辑、保存、刷新引用和删除对话需先处理当前进度。切换对话或关闭页面不停止后台任务；刷新后恢复观察。未发送输入按对话分别保存。

## 长对话与验证

上下文到 70% 时提醒模型安排换窗，达到上限时要求换窗；handoff 默认最多 2048 tokens。确认方案、当前卡片、最近两轮交互和当前输入继续保留，旧工具交换整体退出，可完整读取历史。换窗不会重置当前批次调用额度。超长原文不会被截断；服务商窗口不足时报告实际失败。

“工具与上下文”提供只读预览和实际工具契约；尚未执行的工具结果不在预览中。动作详情只显示日志摘要，模型读取的原文完整发送。

诊断区区分结构检查、创作完整性和运行范围。模型可使用本地验证工具检查指定开场的初始化、正则样例和脚本启动；界面按钮检查默认开场。沙盒只使用内嵌或已缓存资源，不下载依赖、不发起模型回合、不修改正式故事或永久脚本权限。依赖缺失、超时和不支持的能力不算通过；实际叙事、其他开场及完整视觉交互仍需验收。

## 世界书用途与初始化

| 用途 | 行为 |
|---|---|
| `writer` | 两种模式可见的叙事与规则资料，沿常驻及检索规则注入 |
| `tracker_mvu` | 两种模式的变量规则；Half Agent 提供给 Tracker，Full Agent 在当前上下文首次授权更新时追加全部启用条目，同版本不重复，换窗后按需补入 |
| `runtime_init` | 交给确定性 Runtime 的初始化数据，不进入模型请求 |

开场 `<initvar>` 提供该开场的完整初值，覆盖角色卡世界书初始化，不从条目补齐遗漏字段。无开场 `<initvar>` 时使用世界书初值；传统 `[InitVar]` 标记条目即使禁用也会被读取，未带该标记的 `runtime_init` 条目按启停设置处理。已有对话的初始化记录不会自动重演。

两种模式共用分流、适配和检查规则，已有 tracker_mvu 规则无需为 Full Agent 搬到 writer。变量更新使用相对于 stat_data 的 JSON Patch，无变化提交 []，不混入故事正文。规则和宏值按任务固定，规则修改从后续任务起生效。普通编辑不自动迁移工作流；开场内联 MVU 默认保留，明确要求迁移时使用专用工具维护关联。静态合法和本地检查通过均不能证明所有模型或脚本行为正确。

对于要求模型每轮输出 HTML 状态栏、Markdown 表格或固定标签状态块的卡，可以明确要求“将正文状态栏迁移为独立变量，使用项目变量面板”。Agent 会读取专门的适配指南，拆分叙事、初值和变量规则，并处理相关开场示范；普通项目适配仍默认保留开场。余额含义、进度条数值等不明确时应保留待确认项，不能自动发明计算规则。迁移只修改草稿，保存后在新故事验证；已有故事状态不会自动迁移。

诊断会提示疑似重复输出模板、静态开场状态栏、宏路径和缺失的初始化/更新规则来源。普通 HTML 排版不因此禁止，程序读取变量的展示也无需一律移除。这些提示是启发式检查；无警告不代表已完成语义适配，Agent 仍需核对全部相关内容与本地初始化结果。

## 删除、备份与旧版本

移除卡片引用会删除本对话中该卡的草稿和撤销记录，书架卡片保留。左侧“制卡”列表的每条对话旁提供删除按钮，对话顶部也可删除，均需确认。删除会清除聊天与全部草稿，先保存需要保留的成果；已保存的角色卡、用户角色和故事保留。运行中或有待续进度时须先停止并处理进度。删除其他对话不会切换当前对话，删除当前对话后打开剩余对话，删空后可直接新建。源卡删除后的草稿仍能从制卡列表恢复并另存。

对话、原文、确认方案和待续进度随应用备份保存；它们不作为普通诊断日志清理。运行中不能备份，停止后可备份并在恢复后继续。数据库升级到 schema 3 前会备份，旧工作区保持原对话身份和历史，旧程序回退须恢复升级前备份。
