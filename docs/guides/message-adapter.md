# 消息类型与适配

运行时用自己的消息类型区分资料、任务和通知，发送模型请求时才转换成 SDK 角色。常驻世界书与中途世界书使用不同类型；同一类型的初始版本和追加版本使用同一映射及标签设置。

## 设置入口

各模型设置的“消息适配”区域保存新对话的默认值。Half Agent 正文生成与 Tracker、Full Agent、角色卡编辑 agent 模型分别设置，并按接口协议保存选择。修改全局默认值不改变已有对话。

Full Agent 的应用资料与通知默认映射为 system，四种接口协议均保持这一默认值。兼容其他角色须由用户在消息适配设置中选择。

游玩对话在右侧“会话设置 → 消息适配”中调整；制卡对话在输入区的“消息适配”中调整。对话创建时复制默认值，分支复制父对话设置，之后独立保存。

保存对话设置后，下一次模型调用立即按新设置转换整份上下文。同一回合内的工具续答也使用新设置。已发送请求和同一次调用的重试保持原快照。设置使用独立版本号，运行中也能保存，不影响剧情或草稿提交。

## 角色和标签

可配置类型包括中途注入的应用消息，以及可能追加新版本的类型。选择 system、developer、user 或 assistant，并决定是否包裹该类型的标签。标签名称由程序定义；正文自己包含的标签保持原样。输入标签设置不改变检索线索或工具输出协议。

Full Agent 的“长期笔记目录”（`note_list`）也可配置发送角色和标签，默认 system 与 `<tavern_note_list>` 包裹。从第二个窗口起，它位于头部末尾，只列当前有效笔记的名称；笔记正文仍按需读取。

其余应用资料保留固定标签；顶级主系统规则、真实用户发言、模型回复和原生工具交换保留各自身份。列表默认显示可配置项，可勾选“显示固定类型”。

调用额度、剩余次数和最后一次调用提醒已删除，不属于可用消息类型，也没有相关适配设置或通知开关。旧配置中的此类映射会自动清理；后端调用上限仍由运行时执行，耗尽时报告错误。

旧配方的不同来源／role 组合保留为不同兼容类型。配方现在选择运行时类型，发送角色由该类型的 adapter 决定。导入时仍接受旧 role 字段。

状态更新将取代旧版本的说明与新状态放在同一消息内。关闭状态块时停止注入，不单独追加旧状态撤销通知。

## 编排和限制

Full Agent 将头部的可追加类型放在固定 system 区域末尾；其中映射为 system／developer 的类型先于其他角色，同组保持原顺序。后续追加版本保留其时间位置。

Half Agent 保留配方的顺序和深度，只提示可追加类型位于头部中间、映射打断 system 连续性等风险。中途 system／developer 按所选角色及原位置发送，程序不在本地拒绝请求、不自动降级角色或移动历史消息。所选角色是否被接受由服务商判断；服务商拒绝时显示实际请求错误。
