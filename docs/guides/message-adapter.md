# 消息类型与适配

运行时用自己的消息类型区分资料、任务和通知，发送模型请求时才转换成 SDK 角色。常驻世界书与中途世界书使用不同类型；同一类型的初始版本和追加版本使用同一映射及标签设置。

## 设置入口

游玩和制卡模型设置中的“消息适配”保存新对话的默认值。Half Agent 正文与 Tracker、Full Agent、制卡 agent 分别配置，并按接口协议保存。已有对话使用自己的副本。

参谋 agent 使用其独立模型配置中的消息适配，每次咨询按开始时的设置建立请求。

**默认角色**：可配置的资料类消息在 Google GenAI 接口默认映射为 user，在 Chat Completions、Responses 和 Anthropic Messages 接口默认映射为 system，各调用链规则相同。Tracker 的实际任务输入（`tracker_input`）在所有协议下默认为 user，确保请求里有真正的输入，而不是只有系统指令；它同样可以自定义角色与标签，已保存的映射不会被程序覆盖。

**切换接口**：手动切换接口时，该协议已有的可调角色（包括中途／可变世界书和兼容类型）恢复默认，标签选项和其他协议的配置保留。普通加载、切换调用链或对话都不会重置已有配置。切换后仍可自定义角色，或用“默认”按钮恢复该协议的默认值。

游玩对话在右侧“会话设置 → 高级 → 消息适配”中调整；制卡对话在输入区的“消息适配”中调整。对话创建时复制默认值，分支复制父对话设置，之后独立保存。

保存对话设置后，下一次模型调用立即按新设置转换整份上下文。同一回合内的工具续答也使用新设置。已发送请求和同一次调用的重试保持原快照。设置使用独立版本号，运行中也能保存，不影响剧情或草稿提交。

## 角色和标签

可配置类型包括中途注入的应用消息，以及可能追加新版本的类型。选择 system、developer、user 或 assistant，并决定是否包裹该类型的标签。标签名称由程序定义；正文自己包含的标签保持原样。输入标签设置不改变检索线索或工具输出协议。

Full Agent 的“长期笔记目录”（`note_list`）也可配置发送角色和标签，默认角色遵循上述接口规则，并使用 `<tavern_note_list>` 包裹。本地模式从第二个窗口起、云端模式始终提供；目录位于动态内容区，名称变化时追加完整新目录并注明取代此前目录，保持旧请求前缀。只列当前有效笔记的名称，笔记正文仍按需读取。

角色卡字段、合并角色资料、用户角色资料、常驻世界书、创作偏好和检索输出协议也可配置角色与标签，默认保留原有资料标签。它们可由配方定位到正文中，不视为只能处于顶部的系统规则。顶级主系统规则、工具协议、窗口机制、环境快照与后台固定契约保持固定；真实用户发言、模型回复和原生工具交换保留各自身份。列表默认显示可配置项，可勾选“显示固定类型”。

模型调用额度由运行时内部管理，达到上限时返回错误并保留可恢复进度。可配置消息类型以界面目录为准。

旧配方、世界书和脚本产生的不同来源／role 组合保留为不同兼容类型；目录包含各类型支持的全部兼容组合，不依赖它是否已经出现在配方中。可通过“显示兼容类型”或搜索查看，已保存的兼容设置始终显示。兼容类型独立保存映射，不继承基础类型的自定义值。配方现在选择运行时类型，发送角色使用对应接口默认值或该类型显式保存的适配设置。导入时仍接受旧 role 字段以识别兼容类型。

世界书和脚本注入的可选 `role: null` 按未设置处理，来源角色默认 system，不生成空角色的兼容类型。脚本生成选项（含嵌套脚本生成）任意层级的 `null` 在入口统一按省略处理，例如注入深度默认 0、自定义提示内容和本轮输入默认为空；明确的空字符串、空列表、`0` 和 `false` 保持原有含义。

状态更新把版本说明和新内容放在同一消息中。Half Agent 配方关闭状态块时，追加记录层写入一次撤销通知；重新启用后提供当前状态。详细规则见[动态上下文记录](../design/context-lifecycle.md#动态上下文记录)。

## 编排和限制

Full Agent 将头部的可追加类型放在固定 system 区域末尾；其中映射为 system／developer 的类型先于其他角色，同组保持原顺序。后续追加版本保留其时间位置。

Half Agent 仅在已划定的头部区域内兜底保持 system 连续：system／developer 在前，其余角色的头部资料在后；两组内部顺序不变，只消除打断连续性的交叉，保持位置变化最小。该规范顺序供预览、请求和回放共同使用，重复适配不再按旧序号排回；头部内容及映射不变时，新增轮次只扩展正文，保持请求前缀稳定。保存的配方和正文深度位置不变，发生调整时在上下文诊断中说明。

包括 Google GenAI 在内的部分 API 明确不支持中途 system 消息。GenAI 仅将开头连续的 system 区域放入顶层 `systemInstruction`；正文仅接受 user／model（界面中的 assistant）。显式设置或正文深度位置导致不支持的角色时，在普通请求、流式请求或缓存创建发送前报错，提示调整消息适配或系统区位置，不静默改写角色。其他接口仍按所选角色发送，服务商拒绝时显示实际请求错误。

GenAI 角色错误使用“新一轮消息中的……”表述，显示消息类型、条目标题（如有）和实际 role，不显示序号。只读预览不会执行当轮检索，可能尚未包含当轮注入的资料。

上下文预览显示运行时类型、实际发送角色、标签结果和 adapter 版本。缓存与请求记录根据适配后的实际内容计算。接口能力探测仍检查原始协议；本地 Embedding／Reranker 不使用这套设置。

## Full Agent 的回合内消息

以下两类消息都可在 Full Agent 消息适配中查看和配置，都不触发卡片的 MESSAGE_RECEIVED。

**本轮正文草稿**（`roleplay_draft`）：在正文接收后的工具续答和失败续接中出现，说明正文的 H 引用和已接收段数。

- 普通对话未满三段时允许按需追加。Kemini 实验对话接收完整正文后，提示模型停止调用 `submit_story`，完成剩余工具调用或直接结束。
- 换窗或重建后，原响应不在上下文中时，补入已接收的完整累计正文；原响应已携带全部段落时不重复追加。回合提交后不再回放。

**回合完成标记**（适配键仍为 `turn_commit`）：默认用 `<tavern_turn_completed>` 标签，内容为“以上回合已完成，正文为 H{n}。”

- 只指明已完成的交流及其正文位置，不暴露草稿和事务提交状态，也不重复正文。正文由按最终生效文本回放的原响应承载；原响应已退出窗口时，改以普通历史回复出现。
- 它标识已完成交流的结束位置，供缓存断点使用。由于它紧邻下一条输入，措辞里不写“本轮”，也不写禁止性指令，以免被读成对新回合的要求。

## Kemini 实验模式

Kemini 实验对话中，Writer 和 Full Agent 的剧情请求改用保序规则，替代上述 system 前置分组。前缀与尾部各项的完整顺序见[设置指南](settings.md#kemini-式实验功能)，这里只说明角色如何转换：

- 四条绝对前缀（小说填充 → CLEAR → 创作身份与文风 → 资料起始）的源角色依次为 user / system / user / system；小说填充非空时，最终四条都是 user。
- 已保存的角色和标签映射先照常应用，再把中途的 system 转为 user；开头连续的 system 和真实的用户、模型、工具交换保持不变，不同来源的消息不合并。原生接口不额外插入通用 system 说明。
- 这一转换不改写已保存的映射。此类对话的剧情消息适配页显示当前实验规则，上下文预览展示最终角色和转换诊断。普通对话、Tracker、参谋 agent 和制卡 agent 沿用各自规则。
