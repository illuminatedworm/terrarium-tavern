# Half Agent 周期记忆与来源一致性

Half Agent 的 Tracker 在独立上下文中维护文本记忆、授权设定和 MVU 变量，Writer 负责正文生成。文本记忆承接近期剧情，角色卡和世界书保存稳定设定及长期经历，MVU 变量表示当前状态。

## 一次整理如何工作

1. Runtime 确定待处理范围。默认每五轮在正文后整理，可包含当轮待提交正文；裁剪前覆盖检查仅处理已有历史。周期、裁剪和手动重建使用同一增量引擎。重生成恢复回合前记忆，不执行新的周期或推进窗口。
2. 输入包括已有分类记忆、本批新剧情、之前最多两次交流及选中的完整辅助资料。背景交流与设定不会被标为新发生的事件。
3. 优先读取消息快照中的冻结世界书，再用本地 BM25 找相关角色资料、世界书和批次边界状态。没有保存历史角色资料时标注当前版本回退；模型不得把回退资料当作过去设定的证据。人物身份宏按当前会话规则展开；缺失的历史身份版本不能从该投影推断。
4. Runtime 将原文无损拆成带短编号的片段，Tracker 调用 write_memory 提交增量操作及所选编号；无变化也提交空操作。遗漏的旧记录不会自动删除。Runtime 回填真实消息 ID、逐字摘录及指纹，核对提供范围、引用及容量后合并草稿；模型通过选择短编号表达来源。
5. 关键变化有疑问且找到新资料时，最多复核一次。新增材料附加到尚未发送的 write_memory 工具结果，在同一循环中只修订对应待确认条目，不能扩展任务。无新材料或复核失败都保留待确认结论。
6. 工具仅写入任务草稿。正文、MVU和所有回调完成后，绑定本轮来源并校验最终原文，再将记忆和覆盖水位随同一回合事务提交。手动重建全部成功后才替换自动记忆，手工修订和删除标记保持。

原文引用确认某段文字的出处，角色说法的真实性仍需结合剧情判断。例如“我没有杀人”保存为否认；“明早给你钥匙”是事项，不立即改变保管人；回忆旧伤不覆盖当前伤势。设定与明确叙述冲突时保留发生记录，把争议结论放入待确认。

## 分类及来源

快照字段 `memory_document` 的格式版本为 1，包含稳定 ID 的条目。四种剧情分类是 `current` 当前进展、`episode` 变化与经历、`open` 未完成事项、`uncertain` 待确认内容；手工条目使用 `manual`。

条目记录内容、事实/说法/推断、人物、故事时间、明确知情对象、状态、剧情引用及设定引用。未知时间与知情范围保持未知。自动准出、移除和合并使用临时的 superseded 标记，提交当前记忆时完全移除，由程序维护。deleted 只保留用户手工删除的屏蔽记录，并回传给 Tracker。旧版本仍在原消息快照中；不会删除剧情。

剧情引用保存消息 ID、原文及宏输入的指纹、逐字摘录；设定引用使用短句柄；条目同时保留字段/条目身份、版本和完整片段身份，详细文本保存在资料日志。详细资料日志按保留策略清理，记忆条目和提示词日志分别管理。UI 的 valid 表示来源指纹匹配，unverified 表示来源缺少指纹，changed/missing 表示修改或不在分支。来源匹配确认文本与版本，语义判断由模型负责。

Writer 只接收按分类生成的自然语言文本；快照仅保存结构化条目，界面按分类显示。推断与人物说法带标记。仍有效的事项不会因模型本次未提及而消失。

Runtime 每次发送和整理时按原文来源执行准出：自动生成的当前进展默认最多 5 条，超出时先退出来源最旧的条目；自动生成的变化与经历在其最新来源之后满 20 个已完成剧情轮次退出，也可将轮数设为 0关闭时间准出。若活跃记忆超过容量，继续按来源从旧到新退出经历。手工条目、未完成事项、待确认内容及原文来源失效的条目不参加自动准出；它们仍占容量，剩余内容无法装入时明确报错。已完成的经历同样受准出规则约束。退出只改变当前记忆投影，不删除剧情原文；按轮数或容量退出的经历进入归档，见下一节。

## 归档与召回

活跃记忆是常驻 Writer 请求的投影，容量有限；按轮数或容量退出的自动经历不丢弃，而是进入当前分支的归档。当前进展、原话回调以及 Tracker 的移除与合并不进入归档：前者已被新状态取代，后者是模型判断为无效或已并入其他条目的内容。

**存储。** 每条消息快照的 `memory_retired` 只保存本条消息自己新增或修改的归档条目（增量），分支归档是从开场白到当前消息的增量依次合并，同一条目后写覆盖前写。回合草稿把本轮准出的条目暂存在 `memory_retiring`，提交事务、手工修改、手动重建和上下文方式切换在写入快照前统一与父链比较，只保留真正的新增或变化，因此草稿携带的上一条快照副本不会重复保存。分叉天然继承分叉点之前的归档，重生成使用回合前快照；分支复制时一并重映射归档来源。归档增量属于记忆格式，`memory_document.version` 因此为 2；version 1 的记忆不迁移，读取时报错并提示新建对话，见[设置迁移](../reference/settings-api.md#数据库与设置迁移)。

**召回。** 每次 Writer 请求前，Runtime 用世界书相同的查询（当前输入与最近 `<tavern_retrieval>` 线索）在归档中检索：BM25 始终启用，开启向量通道时共用世界书的向量缓存与索引任务，但两类索引分别判断完整性，缺失向量只使对应类别的向量通道降级；归档条目没有触发关键词，不走关键词通道。准入沿用世界书门槛：BM25 覆盖率与分数下限、向量相似度下限，开启重排时再按重排分数下限过滤；重排失败只保留有独立词法证据的候选，不放宽门槛。最终最多保留 `memory_recall_count` 条（默认 3，0 关闭召回及归档向量准备），选中的条目完整注入。只读预览只运行 BM25，并返回独立的召回证据，不修改传入的缓存检索结果。

**筛选（可选）。** 开启 `memory_recall_filter` 后，已准入的候选再交给后台模型判断下一段正文是否真正需要。模型只看到候选的 A1、A2… 短编号、内容、人物、故事时间与性质，以及最近一次交流和当前输入，通过强制工具 `select_recall` 返回所选编号；引用未提供的编号视为失败。模型服务失败、超时或返回格式不合法时沿用阈值准入结果并在工作记录中提示，因为筛选只会收窄已通过准入的候选；内部数据或程序错误直接报错，不按筛选失败降级。输出上限沿用 `memory_output_tokens`。默认关闭；开启且召回非空时，每次正文生成多一次后台请求，脚本每次嵌套生成也分别筛选其当前输入的候选。

筛选响应返回后，先按 `memory_recall` 用途记录实际用量、调用次数和耗时，再校验所选编号；格式错误的响应也计入会话累计用量，服务商未提供的计数保持未知。筛选结果与失败回退记录使用同一用途，工作记录中统一显示为“归档召回筛选”。

筛选失败的回退也覆盖创建后台连接时的配置、认证和账号刷新错误；该可选请求失败不会阻断正文。配方关闭记忆块、记忆块条件不满足，或脚本的 `ordered_prompts` 未包含记忆时，不发起筛选请求。

缓存引用由正文请求和索引准备维护；Tracker、参谋 agent 与脚本临时查询不覆盖会话的缓存集合。世界书和归档分别复用已读取的向量，新增条目或索引未齐时只读取新增、变化或缺失项；缓存仍有容量边界，缺失项未齐时保持原有通道降级规则。

**注入。** 召回结果以独立的动态来源“相关旧事”（`memory_recall`）紧跟记忆块，同样使用 `<tavern_memory>` 标签并注明“只是过去的经历，当前状态以记忆与剧情状态为准”。它与记忆块分开跟踪：召回变化时只追加新的相关旧事版本，不会重发整个活跃记忆；召回为空时追加撤销。记忆块关闭时召回也不注入。

**手工修改。** 记忆面板的“已归档经历”分组列出当前分支归档、来源状态及归档时已完成的剧情轮数，可编辑文字与内容性质（保存后标记为手工修订）或删除（写入删除标记）。修改写在当前消息的增量里，因此分叉到修改之前的分支仍保留原条目。手动重建会为所有自动归档条目写入删除标记，再保存本次重建产生的归档；手工修订过的归档条目保留。归档删除不阻止重建以新条目重新归档同一事件。

来源标签在部分来源无法定位时同时显示来源总数与无法定位的数量；展开后仍保留各处完整摘录和来源状态。

## 短编号输出协议

模型请求与存储格式分开，引用身份由程序恢复：

| 编号 | 用途 | 模型需要做什么 |
|---|---|---|
| H52 | 当前分支第 52 条消息（开场白为 H1） | 标识消息与读取历史；不能直接作为 `sources` |
| H41-H50 | 连续闭区间 | 输入用 `batch_range`、`background_range` 声明本批与背景的位置 |
| H52#3 | H52 的第 3 个原文片段 | `sources` 只选本次展示过的片段，至少一个落在 `batch_range` 内 |
| R1、R2… | 已有记忆 | 修改、完成、合并、移除时选条目，不抄写永久 ID |
| E1、E2… | 本次提供的设定/状态片段 | `setting_refs` 选择资料；完整版本和身份由程序保存 |
| N1、N2… | 本次新增记忆的临时编号 | 疑问可按 `add` 出现顺序引用未写 ID 的新条目；也可在 `add.id` 显式编号，显式编号优先且不能重复 |

H 是分支位置，与 Full Agent、参谋 agent 和剧情界面显示的编号相同，由共享的 [history_refs.py](../../src/tavern/core/history_refs.py) 计算；当前输入和待提交正文按将要占据的位置编号。片段由同一切分规则对宏展开后的模型可见文本确定，所以同一消息在本批输入、背景、补查结果和复核中给出相同的片段编号。H 编号跨请求不变，但每次基础批次、复核只登记本次实际展示的片段：上批展示过而本次未展示的片段不能引用。设定版本的 V 编号用于说明结构；R、N、E 编号每次基础批次、复核重新分配，同一次工具续答沿用该请求的映射。映射仅在 Runtime 内存中存在，不由模型提交，不写入存档。实际存档仍使用原有 `memory_document`、消息 ID、内容指纹与逐字摘录，H 只是给模型和界面看的渲染形式；来源定位、编辑提示和分叉重映射使用恢复后的身份，随回合事务提交。

例如 `batch_range` 为 `H3-H4`，输入片段 `{"ref":"H4#1","text":"她把戒指借给了用户。"}`，write_memory 的参数可以是：

```json
{
  "operations": [
    {
      "op": "add",
      "record": {
        "category": "current",
        "content": "戒指暂由用户保管。",
        "sources": [
          "H4#1"
        ]
      }
    }
  ],
  "questions": []
}
```

程序生成新增记忆的永久 ID，并从 H4#1 精确回填原文和消息引用。新增时未知人物、时间及知情范围、默认有效状态等可省略；修订时省略的内容字段继承旧值，`sources` 每次必填，`setting_refs` 每次默认为空。角色说法必须写 `kind: "claim"`，推断必须写 `kind: "inference"`。模型仍需判断片段与结论之间的关系，引用校验只确认来源存在且有效。

原文按标点/换行组织，每个片段最多 600 字符；极长无标点文本连续拆分，所有字符按原序在同一次请求中完整保留，不截掉消息尾部。每条记录最多选择 8 处来源。“至少一处来源属于本批”按位置判断：来源片段所在消息须落在 `batch_range` 内；背景和补查片段只能补充。只有实际展示的片段可引用；搜索只展示命中片段时，复核也只列出这些片段并保留原编号，不把不连续的命中拼成一条假原文。编号及片段包装计入输入估算；比较输入成本时需要同时计算资料、工具结果及封装。

## 调用预算与失败策略

参数默认值、范围和保存位置统一见[记忆与任务限额](../guides/history-maintenance-settings.md#记忆与任务限额)。这里说明额度的共享方式和失败语义。

自动整理最多两批和一次可选复核。前置/后置任务各自默认最多 8 次模型请求，分批、复核、工具续答不重置额度；提前完成即停止。历史补查另限整次操作 3 次。手动重建不限总批数，每批使用模型调用额度和独立上下文，携带累计记忆而不重放此前全部原文；启动前显示批次数估算，可取消。输入按完整交流分批，单条超量仍完整发送；最终请求估算包含实际工具定义和完整交换。

容量超限会按来源时间退出自动经历，仍不足时明确报错，不删除未完成事项、待确认或手工内容。纯周期任务失败时丢弃整个后台任务的修改，保留旧档案和覆盖并提示，可保存正文；混合任务包含变量更新或明确设定修改，或者裁剪前覆盖不足时，整轮不提交。关键记录的引用或操作无效会拒绝本批；只有新增的可选台词/动作记录可单独丢弃并提示。纯文本无法解析、后续分批失败、取消和审核拒绝均不部分提交。

轻量 callback 本身不增加专门的模型调用；历史补查工具仅用于本批连续性核对，不能为了制造回调反复检索。仅附带保留已读剧情中最多三条代表性原话/动作，合计 300 tokens；超限先退出旧的可选条目。它只提供有限的近期细节，不承担长期事实存储。

工作记录区分 memory 基础整理与 memory_review 疑难复核，记录批次来源、估算输入、资料候选及实际选入内容、结果、实际 token 用量和耗时。服务商缺失字段不能当成零消耗；只有计价信息完整时才能换算金额。

## 手工修改与接口

`memory_document` 的格式版本为 1，与数据库 schema 独立演进。读取存档使用已有记忆及来源记录；数据库升级见[设置持久化与 API](../reference/settings-api.md#数据库与设置迁移)。

- `PUT /api/sessions/{sid}/memory/records`：`expected_revision`、`action`（add/edit/delete）、已有条目 `id`，以及 `content/category/kind`。增删改受会话版本与运行互斥保护；手工添加/修改不会自动被覆盖。删除保留紧凑屏蔽标记，防止相同条目/原文被重新加入。Tracker 再次提出被屏蔽内容时只忽略该操作及其依赖，不阻断本批其他有效修改和覆盖水位；工作记录显示忽略原因。其他关键来源错误仍使整批失败。
- `GET /api/sessions/{sid}/memory/rebuild-estimate`：只读估算基础批次数和额外复核上限，不能保证实际费用。
- 会话返回 `memory_view`，含分类与来源状态；`archived_memory` 是当前分支的归档条目及来源状态。上述 `PUT` 的 `id` 指向归档条目时，`edit` 修订文字与性质、`delete` 写入删除标记，`add` 不适用。`POST /api/sessions/{sid}/scene/memory/regenerate` 提交独立的记忆重建任务，成功受理返回 202。
- 编辑剧情保留旧记忆，只提示来源已改；覆盖指纹仍按既有行为重定位，下一周期不会借机重读旧剧情。手动重建才重新核对全部可见原文。新发生的变化仍可以正常处理。
- 分叉重映射引用，重生成使用对应历史快照。设置使用 `tracker_system_prompt`，程序提供任务范围，工具定义规定 `operations/questions` 参数。旧提示词处理见[设置迁移](../reference/settings-api.md#数据库与设置迁移)。

## 整理入口

[tracker/workflow.py](../../src/tavern/tracker/workflow.py) 调度前后置任务；[tracker/task.py](../../src/tavern/tracker/task.py) 的原生工具循环接入 `memory_engine.consolidate`，周期、裁剪前及手动重建共用来源、保护和增量校验。`memories/memory.py` 的 `Tracker.prepare` 是低层兼容入口，普通回合使用统一任务调度。

## 排查

“模型服务拒绝超长输入”：检查上下文容量或自行精简原文。程序不会把已有资料截短后重试。

“活跃记忆超过容量”：可退出的经历已经用尽；合并受保护条目或提高容量，这也会增加后续Writer和Tracker输入。

“关键来源无效”：核对批次原文和错误详情，修正引用后重试；期间保留原窗口。

“未知原文片段编号……本次未提供”：模型引用了本请求没有展示的片段，包括上批展示过的片段、只写消息编号 H52 或不存在的编号。关键变化仍拒绝本批，旧记忆和覆盖水位保留；重试时使用当前批次或本批补查展示的片段编号。仅新增可选 callback 的无效来源可以丢弃并提示。若自定义提示还要求消息 ID、逐字摘录或旧 `text/memories`，应按上述最小协议修订。完整 JSON 无法解析仍不自动重试。

“原文已修改，尚未重建”：这是一条持续提示，不会自动修复；使用重新生成记忆。手工修订仍受保护，冲突需要人工处理。

“疑难复核未运行”：检查复核开关、新增材料和调用上限，疑问继续保存在待确认记录中。

实现入口包括 [memory_archive.py](../../src/tavern/memories/memory_archive.py)（归档增量与召回渲染）、[recall_filter.py](../../src/tavern/memories/recall_filter.py)（可选筛选）、[memory_engine.py](../../src/tavern/memories/memory_engine.py)（编排与增量校验）、[memory_protocol.py](../../src/tavern/memories/memory_protocol.py)（短编号及恢复）、[memory_evidence.py](../../src/tavern/memories/memory_evidence.py)（参考资料）和 [memory_records.py](../../src/tavern/memories/memory_records.py)（分类投影与来源）。

## Tracker 历史补查工具（固定 3 次）

`tavern_recall_history` 只给 Tracker 使用，Writer 无工具。工具读取当前分支已提交历史，并遵守当前记忆批次截止位置；待提交正文通过任务材料提供，不混进历史补查。

- `query` 与 `ref` 二选一。搜索使用空格分隔的关键词，每条命中消息返回其消息编号及包含命中处的完整片段（每段不超过 600 字符，使用全局片段编号，如 `H52#3`）；未返回该消息全部片段时标 `partial: true`。读取用 `ref`（如 `H52`）返回该消息所在完整交流及附近交流的全部片段。limit 按命中的完整交流数计，范围 1–8、默认 5；一个交流中的用户与助手消息均命中时分别返回。radius 是中心交流前后各额外读取的完整交流数，范围 0–2、默认 1，0 只读中心交流，到历史边界时不越界。所有区间均含两端。
- 完整交流由用户输入及其回复组成，开场白单独算一个；关键词不能跨用户与助手的消息边界拼成命中，只有能返回命中片段的交流才占搜索名额。只能读取不晚于本批且已有回复的消息，越界或末尾尚无回复的输入返回参数错误并说明可查范围。记忆周期另按成功交流轮数计算。
- 整次 Runtime 操作共享 3 次额度，搜索、读取、空结果、错误和重复查询均计次；前后置、分批、复核不重置。手动重建也整次共享 3 次。
- 来源引用仅限实际返回的片段；补查不能单独证明本批新变化，不能恢复手工删除内容、覆盖手工记录或自动修复来源已改动的旧记忆。
- 不设置跨轮冷却；工具续答计入 Tracker 模型调用额度。超长原文仍完整发送，服务商拒绝时保留旧档案与覆盖。

## 其他层级与权限

仅更新变量或设定、尚未到记忆周期的任务，不开放 write_memory。search_memory 返回完整命中记录及类型、手工保护和来源过时状态。所有记忆写入都通过批量增量协议，受同一删除屏蔽规则约束。

read_character 与 revise_content 均相对于角色数据根，程序处理 data 包装及隐藏身份。search_lore 只读取，不改变 Writer 的准入选择。修改后 Runtime 重新检索；长期沉淀可以修订现有资料或新增世界书，不自动删除对应文本记忆。

patch_state 只在勾选本轮更新变量时开放，接受一次补丁或空数组；它仅暂存，最终才执行一次 MVU 与消息回调。失败、重试、重生成不会重复应用。变量分析由该 Tracker 任务完成。

工作记录以 tracker_pre、tracker_post、tracker_rebuild 区分阶段，并区分文本记忆写入、角色卡修改、MVU补丁暂存。读取历史日志时兼容其原用途名称。所有真实请求均计入用量，工具和最终提交的状态分开呈现。
