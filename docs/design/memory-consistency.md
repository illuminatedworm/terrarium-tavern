# 一致性优先的周期记忆

本功能只改进 Tracker 的记忆整理。Writer 仍零工具，MVU 仍由独立分析路径更新，授权设定维护仍为独立工具模式。记忆不是第二套变量数据库；它保存有出处的剧情发展及尚不能定性的内容。

## 一次整理如何工作

1. Runtime 确定待处理的已提交消息范围。五轮周期、裁剪前覆盖检查及手动重建使用同一引擎。重生成不自行推进覆盖。
2. 输入包括已有分类记忆、本批新剧情、之前最多两次交流及选中的完整辅助资料。背景交流与设定不会被标为新发生的事件。
3. 优先读取消息快照中的冻结世界书，再用本地 BM25 找相关角色资料、世界书和批次边界状态。没有保存历史角色资料时标注当前版本回退；模型不得把回退资料当作过去设定的证据。人物身份宏仍沿用现有会话展开规则，不声称恢复了不存在的身份修订档案。
4. Runtime 将原文无损拆成带短编号的片段，Tracker 返回增量操作及所选编号。遗漏的旧记录不会自动删除。Runtime 回填真实消息ID、逐字摘录及指纹，核对提供范围、引用及容量后合并草稿；模型不再负责复制或配对长ID与原话。
5. 关键变化有疑问且找到新资料时，最多复核一次。只修改对应的待确认条目，不能循环检索或扩展任务。无新材料或复核失败都保留待确认结论。
6. 正文及后续处理成功后，记忆和覆盖水位随同一回合事务提交。手动重建全部成功后才替换自动记忆，手工修订和删除标记保持。

原文引用只能证明某段文字出现过，不能证明角色说法客观为真。例如“我没有杀人”保存为否认；“明早给你钥匙”是事项，不立即改变保管人；回忆旧伤不覆盖当前伤势。设定与明确叙述冲突时保留发生记录，把争议结论放入待确认。

## 分类及来源

快照字段 `memory_document` 的格式版本为 1，包含稳定 ID 的条目。四种剧情分类是 `current` 当前进展、`episode` 变化与经历、`open` 未完成事项、`uncertain` 待确认内容；手工条目使用 `manual`。

条目记录内容、事实/说法/推断、人物、故事时间、明确知情对象、状态、剧情引用及设定引用。未知时间与知情范围保持未知。自动准出、移除和合并使用临时的 superseded 标记，提交当前记忆时完全移除；它不是模型应填写的条目状态。deleted 只保留用户手工删除的屏蔽记录，并回传给 Tracker。旧版本仍在原消息快照中；不会删除剧情。

剧情引用保存消息 ID、原文及宏输入的指纹、逐字摘录；设定引用使用短句柄；条目同时保留字段/条目身份、版本和完整片段身份，详细文本保存在资料日志。详细资料日志受日志保留期约束，长期记忆不是永久的全部提示词档案。UI 的 valid 表示来源指纹匹配，unverified 表示来源缺少指纹，changed/missing 表示修改或不在分支。来源匹配不等于语义判断正确。

Writer 只接收按分类生成的自然语言文本；快照仅保存结构化条目，界面按分类显示。推断与人物说法带标记。仍有效的事项不会因模型本次未提及而消失。

Runtime 每次发送和整理时按原文来源执行准出：自动生成的当前进展默认最多5条，超出时先退出来源最旧的条目；自动生成的变化与经历在其最新来源之后满20个已完成剧情轮次退出，也可将轮数设为0关闭时间准出。若活跃记忆超过容量，继续按来源从旧到新退出经历。手工条目、未完成事项、待确认内容及原文来源失效的条目不参加自动准出；它们仍占容量，剩余内容无法装入时明确报错。已完成的经历同样受准出规则约束。退出只改变当前记忆投影，不删除剧情原文。

## 短编号输出协议

为了降低小模型的机械复制负担，模型请求与存储格式分开：

| 编号 | 用途 | 模型需要做什么 |
|---|---|---|
| S1、S2… | 本批原文及明确分开的背景原文片段 | `sources` 选择支持结论的片段，至少一个属于本批新增 |
| H1、H2… | 历史工具实际返回的片段 | 可以补充引用，不能单独证明本批新变化 |
| R1、R2… | 已有记忆 | 修改、完成、合并、移除时选条目，不抄写永久ID |
| E1、E2… | 本次提供的设定/状态片段 | `setting_refs` 选择资料；完整版本和身份由程序保存 |
| N1、N2… | 本次新增记忆的临时编号 | 疑问可按 `add` 出现顺序引用未写 ID 的新条目；也可在 `add.id` 显式编号，显式编号优先且不能重复 |

消息容器的 M 编号和设定版本的 V 编号只供理解，不是剧情来源编号。编号每次基础批次、复核重新分配；同一次工具续答沿用该请求的映射。映射仅在 Runtime 内存中存在，不由模型提交，不写入存档。实际存档仍使用原有 `memory_document`、消息ID、内容指纹与逐字摘录，来源定位、编辑提示、分叉重映射及事务提交规则不变。

例如输入片段 `{"ref":"S2","text":"她把戒指借给了旅人。"}`，最小输出可以是：

```json
{"operations":[{"op":"add","record":{"category":"current","content":"戒指暂由旅人保管。","sources":["S2"]}}],"questions":[]}
```

程序生成新增记忆的永久ID，并从 S2 精确回填原文和消息引用。新增时未知人物、时间及知情范围、默认有效状态等可省略；修订时省略的内容字段继承旧值，`sources` 每次必填，`setting_refs` 每次默认为空。角色说法必须写 `kind: "claim"`，推断必须写 `kind: "inference"`。这不是语义真实性保证：模型仍须判断片段是否真正支持结论，选对一个合法编号也可能理解错剧情。

原文按标点/换行组织，每个片段最多600字符；极长无标点文本连续拆分，所有字符按原序在同一次请求中完整保留，不截掉消息尾部。每条记录最多选择8处来源。只有实际返回的片段可引用；复核不把不连续的搜索命中拼成一条假原文。编号及片段包装计入输入估算，省去响应中的原文复制和历史记忆中的技术字段，但不承诺所有场景都降低总 tokens，也不增加模型请求或自动重试。

来源统一使用请求内短编号；程序回填消息身份、指纹与摘录并验证来源。

## 设置、成本与失败策略

| 设置 | 默认值 | 范围与作用 |
|---|---:|---|
| memory_input_tokens | 32768 | 2048–2000000，按完整交流分批的目标；单条超量仍完整发送 |
| memory_evidence_tokens | 4096 | 旧配置兼容字段；0 禁用辅助资料，正数启用，均不限制选中资料的长度 |
| memory_output_tokens | 4096 | 256–65536，新安装默认值；旧配置继承原后台输出上限，之后独立调整 |
| memory_capacity_tokens | 4096 | 512–65536，交给Writer的活跃记忆文本容量；容量不足时明确报错，不截断必要数据 |
| memory_current_max_records | 5 | 1–100，自动生成的当前进展条数上限；超出时退出来源最旧者 |
| memory_episode_cooldown_rounds | 20 | 0–10000，自最近引用的已完成剧情轮次起算；0关闭按轮数退出 |
| memory_review_enabled | true | 关键疑问最多一次复核；输出最多2048 tokens，输入保持完整 |
| memory_timeout | 120秒 | 5–180秒，每个请求计时，基础请求与复核均不自动重试 |

自动整理一轮保留最多两次基础分批加一次复核，窗口重新规划不会重置计数。只读历史工具另有独立的3次总额度；实际使用后最多追加3次模型续答，所以自动记忆部分最多6次模型请求。授权设定维护仍独立受原有4次模型调用上限约束。输入按完整交流分批，绝不从一条原文中间截断。单条交流或已有记忆超出估算预算时仍完整发送；服务商若拒绝则如实报错。手动重建没有两批限制，启动前显示按当前记忆计算的批次估算；记忆增长可能使实际批次增加，可取消。

容量超限会按来源时间退出自动经历，仍不足时明确报错，不删除未完成事项、待确认或手工内容。无需退出窗口时保留旧档案并继续正文；必须退出且覆盖不足时停止本轮发送。关键记录的引用或操作无效会拒绝本批；只有新增的可选台词/动作记录可单独丢弃并提示。纯文本无法解析、后续分批失败、取消和审核拒绝均不部分提交。

轻量 callback 本身不增加专门的模型调用；历史补查工具仅用于本批连续性核对，不能为了制造回调反复检索。仅附带保留已读剧情中最多三条代表性原话/动作，合计300 tokens；超限先退出旧的可选条目。它不保证几十轮后自动想起某个特定片段。

工作记录区分 memory 基础整理与 memory_review 疑难复核，记录批次来源、估算输入、资料候选及实际选入内容、结果、实际 token 用量和耗时。服务商缺失字段不能当成零消耗；只有计价信息完整时才能换算金额。

## 手工修改与接口

数据库和记忆文档均采用版本 1；存档读取不调用模型、不自动重建、不补造来源。

- `PUT /api/sessions/{sid}/memory/records`：`expected_revision`、`action`（add/edit/delete）、已有条目 `id`，以及 `content/category/kind`。增删改受会话版本与运行互斥保护；手工添加/修改不会自动被覆盖。删除保留紧凑屏蔽标记，防止相同条目/原文被重新加入。Tracker 再次提出被屏蔽内容时只忽略该操作及其依赖，不阻断本批其他有效修改和覆盖水位；工作记录显示忽略原因。其他关键来源错误仍使整批失败。
- `GET /api/sessions/{sid}/memory/rebuild-estimate`：只读估算基础批次数和额外复核上限，不能保证实际费用。
- 会话返回 `memory_view`，含分类与来源状态。`scene/memory/regenerate` 用于手动重建分类记忆。
- 编辑剧情保留旧记忆，只提示来源已改；覆盖指纹仍按既有行为重定位，下一周期不会借机重读旧剧情。手动重建才重新核对全部可见原文。新发生的变化仍可以正常处理。
- 分叉重映射引用，重生成使用对应历史快照。内容整理原则与唯一的 `operations/questions` 输出契约组装在同一系统消息中；自定义提示词只调整内容取舍，不能要求完整快照格式之外的输出。自定义提示词必须遵循同一输出契约。

## 整理入口

`memory_engine.consolidate` 统一承担周期、裁剪前及手动重建。

## 排查

“模型服务拒绝超长输入”：检查上下文容量或自行精简原文。程序不会把已有资料截短后重试。

“活跃记忆超过容量”：可退出的经历已经用尽；合并受保护条目或提高容量，这也会增加后续Writer和Tracker输入。

“关键来源无效”：查看批次原文与错误详情。原窗口保留；不要把删除来源检查当作解决办法。

“未知原文片段编号”：模型引用了本请求没有提供的 S/H 编号。关键变化仍拒绝本批，旧记忆和覆盖水位保留；不要借用上批编号。仅新增可选 callback 的无效来源可以丢弃并提示。若自定义提示还要求消息ID、逐字摘录或旧 `text/memories`，应按上述最小协议修订。完整 JSON 无法解析仍不自动重试。

“原文已修改，尚未重建”：这是一条持续提示，不会自动修复；使用重新生成记忆。手工修订仍受保护，冲突需要人工处理。

“疑难复核未运行”：可能关闭、没有新增材料或达到本次上限；待确认不等于遗忘或失败覆盖。

实现入口为 memory_engine（编排与预算）、memory_protocol（请求内短编号及程序回填）、memory_evidence（只读参考材料）、memory_records（分类投影与来源）；scene 的旧整理函数仅用于历史格式测试及有预算的旧实现对照，不再被生产整理路径调用。


## Tracker 历史补查工具（固定3次）

`tavern_recall_history` 只给 Tracker 使用，Writer 的工具集合仍为空，MVU 分析不接入该工具。既有分类记忆和周期/裁剪前/手动整理流程继续保留，不调整触发频率。工具只作为信息不足时的补充，并不自动搜索每轮剧情。

- `query` 与 `turn` 二选一。搜索使用空格分隔的关键词，本地按短语与词项覆盖排序，记忆整理和独立授权维护都返回段编号及 H 编号片段，不让模型复制消息ID。授权维护的 `write_memory` 选择 H 编号后由程序填写来源。`limit` 默认5、最大8个历史段。
- 按 `turn` 读取附近原文，`radius` 默认1、最大2。段编号从1开始，开场白单独编号；它与设置中的“完成交流轮数”不是同一个计数。
- 整次Runtime操作共用3次额度，搜索、读取、空结果、错误参数及重复查询都消耗一次。自动分批、窗口重算、疑难复核、本轮授权维护不会重置；手动重建所有批次合计也只有3次。第四次不执行查询。老的授权维护 `search_history` 别名也共享额度，不能绕过限制。
- 只读取Runtime传入的当前有效分支，不接受会话或分支ID参数；周期和手动分批不得访问本批之后的消息。待提交输入、失败草稿、其他分支和工具轨迹不作为检索资料。
- 按 `turn` 读取时完整返回选中历史段，不按 token 截断。搜索仍返回定位用的原文摘要；模型引用的内容必须实际出现在工具结果中。
- 历史可以作为补充依据，但一项新变化仍须引用本批新增剧情。不能借补查恢复手工删除记录、覆盖手工内容或自动修复来源已变动的旧记忆。
- 不设置跨轮冷却。仅同一模型续答上下文内去重；跨批次不能假定模型仍看到上一次工具结果，但次数额度仍共享。
- 本地查询没有生成式API开销；工具调用后的模型续答有。最多3次额外续答，不截断返回原文；若模型服务无法容纳完整结果，本次整理失败并保留旧档案和覆盖水位。达到工具额度后停用工具；模型仍请求工具时停止该次整理。
- 工作记录逐次显示历史查询结果、次数、限额拒绝及实际模型用量，`history_continuation` 区分工具后的续答。工具不会写状态、记忆、世界书或窗口游标。

后台模型需支持原生函数调用。默认记忆提示词已允许这个唯一的只读工具，自行编写了“不调用工具”的自定义记忆提示词应同步调整。实际效果和成本需按所用模型独立评估。
