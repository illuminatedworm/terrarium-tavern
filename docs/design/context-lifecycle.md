# Half Agent 上下文生命周期

Writer 的上下文由配方、本地滚动窗口或云端 compact，以及 Tracker 记忆覆盖共同管理。Full Agent 使用[独立工作窗口](full-agent.md#工作窗口与追加记录)。两种模式共享压缩协议与操作服务，但分别规划来源及切回本地的行为。

## 编排与资料标签

上下文配方控制文本块的顺序、角色、深度、预算提示阈值和条件。新会话复制全局配方，已有会话及分支独立保存。深度留空按列表顺序，0 放在末尾，正整数从最后一条剧情消息向前定位。

运行时补充检索协议、当前对话偏好和常驻世界书，默认跟在应用系统提示词之后。世界书统一使用 `<lorebook>`，记忆投影使用 `<tavern_memory>`，剧情状态使用 `<tavern_state>`，作者注使用 `<author_note>`。作者注、角色后置要求和状态的动态更新说明与撤销消息也包在各自标签内。

应用系统提示词本身不加资料标签，开场白及备选开场作为普通剧情。新配方将角色系统提示、描述、性格和场景拆成独立块；仍使用合并块的配方可在编辑器拆分，保留角色、深度及条件。

默认编排让历史正文、本次输入锚定的世界书和当前输入连续出现，之后追加后置要求、作者注、记忆及状态。滚动世界书始终贴近对应锚点，其位置不随再次命中改变。

Kemini 实验对话使用显式的保序例外：小说填充、CLEAR、创作身份与文风、资料起始构成独立的绝对头部，整体在所有应用消息之前，不参加配方／世界书／脚本的深度计算，也不能被应用规则穿插；角色扮演追加要求、助手确认和输出要求在历史后，并排在本轮动态更新与撤销说明之后、始终位于请求末尾；它们按本轮临时帧处理，原文直接发送，不叠加动态更新说明，也不回放到后续轮次。输出要求依次包含自检、正文约束、可选免责声明、正文传输指令和末尾输出提示。完整的 Interleaving 三段式示例成对保留在这同一条 `kemini_control` 消息中，CLEAR 和末尾提示仅引用名称，不通过孤立开标签跨消息续写。最终消息适配保留此顺序，将中途 system 转为 user；普通对话使用普通分组。角色映射的保存值保持不变，界面说明和预览诊断见[消息适配](../guides/message-adapter.md#kemini-实验模式)。

以下示例展示剧情与当前输入锚点的相对位置：

```json
[
  {"role":"user","content":"我来到港口。"},
  {"role":"assistant","content":"钟声从防波堤另一侧传来。"},
  {"role":"system","content":"<lorebook>港口钟塔每天黄昏鸣钟。</lorebook>"},
  {"role":"user","content":"我向钟塔走去。"}
]
```

Writer 请求不自动添加 `[H52]` 位置行：历史用户消息、当前输入、AI 回复、开场白及脚本生成均保留原文中的编号文本，原生 API 回放也不添加编号。Tracker 的独立上下文、历史工具和剧情界面仍按分支位置使用 H 编号；Full Agent 的请求编号规则见[Full Agent 设计](full-agent.md#handoff-章节)。这份片段有四条协议消息，其中三条是剧情。世界书影响 token 占用，不增加历史剧情条数。

## 角色卡顶层字段（两种模式共用）

以下为 Half Agent 默认配方与 Full Agent 固定编排的字段顺序。Full Agent 的角色资料也拆成独立消息，可分别预览和计数。

| 字段 | 默认位置 | 包裹标签 |
|---|---|---|
| `system_prompt` | 固定角色资料区第一块 | `<card_system_prompt>` |
| `description` | 角色系统要求之后 | `<card_description>` |
| `personality` | 描述之后 | `<card_personality>` |
| `scenario` | 性格之后 | `<card_scenario>` |
| `mes_example` | 用户角色资料之后、真实剧情之前 | `<card_mes_example>` |
| `post_history_instructions` | 历史和当前输入之后的动态要求区 | `<card_post_history_instructions>` |

字段非空才注入，完整展开受支持的宏后发送，不按长度裁剪。Half Agent 尊重已保存配方的启用、条件和深度；头部按最终角色做稳定分组，system／developer 在前、其他角色在后，各组内部保持配方顺序，以最小位移保证系统区连续。规范顺序在重复适配和后续回放中保持不变，正文深度位置不参与该分组，实际调整在预览诊断中展示。旧 `character` 合并块继续包含系统要求、描述、性格、场景，不自动改写旧配方或叠加一份独立字段。Full Agent 不消费 Half Agent 配方，固定字段随工作窗口恢复。

运行时用字段标签标识来源，不额外注入字段用途说明，也不根据字段名限定作者实际写入的内容。具体含义由模型结合卡片原文和上下文理解。固定字段改变时按现有机制重建基线；后置要求继续按下述动态记录规则更新或撤销。

其他顶层字段的去向：`name`／`nickname` 用于身份及宏；`first_mes`／`alternate_greetings` 只将用户选中的一个开场作为普通 assistant 剧情，未选开场不注入。`creator_notes`、`creator`、`tags`、`character_version` 留在卡片信息中，作者备注作为卡片元数据保存，运行时作者注由配方配置。`character_book` 沿用世界书准入机制；`extensions` 仅按已支持的扩展解释，不整包注入。

Half Agent 的 Tracker 使用独立维护上下文：`name`、`description`、`personality`、`scenario` 位于 `tavern_tracker_input` 的结构化 `character` 资料中。任务输入类型 `tracker_input` 在各协议中默认发送为 user，固定规则和操作契约保持 system；避免中转把全部输入当作系统指令提取后，得到空的 Responses `input` 或 Gemini `contents`。卡内系统要求、后置要求和示例不作为维护指令注入，需要编辑时通过工具读取。记忆参考池仅选取描述、性格、场景等设定资料，示例与未选开场不进入剧情证据。资料与剧情的区别由现有维护契约处理，不另加字段用途说明。

## 动态上下文记录

配方决定准入和位置，追加记录层保持已发送动态内容的顺序。普通尾部的作者注、角色后置要求、分类记忆、相关旧事（归档召回，紧跟记忆块）和状态按来源、角色及宏展开后的内容跟踪：首次注入，变化时追加新版本，内容退出编译结果时追加撤销。剧情状态块关闭或条件不满足时只追加一次撤销；重新开启时追加当前值，即使它与撤销前相同。块保持启用而状态清空为空对象时，完整发送空状态更新以取代旧值。

例如，状态从“戒指由艾琳保管”变为“戒指借给用户”，旧版本保留在原位置，新版本在变化后追加。再次变回原值也需要新的更新。不同来源中的相同文字不能合并为一个块，本轮额外要求只作用于所属回合。

深度注入、脚本显式排序或历史覆盖遵守编排结果。移动配方块、改变深度、固定前缀或可见窗口时建立新基线，不能带入过期动态副本。预览、Writer 请求和窗口判断使用同一记录层，按实际请求内容匹配接口快照，不推算未计量增量。

普通对话的策略指纹不含 Kemini 字段；Kemini 实验对话的提示文本变化时建立新基线。Writer 与 Full Agent 的资料策略指纹也不包含思考强度及其请求字段格式：只调整生成控制时保留已发送记录、原生回复与窗口 epoch，实际缓存复用由服务商决定。系统规则、工具、资料、模型身份及真实窗口变化仍按各自条件失效。Tracker 保持每个维护任务的独立上下文，任务内工具续答追加；参谋 agent 沿用不包含思考控制的咨询身份比较。

## 容量与窗口规划

窗口同时检查剧情条数和有效的上次接口实测输入，并按完整交流边界退出旧历史。默认值和可调范围集中在[窗口设置](../guides/history-maintenance-settings.md#窗口设置)。日常预算与模型可用输入容量取较小值，一次实测压力只触发一个退出批次，之后等待新实测；消息 cap 可独立继续退出；最近两次完整交流及当前输入受保护。

五条世界书加一组用户／assistant 交流只计两条剧情。条目与锚定交流一起退出，退出后才开始冷却。原文留在存档，退出请求不会删除消息。

已选文本不因估算超量被缩短。固定资料与受保护内容仍过大时，提示后完整发送，服务商可能拒绝；规则见[文本完整性](text-integrity.md)。

## 覆盖水位与提交

| 快照字段 | 表达的状态 |
|---|---|
| `memory_archive` | 已完成记忆整理的剧情来源范围 |
| `context_window` | 已退出 Writer 请求的剧情来源范围 |
| `memory_document` | 当前分类记忆及其来源 |

两个水位不能互相替代。周期整理可能先于退出发生，裁剪前仍必须检查真实来源覆盖；不能仅凭已过去若干轮推断可以丢出原文。

Tracker 使用独立上下文和来源短编号，不消费 Writer 配方或创作提示。后置任务可处理待提交正文，最终脚本和正文变换结束后才绑定来源指纹。来源不支持记录时不提交相关必要结果。协议、失败处理和手工保护见[记忆设计](memory-consistency.md)。

用户消息保存任何本轮脚本、Tracker 或模型处理之前的快照。普通发送、未改输入的重生成和修改输入后的重试共用回合起点解析；重试恢复同一起点并按相同轮号重算窗口与周期任务，不因尝试次数累计推进。预览和手动整理不推进剧情窗口；取消、失败或拒绝审核不会提前提交窗口、记忆和世界书状态。

## 官方渠道的云端 compact

新会话默认本地滚动窗口。官方渠道可在“场景 → 上下文方式”选择云端 compact，此时消息 cap、批量移除和压力裁剪全部停用；Tracker 的周期记忆、变量与设定维护仍独立运行。

每次用户发起发送或重生成，在前置维护、检索和 Writer 编译完成后检查一次。上次有效实测输入严格超过 Writer 的 `context_tokens`、上次请求被服务端明确以上下文超限拒绝且内容前缀未变，或已有压缩状态失效，且自动压缩开启时，先整理已完成交流，再发送当前输入；不在 Writer 正文、Tracker 工具续答或脚本嵌套请求中安装服务端自动阈值。无可压缩历史时仍完整发送，超长单个交流不拆开。必要压缩失败或未返回有效加密状态时停止正文，关闭自动压缩则只提示超量。

`half_context.compaction` 记录 Writer 的压缩状态，不冒充 `memory_archive` 或 `context_window`。完整来源用于校验和重建，实际请求使用有效前缀、压缩状态与未覆盖尾部。压缩后首次生成会重新追加当前动态内容及必要撤销，后续仍按变化追加；账号连接、模型、配方、适配器或已覆盖来源变化使旧状态失效。预览只展示重建需要，不发维护请求；自动压缩开启时，失效状态在下次发送前重新整理全部已完成交流，优先一次处理，仅明确超限时按完整交流二分；关闭时回退到完整有效原文。当前未完成交流完整保留。

普通尾部记忆、变量等动态块沿用追加更新与明确撤销；固定角色资料、常驻世界书按宏展开后的实际文本校验。变量未被固定资料引用，或展开结果未变，不因变量变化本身重建；自定义配方把动态内容放入固定前缀时，实际前缀变化仍会使旧状态失效。

被压缩的中途世界书退出活跃注入并开始冷却，冷却后再次相关可注入当时的完整条目。冻结原文保存在所属交流的 trace 和历史快照中，重建不会丢失它们；手工移除标记优先于旧副本，删除或禁用的资料不会复活。旧存档按已有剧情、快照及动态记录建立基线，未持久保存的历史临时提示无法还原，预览会说明。

切到云端时从当前分支完整可回放来源建立基线，无有效实测证明超量时不增加模型请求。显式“立即压缩”仍可执行；以完整交流为候选，仅服务端明确超限时二分，单次交流仍超限则停止。切回本地时从原文重新规划滚动窗口，必要时由 Tracker 分批补齐退出范围的记忆，保留手工条目与删除保护；不生成 handoff。关闭本地窗口时恢复全部原文。显式切回本地会在完成时提交目标窗口，其余预览和手动记忆整理仍不推进窗口。

手动切换与立即压缩支持进度、取消及恢复，并与生成和待审核回合互斥。自动压缩仅修改回合草稿，随正文及 Tracker 结果原子提交；重生成从原用户快照开始。分支及导入重映射来源后建立自己的基线，不携带分叉点之后的状态。检查点、交流 trace 和剧情快照不属于可清理日志。

## 模型视图与预览

状态块仅包含实际剧情值。初始化账本、MVU schema、重复 display/delta 缓存和内部元数据不进入业务输入；宏、变量分析和记忆辅助资料采用相同投影，存档和执行校验使用完整数据。详见[数据边界](model-data-boundary.md)。

会话设置中的“导出请求（调试）”按当前分支与输入只读编译消息数组（含适用的后置要求和动态块）并导出为 JSON，供调试使用，与面向他人的“分享对话”不同。预览不执行神经召回，因此实际发送的世界书命中可能不同。源身份和指纹保留在编译 trace 中，检索线索不作为剧情或 MVU 数据。
