# Half Agent 上下文生命周期

本文说明 Writer 的上下文编排、本地滚动窗口、云端 compact 和记忆覆盖。Full Agent 使用[独立工作窗口](full-agent.md#工作窗口与追加记录)。两种模式共享压缩协议与操作服务，但分别规划来源及切回本地的行为。

## 编排与资料标签

上下文配方控制文本块的顺序、角色、深度、预算提示阈值和条件。新会话复制全局配方，已有会话及分支独立保存。深度留空按列表顺序，0 放在末尾，正整数从最后一条剧情消息向前定位。

运行时补充检索协议、当前对话偏好和常驻世界书，默认跟在应用系统提示词之后。角色字段分别使用 `<card_system_prompt>`、`<card_description>`、`<card_personality>`、`<card_scenario>`、`<card_mes_example>` 和 `<card_post_history_instructions>` 包裹。世界书统一使用 `<lorebook>`，记忆投影使用 `<tavern_memory>`，剧情状态使用 `<tavern_state>`，作者注使用 `<author_note>`。作者注、角色后置要求和状态的动态更新说明与撤销消息也包在各自标签内。

应用系统提示词本身不加资料标签，开场白及备选开场作为普通剧情。新配方将角色系统提示、描述、性格和场景拆成独立块；仍使用合并块的配方可在编辑器拆分，保留角色、深度及条件。

默认编排让历史正文、本次输入锚定的世界书和当前输入连续出现，之后追加后置要求、作者注、记忆及状态。滚动世界书始终贴近对应锚点，其位置不随再次命中改变。

下面只展示剧情与一个本次输入锚点，不包含固定系统规则和配方的其他部分：

```json
[
  {"role":"user","content":"我来到港口。"},
  {"role":"assistant","content":"钟声从防波堤另一侧传来。"},
  {"role":"system","content":"<lorebook>港口钟塔每天黄昏鸣钟。</lorebook>"},
  {"role":"user","content":"我向钟塔走去。"}
]
```

这份片段有四条协议消息，其中三条是剧情。世界书影响 token 占用，不增加历史剧情条数。

## 动态上下文记录

配方决定准入和位置，追加记录层保持已发送动态内容的顺序。普通尾部的作者注、角色后置要求、分类记忆和状态按来源、角色及宏展开后的内容跟踪：首次注入，变化时追加新版本，内容退出编译结果时追加撤销。剧情状态块关闭或条件不满足时只追加一次撤销；重新开启时追加当前值，即使它与撤销前相同。块保持启用而状态清空为空对象时，完整发送空状态更新以取代旧值。

例如，状态从“戒指由艾琳保管”变为“戒指借给用户”，旧版本保留在原位置，新版本在变化后追加。再次变回原值也需要新的更新。不同来源中的相同文字不能合并为一个块，本轮额外要求只作用于所属回合。

深度注入、脚本显式排序或历史覆盖遵守编排结果。移动配方块、改变深度、固定前缀或可见窗口时建立新基线，不能带入过期动态副本。预览、Writer 请求和窗口预算使用同一记录层，估算包含实际回放的动态内容与原生块。

## 容量与窗口规划

窗口同时检查剧情条数和本地 token 占用，并按完整交流边界退出旧历史。默认值和可调范围集中在[窗口设置](../guides/history-maintenance-settings.md#窗口设置)。日常预算与模型可用输入容量取较小值，压力触发后裁剪到目标；最近两次完整交流及当前输入受保护。

五条世界书加一组用户／assistant 交流只计两条剧情。条目与锚定交流一起退出，退出后才开始冷却。原文留在存档，退出请求不会删除消息。

已选文本不因估算超量被缩短。固定资料与受保护内容仍过大时，提示后完整发送，服务商可能拒绝；规则见[文本完整性](text-integrity.md)。

## 覆盖水位与提交

| 快照字段 | 表达的状态 |
|---|---|
| `memory_archive` | 已完成记忆整理的剧情来源范围 |
| `context_window` | 已退出 Writer 请求的剧情来源范围 |
| `memory_document` | 当前分类记忆及其来源 |

两个水位不能互相替代。周期整理可能先于退出发生，裁剪前仍必须检查真实来源覆盖；不能仅凭已过去若干轮推断可以丢出原文。

Tracker 使用独立上下文和来源短编号，不消费 Writer 配方或创作提示。后置任务可处理待提交正文，最终脚本和正文变换结束后才绑定来源指纹。来源不支持记录时不提交相关必要结果。协议、失败处理和手工保护见[记忆设计](memory-consistency.md)。

普通发送可以推进窗口；重生成复用目标用户输入的历史快照，预览和手动整理不推进窗口。取消、失败或拒绝审核不会提前提交窗口、记忆和世界书状态。

## 官方渠道的云端 compact

新会话默认本地滚动窗口。官方渠道可在“场景 → 上下文方式”选择云端 compact，此时消息 cap、批量移除和压力裁剪全部停用；Tracker 的周期记忆、变量与设定维护仍独立运行。

每次用户发起发送或重生成，在前置维护、检索和 Writer 编译完成后检查一次。可见输入估算严格超过 Writer 的 `context_tokens` 且自动压缩开启时，先整理已完成交流，再发送当前输入；不在 Writer 正文、Tracker 工具续答或脚本嵌套请求中安装服务端自动阈值。无可压缩历史时仍完整发送，超长单个交流不拆开。必要压缩失败或未返回有效加密状态时停止正文，关闭自动压缩则只提示超量。

`half_context.compaction` 记录 Writer 的压缩状态，不冒充 `memory_archive` 或 `context_window`。完整来源用于校验和重建，实际请求使用有效前缀、压缩状态与未覆盖尾部。压缩后首次生成会重新追加当前动态内容及必要撤销，后续仍按变化追加；账号连接、模型、配方、适配器或已覆盖来源变化使旧状态失效。预览只展示重建需要，不发维护请求；自动压缩关闭时失效状态回退到完整有效原文。

被压缩的中途世界书退出活跃注入并开始冷却，冷却后再次相关可注入当时的完整条目。冻结原文保存在所属交流的 trace 和历史快照中，重建不会丢失它们；手工移除标记优先于旧副本，删除或禁用的资料不会复活。旧存档按已有剧情、快照及动态记录建立基线，未持久保存的历史临时提示无法还原，预览会说明。

切到云端时从当前分支完整可回放来源建立基线，短历史无需模型请求。切回本地时从原文重新规划滚动窗口，必要时由 Tracker 分批补齐退出范围的记忆，保留手工条目与删除保护；不生成 handoff。关闭本地窗口时恢复全部原文。显式切回本地会在完成时提交目标窗口，其余预览和手动记忆整理仍不推进窗口。

手动切换与立即压缩支持进度、取消及恢复，并与生成和待审核回合互斥。自动压缩仅修改回合草稿，随正文及 Tracker 结果原子提交；重生成从原用户快照开始。分支及导入重映射来源后建立自己的基线，不携带分叉点之后的状态。检查点、交流 trace 和剧情快照不属于可清理日志。

## 模型视图与预览

状态块仅包含实际剧情值。初始化账本、MVU schema、重复 display/delta 缓存和内部元数据不进入业务输入；宏、变量分析和记忆辅助资料采用相同投影，存档和执行校验使用完整数据。详见[数据边界](model-data-boundary.md)。

“预览下次 messages”按当前分支与输入只读编译消息数组，包含适用的后置要求和动态块。预览不执行神经召回，因此实际发送的世界书命中可能不同。源身份和指纹保留在编译 trace 中，检索线索不作为剧情或 MVU 数据。
