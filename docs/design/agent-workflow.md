# Writer、Tracker 与 Roleplay Runtime 工作流

前台 Writer 生成正文，后台 Tracker 整理记忆及执行授权维护，Roleplay Runtime 负责程序编排。正式职责和代码映射见[架构](architecture.md#正式角色与职责)。三者通过 Runtime 管理的回合草稿交换数据；Writer 与 Tracker 不互相自由对话或委派工作。SQLite 是剧情与状态的权威来源。

## 普通发送

以下步骤均由 Roleplay Runtime 驱动；后台表示模型职责，不承诺异步并行。

1. 校验模型配置、operation_id 和会话 revision；一个会话只允许一个运行或待审核回合。
2. 恢复分支快照，建立隔离脚本环境，执行输入变换。
3. 检索器完成候选准入，窗口规划按剧情与中途世界书的共同占用计算退出范围。
4. 周期到达或退出范围尚未被覆盖时调度 Tracker 整理记忆，只归档真实剧情，不把世界书当成已发生事实。
5. 授权修改设定时调度 Tracker 的独立维护 Creature，最多四次调用。修改后重新检索并复核记忆覆盖。
6. 为 Writer 编译上下文；Writer 执行一次无工具正文调用。最终 HTTP 请求再次检查消息、工具及输出预算。
7. 隔离检索线索。输入框“本轮更新变量”默认关闭；开启后，独立后台调用使用后台模型配置、当前变量、最近 6 条分支历史消息以及本轮输入和正文，生成 JSON Patch，经 MVU 与同步/异步回调更新草稿快照。Writer 正文不再作为变量指令解析，后台结果不写入正文。分析或应用失败保留草稿，整轮不提交；重生成从原轮之前的快照重新分析。重试使用输入框当前勾选状态。

变量更新使用相对于 stat_data 的 JSON Patch 数组。全部启用 tracker_mvu 规则仅在更新时注入；runtime_init 条目仅供初始化，二者均不进入 Writer，包括旧冻结记录。适配 skill 默认保留原卡开场及其 MVU/正则行为，仅在用户明确要求时迁移开场；独立 Card Editor 流程见[角色卡编辑指南](../guides/card-editor.md)。
8. 自动提交或保存待审核包。消息、快照、head、revision 和提交事件在同一事务生效。

## 操作边界

| 操作 | 起点与结果 |
|---|---|
| 重复 operation_id | 相同请求返回原回合，不再次执行；不同内容冲突 |
| 失败/取消后重试 | 新操作 ID，仍校验会话版本 |
| 重生成 | 复用原用户节点与生成前快照，不推进窗口，不新增用户台词 |
| 分支继承 | 复制所选 assistant 的祖先前缀，重映射消息、记忆来源、世界书锚点与窗口指纹 |
| 编辑原文 | 修改当前分支可见消息，失效相关线索、记忆和窗口；不自动重演后续剧情或变量 |
| 手动记忆整理 | 独立回合，只替换当前快照记忆，不生成正文，不推进窗口 |
| 卡片交互 | 独立事务，只操作当前进度，受设定权限和审核策略约束 |
| 取消/异常/拒绝审核 | 保留草稿，不提交剧情状态 |
| 断线/重新打开 | 服务端继续执行，SSE 按序号观察；前端去重并隔离旧视图响应 |
| 服务重启 | 未完成回合标记 interrupted，保留草稿 |

周期记忆失败且无需裁剪时继续正文，页面持续提示；必须裁剪而覆盖不足时停止发送。
工作记录按回合分页，徽标统计当前对话的回合总数，完整载荷按需加载。
过期详细载荷转为紧凑摘要，剧情、分支及恢复所需快照不被删除。

## 请求身份与原生回复

Half Agent 的前台请求使用剧情会话 UUID；记忆整理、记忆复核、设定维护、变量分析及脚本生成按会话与用途派生稳定 UUID。设备标识保存在应用数据库，不依赖缓存开关。每次维护批次拥有独立操作上下文，工具续答复用该操作的 Responses 路由状态；新操作、重生成或提供商身份变化清除路由状态。失败重试仍按原有新操作执行，不新增后台任务恢复协议。

Anthropic `content` 与 Responses `output` 保留原始块顺序、工具 ID、思考签名和加密推理。流式响应完整结束后才成为可持久回放附件。后台原生响应进入工作记录，工具循环回放对应块，后台过程不进入剧情历史。

前台原生附件和动态上下文记录保存在独立 `half_agent_trace`，与剧情消息原子提交，随分支、备份和删除管理，不复制进各轮快照，也不受普通日志清理影响。检索线索继续从正文中剥离，仅可随有效原生附件回给兼容模型；界面正文、MVU、脚本和后台记忆使用清理后的文本。模型用正则、脚本、宏展开或用户编辑改变正文时改用当前有效文本；仅显示变化不影响回放。切换来源后，旧模型附件不因切回模型而自动复活。

## 兼容优先的追加上下文

原编排器仍控制准入和位置。普通尾部的作者注、角色后置要求、分类记忆及剧情状态按来源、角色和实际展开后的内容跟踪：首次注入，变化时追加替代版本，清空或关闭时追加撤销。本轮额外要求按回合限定；不同来源的相同文字不会合并，`A → B → A` 会再次表达 A。

已发送的动态版本留在原剧情位置，普通新轮次只追加新内容。深度注入、显式脚本排序／注入及历史覆盖保持原编排结果；旧前缀或可见窗口改变时建立新基线，不带入过期动态副本。默认变量的 depth=0 属于普通尾部快照。授权维护的工具循环也保留已发送前缀，在工具结果后追加变化；固定资料变化时重建。

预览、Writer 请求和窗口预算使用同一记录层，预算包含实际回放的动态消息与原生块。诊断记录重建原因、撤销及原生失效；缓存断点仍绑定原剧情节点，不随工具结果移动。旧存档首次建立基线，不补造丢失的原生响应。真实中转的缓存命中仍以服务商日志为准。

## 开发入口

- service.py / RoleplayRuntime：编排、恢复、取消、审核、脚本回调和提交。
- retrieval.py / lore_admission.py：证据、准入、递归和降级。
- window.py：Runtime 的窗口规划；memory.py / Tracker：记忆整理入口与覆盖协调；scene.py：Tracker 记忆生成及来源校验。
- context.py：纯组装和最终注入记录，不做新的递归扩展。
- agent.py / Writer：零工具正文入口；TurnAgent：Writer 与 Tracker 维护模式的共享 Terrarium 适配、工具权限和最终 HTTP 预算。
- store.py：事务与分支；turnStream.ts：事件去重和视图归属。

改动工作流时优先测试失败、重试、分支和回调顺序；模块划分可以随功能演进。
