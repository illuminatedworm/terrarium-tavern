# Half Agent 回合工作流

Half Agent 的回合由 Runtime 统一编排；Full Agent 的执行与续接见[独立回合生命周期](full-agent.md#回合生命周期)。前台 Writer 生成正文，后台 Tracker 整理记忆及执行授权维护，Roleplay Runtime 负责程序编排。正式职责和代码映射见[架构](architecture.md#正式角色与职责)。Writer 与 Tracker 通过 Runtime 管理的回合草稿交换数据。SQLite 是剧情与状态的权威来源。

## 普通发送

以下步骤均由 Roleplay Runtime 驱动；Tracker 与 Writer 按阶段执行，“后台”表示维护职责。

1. 校验模型配置、operation_id 和会话 revision；一个会话只允许一个运行或待审核回合。
2. 恢复分支快照，建立隔离脚本环境，执行输入变换。
3. 检索器完成候选准入，窗口规划按剧情与中途世界书的共同占用计算退出范围。
4. 裁剪前覆盖不足时先调度 Tracker；勾选“本轮允许修改设定”时，在同一前置任务中处理明确修改。修改后重新检索和规划窗口。修改保存方式不授予设定修改权限。
5. Writer 使用前置处理后的资料执行一次正文调用，不执行业务工具；Kemini 实验对话先解包正文合成函数并分离显式辅助段，然后剥离检索线索。
6. 正文后检查记忆周期；到期、勾选更新变量或本轮授权维护被触发时，运行统一 Tracker 工具任务。文本记忆仅在周期、裁剪补整理、手动重建时开放；变量任务只在本轮勾选后开放。角色卡与世界书写入只在本轮授权后开放，可保存稳定变化和长期经历。
7. `patch_state` 暂存相对于 stat_data 的 JSON Patch，无变化也提交空数组；一次成功提交后不重复接受。最终仅一次 MVU 处理及消息回调链应用补丁，Writer 正文不作为变量命令解析。同步 Tracker 世界书修改，并逐字段合并脚本修改，保留原条目容器及未知字段。
8. 回调与最终正文变换后绑定本轮记忆来源，校验覆盖，原子提交，或按“审核后保存”策略等待用户接受整轮草稿。必要任务失败整轮不提交；纯周期后台失败丢弃整个后台任务的修改，保留旧记忆、覆盖和失败提示，正文仍可保存。

Tracker 使用专属上下文和 `tracker_system_prompt`，不复用 Writer 的系统提示、配方、写作偏好或故事正文输出约束。角色资料与剧情是数据，工具说明规定操作协议。本轮变量任务才注入全部启用的 tracker_mvu 规则，以及关闭但标题含 `[InitVar]` 的 tracker_mvu 条目；其规则在任务开始时固定，后置修改从后续任务起生效。

Tracker 的 `patch_state` 和 `revise_content` 参数为 `operations` 与 `comment`。`comment` 是必填的简短操作备注，1–2000 字符；旧调用记录保留原字段。

每个前置/后置任务最多 `tracker_max_steps` 次模型请求，默认 8、范围 2–100；分批、工具续答、复核共用额度。自动记忆最多两批和一次可选复核。手动重建按批使用调用额度并建立新的批次上下文，携带已整理记忆而不累积全部旧工具交换；历史补查仍整次操作共用3次。工具结果先进入草稿，MVU 修改经最终校验后随正文提交。

## 操作边界

| 操作 | 起点与结果 |
|---|---|
| 重复 operation_id | 相同请求返回原回合；同一编号对应不同内容时报冲突 |
| 失败/取消后重试 | 新操作 ID，仍校验会话版本 |
| 重生成 | 未改输入时复用原用户节点；从任何本轮处理前的快照重算同一轮，不按尝试次数累计推进窗口或轮数 |
| 分支继承 | 复制所选 assistant 的祖先前缀，重映射消息、记忆来源、世界书锚点与窗口指纹 |
| 修改输入 | 只允许最新用户输入，确认即发起重试。已提交输入创建整轮新版本，失败输入创建新请求；重跑本轮维护、正文及获准变量更新，成功后原子切换，旧版本保留 |
| 手动记忆整理 | 独立回合，只替换当前快照记忆，不生成正文，不推进窗口 |
| 卡片交互 | 独立事务，只操作当前进度，受设定权限和审核策略约束 |
| 取消/异常/拒绝审核 | 保留草稿，不提交剧情状态 |
| 断线/重新打开 | 服务端继续执行，SSE 按序号观察；前端去重并隔离旧视图响应 |
| 服务重启 | 未完成回合标记 interrupted，保留草稿 |

消息修改只使用 `POST /api/sessions/{sid}/turns`：已提交输入使用 `mode="regenerate"`、最新回复的 `message_id` 和 `replacement_text`；失败发言使用新的 `send` 请求，失败的输入替换使用新的 `regenerate` 请求。原消息 PUT 接口与失败输入 PUT 接口均已移除。输入变更时不传 `resume_turn_id`；服务端仍校验操作幂等、会话版本、最新轮次和运行／审核互斥。

周期记忆失败且无需裁剪时继续正文，页面持续提示；必须裁剪而覆盖不足时停止发送。
工作记录按回合分页，徽标统计当前对话的回合总数，完整载荷按需加载。
过期详细载荷转为紧凑摘要，剧情、分支及恢复所需快照不被删除。

## 请求身份与原生回复

Half Agent 的前台、Tracker 各阶段与脚本生成使用各自请求身份，规则见[模型接入参考](../reference/model-api.md#请求身份)。一个 Tracker 任务内的分批、复核和工具续答共享操作路由状态；失败重试创建新操作，不续接已失败的 Tracker 工具进度。

Anthropic `content` 与 Responses `output` 保留原始块顺序、工具 ID、思考签名和加密推理。流式响应完整结束后才成为可持久回放附件。后台原生响应进入工作记录，工具循环回放对应块；新批次和复核资料附加在尚未发送的 write_memory 结果中，已发送前缀不重写，后台过程不进入剧情历史。

前台原生附件和动态上下文记录保存在独立 `half_agent_trace`，与剧情消息原子提交，随分支、备份和删除管理，不复制进各轮快照，也不受普通日志清理影响。检索线索继续从正文中剥离，仅可随有效原生附件回给兼容模型；界面正文、MVU、脚本和后台记忆使用清理后的文本。正则、脚本或宏展开改变模型可见正文时，改用当前有效文本；仅显示变化不影响回放。切换来源后，旧模型附件不因切回模型而自动复活。

## 动态上下文与回放

配方和显式脚本操作决定注入位置，追加记录层保持已发送动态内容的顺序。作者注、记忆和状态变化时追加新版本，清空时追加撤销；固定资料或窗口改变时重建基线。完整规则与编排示例见[上下文生命周期](context-lifecycle.md#动态上下文记录)。

预览、Writer 请求和窗口预算使用同一记录层，计入原生块与动态消息。诊断记录基线重建和附件失效原因，缓存断点始终绑定剧情节点，不跟随工具结果移动。缺少原生记录的存档从当前通用历史建立基线。
