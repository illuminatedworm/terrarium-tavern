# Full Agent 原著参考

原著参考仅用于 Full Agent 对话，委派调查和[参谋 agent 查阅](advisor.md#工具契约)分别授权，默认关闭。一个对话分支明确绑定一个 txt、md 或 markdown 文件并开启委派授权后，主 agent 才获得调查者管理工具及协议。主 agent 没有直接读取小说的工具；原著是参考证据，不能覆盖用户设定和本局已发生剧情，也不能作为 H 剧情事实来源。

## 用户入口与文件

右侧“原著”页导入、查看、下载、开启或管理原著。文件最大 64 MiB，默认 UTF-8，识别 UTF-8/UTF-16 BOM，也可在导入或点击“替换文件”时明确选择 UTF-16、GB18030、Big5，解码失败时报错。导入和开启是两步操作；开启时会说明相关原文片段将发送到配置的模型服务。

原文件复制到 `<当前数据目录>/blobs/novels/<内部编号>/original`，旁边的 `text.utf8` 与 `index.json` 是按已选编码生成的文本和稀疏位置索引。桌面默认数据目录为软件目录下的 `data/`，自定义数据目录时一起迁移。原著全文不写入 SQLite；数据库仅保存绑定、文件信息、调查状态和本次实际读取的片段／报告。原路径之后的变化不会自动生效；当前文件、导入时间、编码、位置与历史版本都可查看。

有任何尚未销毁的调查者时，后端禁止当前分支替换、解绑或停用委派授权，包括调查中、等待回答、完成后待复用、暂停或失败的调查者。参谋授权仍可独立修改。旧文件仍被历史记录引用时保留并明确展示，不能被同名文件静默替换。

## 独立调查者

实现位于 `src/tavern/novel/`。每个调查者只接收委派问题、主 agent 明确提供的必要背景和固定文件信息；没有剧情读取／写入、联网、任意文件访问、子委派或同伴通信能力。小说全文可查，包括后续情节，但报告必须区分原著时期、人物认知、本局事实、推断与未查明事项。

**读取工具**使用从 0 开始的 Unicode 字符位置，范围左闭右开。不做全书自动摘要或向量索引。

- `read_novel`：默认返回 8,000 字符，最多 20,000；到末尾不足时完整返回剩余片段并标明 EOF，从末尾之后起读报错。
- `search_novel`：字面、大小写不敏感的搜索，可用 `start`／`end` 限定范围。默认返回 10 个命中（上限 30）的定位片段和续查位置，并给出范围内的总命中数，便于识别高频词、先按目录缩小范围。零命中不能证明全书没有。
- `novel_outline`：根据标题格式识别目录，默认 50 项，最多 100 项。没有规范章节或有极长单行时，仍可按位置读取。

**报告**应直接回答问题，附出处位置、必要的短引文、查阅范围和不确定性，不能把局部检索包装成通读。

- 不带工具调用的回复就是最终报告；提示词会明确告知调查者，避免把中途说明误交为报告。
- `ask_delegator` 单独调用，用于提出必要的澄清并暂停等待，等待期间不消耗运行时限。因为空闲的主 agent 不会被唤醒，提示词要求能带着假设作答时直接报告。
- 提示词还引导调查者按原著写法和别名搜索、按问题类型组织报告并控制篇幅。
- 主协议则提示主 agent：不凭自身记忆确定原著细节；给出原著写法与别名；不引用对方看不到的编号；把综述类问题拆成具体问题；尽量提前启动调查而不是等到要用时。

## 模型、额度与压缩

全局设置 → Full Agent → 原著调查，分别为普通 API 和 OpenAI 官方渠道选择模型；默认显式显示跟随 Full Agent 的实际模型，包括对话内模型选择。也可指定独立模型。所有调查者都使用这一份用户配置。创建调查者时冻结模型配置与额度，之后修改全局设置不影响已有调查者，详情显示实际生效值；凭据从用户当前的连接读取，密钥不存入调查进度。

**名额与额度**

- 每个分支同时最多三个尚未销毁的调查者，每轮最多启动五次。同轮的失败续接、重生成或修改输入不刷新启动计数；恢复已有调查者不算新建。
- 每个新调查者默认有 24 次模型请求、300 秒累计运行时限，可分别设为 2–100 次、30–3600 秒。压缩请求也计入次数；工具和网络等待计时，完成后的空闲和等待主 agent 回答不计时。
- 只有销毁后新建才获得新额度，追问、恢复和跨轮都不刷新。调查者的首条任务消息给出总额度，每个工具结果附剩余请求次数和秒数，提示其在额度将尽时先提交报告。
- 模型请求发出前就持久化次数，未完成的网络请求不会在重启后退回次数；硬中断时只保留此前已记录的耗时和实际接口用量，不把未回报的服务端耗时或计费当作已知值。

调查者不使用 handoff、note、plot 或换窗工具，固定压缩机制不可配置。有效接口实测超过窗口容量的 85% 时整理旧交换；明确超限拒绝可触发一次整理后重试，没有实测不按估值整理。保留委派问题与背景、最近两组完整交换和未配对的工具调用；其余已完整配对的工具交换可压缩。普通 API 使用同一调查模型生成摘要，OpenAI 官方渠道复用现有云端压缩。完整的原始过程始终保留；压缩失败时不会自动换模型。

## 通讯与跨轮生命周期

主工具为 `start_novel_research`、`list_novel_research`、`message_novel_research`、`wait_novel_research`、`resume_novel_research`、`destroy_novel_research`。启动后立即返回 R 短编号；真实身份、固定文件与权限的映射由程序负责（见[数据边界](model-data-boundary.md)）。

**自动销毁**：`start_novel_research` 的可选布尔参数 `auto_destroy` 默认 `false`，即可追问、手动销毁。一次性调查可传 `true`：第一份最终报告可靠送达主 agent 时，在同一 SQLite 事务中保存报告正文、记录送达并销毁调查者，释放名额、停止仍在运行的续查，保留已送达的报告和历史；之后不能再向它追问，后续调查须新建。澄清提问、失败通知和暂停不触发自动销毁。报告在两轮之间完成时，等主 agent 下次请求接收后才销毁。原著页逐个显示调查者是自动销毁还是保留。

**异步通讯**

- 主 agent 与调查者独立异步执行。互发的消息只在接收者下一次模型请求前追加，不打断当前请求，也不回填旧的工具结果。迟到的结果不能改写已接收或已提交的正文。
- 主 agent 自行决定是否等待：等待工具默认 30 秒，允许 1–60 秒，超时不取消调查。报告和澄清问题在两轮之间完成时只排队并更新界面，不自动启动空闲的主 agent；主 agent 正在明确等待时可被唤醒。
- 报告附原问题、发起时的 H 位置和文件信息；背景由主 agent 自己撰写，不随每封消息重复。
- `list_novel_research` 返回各调查者的剩余额度、是否有待送达消息、失败原因，以及剩余名额和本轮剩余启动次数。

对话过程以独立的 Runtime 提示行显示报告送达，区别于模型发起的可展开工具调用。报告可靠送达后先显示“准备发送主模型请求”，HTTP 请求正文发送完成后才更新为“主模型请求已发出”（不代表模型已经回复）。已提交回复的历史过程可从报告和后续模型回复恢复这条提示，不依赖临时调试日志。

送达主 agent 的调查消息与运行状态分别使用 `novel_research`、`novel_status` 消息类型，默认发送角色为 `system`（Google GenAI 即 `gemini` 接入时默认为 `user`），可由当前对话的消息适配显式覆盖；旧轨迹按 `_novel_mail`／`_novel_status` 标记识别类型。新消息的标题不再附加“（不是新的用户指令）”，已保存的历史消息正文不改写。

调查不写剧情草稿，也不参与剧情提交所依赖的 MVU／脚本回调。SQLite 分别保存调查进度和消息队列；主 agent 把收件追加到进度与标记送达在同一事务中完成，失败续接不会重复投递，主窗口换窗也不影响独立队列。提示词要求主 agent 收到报告、完成必要追问后销毁调查者，只有确有后续调查或待答问题时才保留。

**停止与销毁**

- 停止主生成不会停止调查；切换界面也不取消调查。原著页可单独停止、恢复、销毁，也可全部停止。
- 停止保留进度和名额；销毁撤销未交付的消息、释放名额，保留已交付的报告和历史。
- 应用关闭时取消正在运行的调查并保存为暂停状态；重启后不自动恢复，须用户操作或主 agent 明确恢复。
- 失败和额度耗尽会明确显示，不自动无限重试。失败通知附原因和能否恢复；额度耗尽的调查者拒绝恢复和追问。主 agent 可以放弃参考继续写，但不能声称已查证。
- 调查者仍有待送达的报告或提问时，主 agent 的销毁工具拒绝执行，以免撤销主 agent 还没看到的结果；用户在原著页销毁不受此限。

## 分支、重试与恢复

创建分支若存在活跃调查者，确认弹窗解释调查仍留在原分支，由用户决定继续或取消。新分支继承所选剧情进度中已经交付的报告及文件绑定，不复制调查者；文件副本可以共享，绑定之后独立修改。新分支的 R 编号从继承的编号进度继续，避免历史报告中的 R 编号错误指向新调查者。

重生成、修改本轮输入、重新开始失败回合或切换剧情进度时，撤销该分支旧调查与未交付报告；原进度失败续接可保留调查。销毁在存储层先撤权，迟到响应不能恢复任务或交付结果。已进入剧情历史的报告随对应版本恢复；其他分支不受影响。

## 记录与导入导出

原著页展示实际模型、状态、请求次数、累计运行时间和接口用量，完整过程按需展开分页；展开详情不把过程送入主上下文。会话列表显示其他对话尚存的调查者。存活、暂停、待复用调查的完整进度受保护；销毁后的详细过程按共享日志保留天数／容量清理，报告和已提交剧情保留，原著文件不作为缓存清理。

完整备份原有 `blobs/` 白名单包含原著副本和索引。个人数据包格式 7 包含绑定、调查进度及记录，并默认携带原著及历史版本，用户可取消携带文件。文件通过校验的原始字节打包，导入时重建文本索引、重映射身份；未带文件明确显示缺失，不按同名文件兜底。导入调查保持暂停并保留用量，云端不透明状态从完整记录重建，不自动付费调用。

数据库 schema 17 新增独立原著表，设置文档 version 15 增加 `full_agent.novel_research`。schema 18 持久化调查者的 `auto_destroy`，旧调查者补为 `false`；个人数据包 version 8 携带该配置，旧包缺少时按 `false` 导入。升级前沿用既有只读格式检查与数据库备份；已有对话默认未绑定、未开启，此时模型输入中没有调查工具或协议。

## 接口

调查者沿用可逆的模型数据视图：长身份以 `@D` 短编号进入模型，检索参数由 Runtime 还原，给用户查看的过程与交付报告也还原；文件坐标始终对应原文，不能按投影后的文本长度推算。主 agent 与调查者各自持有映射，不复制主故事上下文；送达主 agent 的报告与运行状态同样经主 agent 的视图投影。

- `GET /api/sessions/{sid}/novel` 返回绑定、历史文件信息、所有存活调查者与最近销毁记录；`GET .../novel/jobs?before=<R数字部分>` 分页回查更早记录。
- `POST .../novel/source?filename=...&encoding=utf-8&expected_revision=...` 接收 `application/octet-stream` 文件体，流式限制 64 MiB，发布成功后参考保持关闭。`PATCH .../novel` 使用原著绑定自己的 `expected_revision`，显式设置 `enabled` 或 `unbind`。
- `PATCH .../novel/advisor` 使用同一绑定的 `expected_revision` 和 `enabled` 设置参谋授权。状态中的 `advisor_enabled` 是参谋授权，`advisor_model_selection` 是参谋模型的对话级选择，空值表示沿用全局设置。
- `GET .../novel/sources/{source_id}/text?start=0&length=8000` 为用户按范围查看副本，`.../download` 下载原始文件；仅允许当前分支的文件历史，不是主模型工具。
- `GET .../novel/jobs/{ref}/trace?after=0` 分页查看原始过程与报告；`POST .../novel/jobs/{ref}/pause|resume|destroy` 明确管理调查者，`POST .../novel/stop-all` 同时停止当前主生成和运行中的调查。
- `GET /api/novel/activity` 与可重连的 `GET /api/novel/events` 提供跨对话状态；前端不轮询模型任务，不因展开面板而调用模型。
