# 资料调查

调查者总开关、联网开关和[参谋 agent 查阅参考文件](advisor.md#工具契约)分别设置，默认关闭。启用调查者至少需要一个可用来源。导入参考文件后即可将其用作当前分支的本地来源。仅使用网络时，开启联网并填写调查指引，再开启调查者总开关。同一调查可同时使用已授权的文件和网页。剧情事实以用户设定和本局已发生的情节为准。

## 用户入口与文件

右侧「调查」页管理文件、联网和调查者总开关。文件最大 64 MiB，默认 UTF-8，识别 UTF-8/UTF-16 BOM，也可在导入或替换时选择 UTF-16、GB18030、Big5。调查使用文件时，选中的片段发送给设置的调查模型。联网调用会向实际服务发送查询词、可选检索目标或目标网址。

原文件复制到 `<当前数据目录>/blobs/novels/<内部编号>/original`，旁边的 `text.utf8` 与 `index.json` 是按已选编码生成的文本和稀疏位置索引。桌面默认数据目录为软件目录下的 `data/`，自定义数据目录时一起迁移。参考文件的全文存放在副本中；数据库仅保存绑定、文件信息、调查状态和本次实际读取的片段／报告。原路径之后的变化不会自动生效；当前文件、导入时间、编码、位置与历史版本都可查看。

替换或解绑前，须销毁仍持有当前文件的调查者。纯联网任务期间可在会话可编辑时管理文件。旧文件只要被历史引用就保留并显示。删除最后一个可用来源时，在同次保存中关闭总开关。文件副本临时缺失且没有其他可用来源时，「调查」页显示已保存的授权和来源状态，可关闭总开关撤销授权。

调查指引是分支保存的自由文本，可写主题、作品名、年代、公开网址或偏好的资料源，由调查者理解后选择查法。程序沿用共享联网工具对公共网址及读取范围的校验。已有可读文件时，联网指引可以留空。调查者启动时固定实际的文件、联网授权和指引，新增加的来源或编辑后的指引用于新任务，任务详情可查看固定值。

## 独立调查者

实现位于 `src/tavern/novel/`。每个调查者只接收委派问题、必要背景、可用来源与后续补充。它只能使用获授权的资料读取和询问工具。调查者可按需查阅绑定文件的全文。两种模型渠道的联网调查都使用应用的共享 `web_search` 和 `read_webpage`，见[联网工具协议](../reference/web-tools.md)。调查者以公开线索构造查询，用委派背景判断相关性。网页内容按外部资料处理，正文与服务返回的有界片段完整保存。任务过程记录所用服务及来源链接。

**读取工具**使用从 0 开始的 Unicode 字符位置，范围左闭右开。读取方式包括目录定位、字面搜索和分段阅读。

- `read_novel`：默认返回 8,000 字符，最多 20,000；到末尾不足时完整返回剩余片段并标明 EOF，从末尾之后起读报错。
- `search_novel`：字面、大小写不敏感的搜索，可用 `start`／`end` 限定范围。默认返回 10 个命中（上限 30）的定位片段和续查位置，并给出范围内的总命中数，便于识别高频词、先按目录缩小范围。零命中只说明本次搜索的结果。
- `novel_outline`：根据标题格式识别目录，默认 50 项，最多 100 项。没有规范章节或有极长单行时，仍可按位置读取。

**报告**应直接回答问题，附文件位置或实际查阅的链接、必要的短引文、查阅范围和证据局限。查阅同一作品或文献的正文且未指定版本时，以绑定文本的版本为准。来源冲突、证据不足或只有搜索摘要时，应注明具体情况，并区分资料记载、本局事实和推断。

- 不带工具调用的回复就是最终报告；提示词会明确告知调查者，避免把中途说明误交为报告。
- `ask_delegator` 单独调用，用于提出必要的澄清并暂停等待，等待期间不消耗运行时限。因为空闲的剧情模型不会被唤醒，提示词要求能带着假设作答时直接报告。
- 提示词还引导调查者按来源的写法和别名搜索、按问题类型组织报告并控制篇幅。
- 主协议则提示剧情模型：重要细节应有来源支撑。委派时给出常见写法和别名，把范围过大的综述拆成具体问题，并在预知需求时提前启动调查。

## 模型、额度与压缩

全局设置 → 游玩 → 资料调查，分别为普通 API 和 OpenAI 官方渠道选择模型；默认显式显示跟随 当前对话的模型，包括对话内模型选择。也可指定独立模型。所有调查者都使用这一份用户配置。创建调查者时冻结模型配置与额度，之后修改全局设置不影响已有调查者，详情显示实际生效值；凭据从用户当前的连接读取，密钥不存入调查进度。

**名额与额度**

- 每个分支同时最多三个尚未销毁的调查者，每轮最多启动五次。同轮的失败续接、重生成或修改输入不刷新启动计数；恢复已有调查者不算新建。
- 每个新调查者默认有 30 次模型请求、300 秒累计运行时限，可分别设为 2–100 次、30–3600 秒。压缩请求也计入次数；工具和网络等待计时，完成后的空闲和等待剧情模型回答不计时。
- 只有销毁后新建才获得新额度，追问、恢复和跨轮都不刷新。调查者的首条任务消息给出总额度，每个工具结果附剩余请求次数和秒数，提示其在额度将尽时先提交报告。
- 模型请求发出前就持久化次数，未完成的网络请求不会在重启后退回次数；硬中断时只保留此前已记录的耗时和实际接口用量，不把未回报的服务端耗时或计费当作已知值。

调查者不使用 handoff、note、plot 或换窗工具，固定压缩机制不可配置。有效接口实测超过窗口容量的 85% 时整理旧交换；明确超限拒绝可触发一次整理后重试，没有实测不按估值整理。保留委派问题与背景、最近两组完整交换和未配对的工具调用；其余已完整配对的工具交换可压缩。普通 API 使用同一调查模型生成摘要，OpenAI 官方渠道复用现有云端压缩。完整的原始过程始终保留；压缩失败时不会自动换模型。

## 通讯与跨轮生命周期

主工具为 `start_novel_research`、`list_novel_research`、`message_novel_research`、`wait_novel_research`、`resume_novel_research`、`destroy_novel_research`。启动后立即返回 R 短编号；真实身份、固定文件与权限的映射由程序负责（见[数据边界](model-data-boundary.md)）。

**自动销毁**：`start_novel_research` 的可选布尔参数 `auto_destroy` 默认 `false`，即可追问、手动销毁。一次性调查可传 `true`：第一份最终报告可靠送达剧情模型时，在同一 SQLite 事务中保存报告正文、记录送达并销毁调查者，释放名额、停止仍在运行的续查，保留已送达的报告和历史；之后不能再向它追问，后续调查须新建。澄清提问、失败通知和暂停不触发自动销毁。报告在两轮之间完成时，等剧情模型下次请求接收后才销毁。「调查」页逐个显示调查者是自动销毁还是保留。

**异步通讯**

- 剧情模型与调查者独立异步执行。互发的消息只在接收者下一次模型请求前追加，不打断当前请求，也不回填旧的工具结果。剧情请求按当前授权接收报告，来源权限在同一回合中变化时追加新的运行状态。迟到的结果不能改写已接收或已提交的正文。
- 剧情模型自行决定是否等待：等待工具默认 30 秒，允许 1–60 秒，超时不取消调查。报告和澄清问题在两轮之间完成时只排队并更新界面，不自动启动空闲的剧情模型；剧情模型正在明确等待时可被唤醒。
- 报告附原问题、发起时的 H 位置和任务来源信息；背景由剧情模型撰写，仅在委派时提供。
- `list_novel_research` 返回各调查者的剩余额度、是否有待送达消息、失败原因，以及剩余名额和本轮剩余启动次数。

对话过程以独立的 Runtime 提示行显示报告送达，区别于模型发起的可展开工具调用。报告可靠送达后先显示“准备发送主模型请求”，HTTP 请求正文发送完成后才更新为“主模型请求已发出”（不代表模型已经回复）。已提交回复的历史过程可从报告和后续模型回复恢复这条提示，不依赖临时调试日志。

送达剧情模型的调查消息与运行状态分别使用 `novel_research`、`novel_status` 消息类型，默认发送角色为 `system`（Google GenAI 即 `gemini` 接入时默认为 `user`），可由当前对话的消息适配显式覆盖；旧轨迹按 `_novel_mail`／`_novel_status` 标记识别类型。新消息的标题不再附加“（不是新的用户指令）”，已保存的历史消息正文不改写。

调查不写剧情草稿，也不参与剧情提交所依赖的 MVU／脚本回调。SQLite 分别保存调查进度和消息队列；剧情模型把收件追加到进度与标记送达在同一事务中完成，失败续接不会重复投递，主窗口换窗也不影响独立队列。提示词要求剧情模型收到报告、完成必要追问后销毁调查者，只有确有后续调查或待答问题时才保留。

**停止与销毁**

- 停止剧情生成不会停止调查；切换界面也不取消调查。「调查」页可单独停止、恢复、销毁，也可全部停止。
- 停止保留进度和名额；销毁撤销未交付的消息、释放名额，保留已交付的报告和历史。
- 关闭联网立即暂停持有联网权限的在途调查。关闭调查者总开关立即停用委派、暂停所有在途调查，并暂缓待送达消息。重新开启总开关后待送达消息可随剧情请求送达，后台调查由明确的恢复或追问继续，保留原任务来源与已用额度。固定来源缺失的任务需要先恢复其来源。
- 应用关闭时取消正在运行的调查并保存为暂停状态；重启后不自动恢复，须用户操作或剧情模型明确恢复。
- 失败和额度耗尽会明确显示，不自动无限重试。失败通知附原因和能否恢复；额度耗尽的调查者拒绝恢复和追问。剧情模型可以放弃参考继续写，但不能声称已查证。
- 调查者仍有待送达的报告或提问时，剧情模型的销毁工具拒绝执行，以免撤销剧情模型还没看到的结果；用户在「调查」页销毁不受此限。

## 分支、重试与恢复

创建分支若存在活跃调查者，确认弹窗解释调查仍留在原分支，由用户决定继续或取消。新分支继承所选剧情进度中已经交付的报告和当前资料调查设置，包括文件绑定、总开关、联网开关和调查指引。文件副本可以共享，分支之后独立修改。新分支沿用继承的 R 编号进度。

重生成、修改本轮输入、重新开始失败回合或切换剧情进度时，撤销该分支旧调查与未交付报告；原进度失败续接可保留调查。销毁在存储层先撤权，迟到响应不能恢复任务或交付结果。已进入剧情历史的报告随对应版本恢复；其他分支不受影响。

## 记录与导入导出

「调查」页展示实际模型、状态、请求次数、累计运行时间和接口用量，完整过程按需展开分页；展开详情不把过程送入主上下文。会话列表显示其他对话尚存的调查者。存活、暂停、待复用调查的完整进度受保护；销毁后的详细过程按共享日志保留天数／容量清理，报告和已提交剧情保留，参考文件不作为缓存清理。

完整备份包含参考文件副本和索引。个人数据包保留来源设置、调查进度及记录，用户可选择是否携带参考文件。导入时重建携带文件的索引、重映射身份，标明缺失的副本。缺少可用来源的分支导入后总开关为关闭。导入的调查保持暂停并保留用量，固定来源齐备后才可继续；云端不透明状态从完整记录重建。

数据库 schema 30 与个人数据包 version 18 支持联网配置和无文件调查。升级前执行只读格式检查与数据库备份。旧分支的总开关沿用原委派状态，旧分支和任务的联网权限默认关闭。

## 接口

调查者沿用可逆的模型数据视图：长身份以 `@D` 短编号进入模型。文件检索参数、用户查看的过程和交付报告由 Runtime 还原；文件坐标始终对应原文，不能按投影后的文本长度推算。网页读取只还原调查指引或联网工具提供的完整来源网址。剧情模型与调查者各自持有映射，不复制主故事上下文；送达剧情模型的报告与运行状态同样经剧情模型的视图投影。

- `GET /api/sessions/{sid}/novel` 返回已保存的总开关 `authorized`、当前能否委派 `enabled`、来源可用性 `can_enable`、`web_enabled`、`web_guidance`、文件历史和调查记录。任务的 `source` 可为空；联网授权与指引记录在任务内。`GET .../novel/jobs?before=<R数字部分>` 分页回查历史。
- `POST .../novel/source?filename=...&encoding=utf-8&expected_revision=...` 接收 `application/octet-stream` 文件体，流式限制 64 MiB。`PATCH .../novel` 使用独立的 `expected_revision`，可更新 `enabled`、`web_enabled`、`web_guidance` 或用 `unbind` 解绑文件。
- `PATCH .../novel/advisor` 使用同一绑定的 `expected_revision` 和 `enabled` 设置参谋授权。状态中的 `advisor_enabled` 是参谋授权，`advisor_model_selection` 是参谋模型的对话级选择，空值表示沿用全局设置。
- `GET .../novel/sources/{source_id}/text?start=0&length=8000` 为用户按范围查看副本，`.../download` 下载原始文件；仅允许当前分支的文件历史，不是主模型工具。
- `GET .../novel/jobs/{ref}/trace?after=0` 分页查看原始过程与报告；`POST .../novel/jobs/{ref}/pause|resume|destroy` 明确管理调查者，`POST .../novel/stop-all` 同时停止当前剧情生成和运行中的调查。
- `GET /api/novel/activity` 与可重连的 `GET /api/novel/events` 提供跨对话状态。界面用 `GET /api/activity/events` 合用一条连接接收调查状态和日文词典进度，为多标签页下的预览、取消等请求留出连接。前端不轮询模型任务，不因展开面板而调用模型。
