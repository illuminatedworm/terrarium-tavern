# 模型输入的数据边界

模型负责理解剧情、判断变化、选择依据和编辑语义内容；程序负责身份、版本、指纹、摘录、转换与提交。模型业务输入只包含完成任务所需的数据，长期存储和协议身份由运行时管理。

## 请求路线

| 路线 | 模型可见内容 | 运行时保留内容 |
|---|---|---|
| Half Agent Writer／脚本生成 | 角色、已准入设定（用户开启时附条目标题）、自然语言记忆、剧情（不自动添加 H 位置行，原文中的编号文本保留）和实际状态 | 消息身份、世界书身份、诊断、初始化账本、schema 与展示缓存 |
| Tracker 记忆任务 | H 消息与片段编号的原文、本批／背景 H 范围、R 旧记录、E 辅助资料与语义字段 | 消息 ID、指纹、设定版本、摘录和新增永久身份 |
| 归档召回筛选（可选） | A 编号的候选内容、人物、故事时间与性质，最近一次交流和当前输入 | 归档记录 ID、来源与指纹 |
| Tracker 授权维护 | 世界书正文、历史 H 引用、记忆、实际变量与可逆角色视图 | 准入／冷却状态、长身份、哈希及提交状态 |
| 制卡 agent | 卡片与引用世界书的内容、C 编号、短路径、@D 引用和校验结果 | 世界书库 ID 与修订号、长身份、指纹与精确恢复映射 |
| Full Agent | 当前窗口（仅用户消息前有 `[H]` 位置行）、由程序标注覆盖范围的 handoff 章节与当前交接（要点可选 H 引用，C 用于章节操作）、规划和按需工具结果 | 存储身份、来源指纹、检索与事务状态 |
| 参谋 agent | 当前故事参考、咨询记录和按需工具结果 | 来源锚点、版本、咨询进度与偏好提交状态 |
| Embedding／Reranker | 正文、标题、关键词及查询 | 索引身份、向量关联键和版本哈希 |
| 模型连接检查 | 探测文字与返回要求 | 剧情、角色和业务身份 |

原始存档、快照、资源、日志和前端编辑 API 保留完整数据。原生工具调用 ID 用于传输关联，不属于模型需要复制或生成的业务身份。Full Agent 的逐类可见性见[数据表](full-agent.md#模型可见数据)。

## 状态投影

[core/model_view.py](../../src/tavern/core/model_view.py) 的 `state_for_model` 生成请求视图，不修改源状态：

- 根部 `initialized_lorebooks`、`schema`、`display_data` 和 `delta_data` 留在运行时。
- 递归排除 `$internal`、`$meta`、`$arrayMeta` 和 MVU 扩展占位值。
- 实际剧情变量和平铺状态保留。

Writer 编译、模型文本宏、Tracker 状态读取、MVU 输入和记忆辅助资料共用此视图。MVU 校验仍访问完整 schema 和初始化记录。

## 来源短编号

H 是当前分支消息位置（开场白为 H1），Half Agent 的 Tracker、Full Agent、参谋 agent 与剧情界面共用 [history_refs.py](../../src/tavern/core/history_refs.py) 的同一定义，Writer 请求不自动添加 H 编号；`H41-H50` 表示连续闭区间，`H52#3` 表示 H52 的第 3 个原文片段。H 只是渲染形式，存档仍保存消息 ID、指纹与逐字摘录。Tracker 的 H 片段指向原文，R 指向已有记忆，E 指向参考资料。模型通过 `write_memory` 的 `operations/questions` 提交语义增量，程序恢复真实消息、原文摘录与指纹。只有本次实际展示的片段可以引用，完整协议见[记忆设计](memory-consistency.md#短编号输出协议)。

Tracker 的 `search_lore` 返回命中的启用条目名称和完整正文，不提供 L 编号，不改变 Writer 的注入选择。设定修改后 Runtime 重新检索。Full Agent 的 `recall_lore` 也直接返回正文，其可选 L 编号仅标识资料，详见[工具参考](../reference/full-agent-tools.md)。

短编号投影、恢复和来源校验均在本地执行。它们不决定是否增加模型调用；任务请求额度由各模式运行时管理。编号和包装仍计入输入 tokens。

## 可逆角色视图

制卡 agent 与 Tracker 授权角色编辑使用 `ModelView`：结构化长身份、不透明键及源代码内的 UUID／长十六进制标记转为 @D 编号；`fingerprint`、`checksum`、`sha256` 和 `_hash` 等字段隐藏。完整映射不交给模型，也不写回卡片。

Tracker 的映射只属于本次操作。制卡 agent 将映射与完成的请求记录一起保存在编辑上下文中，使跨轮原生回复中的编号保持含义；模型/配置重建时保留可恢复的映射；新输入字面编号冲突时重新分配并从原文建立基线。

| 编辑情况 | 恢复规则 |
|---|---|
| JSON Pointer 路径含 `/` 或 `~` | 逐段解码、恢复和转义，保持原键边界 |
| 替换父对象 | 保留被投影隐藏的字段 |
| 数组重排 | 按身份保留对应元数据 |
| 数组插入 | 新项不继承相邻旧项的身份 |
| 新增世界书条目 | 可省略 ID，由程序生成 |
| 未知 @D 或修改隐藏哈希 | 拒绝本次工具修改 |
| 源代码中的身份标记 | 在应用编辑前精确恢复，不模糊匹配 |

资料先完成身份投影，再生成搜索摘要或工具结果；完整读取仍返回全文。搜索、续答和校验错误使用同一视图。开场通过 `set_opening` 编辑完整原文，适配范围见[世界书用途与初始化](../guides/card-author.md#世界书用途与初始化)。

制卡 agent 在调用网页服务前恢复 `web_search` 的 `query`、`objective` 和 `read_webpage` 的 `url`，返回结果继续使用同一视图投影。恢复限定在这两个网页工具的服务调用入口，不对全部工具参数统一展开。

## 验证边界

[test_model_data_boundary.py](../../tests/backend/test_model_data_boundary.py)及编辑专项检查最终业务 messages、工具结果、字段隐藏、编号恢复、父对象替换、数组操作和路径转义。检查覆盖最终模型可见数据与持久化结果。

程序能校验引用存在、权限和数据结构，无法仅凭合法编号证明模型理解正确。语义质量与实际输入成本需要另行评估，见[验证说明](../development/validation.md#检索与模型质量评估)。
