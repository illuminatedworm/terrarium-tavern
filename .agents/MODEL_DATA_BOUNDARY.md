# 模型与程序的数据职责

本文件约束所有模型请求路线的业务输入、工具结果与回写。各路线当前实际可见字段见 [模型输入的数据边界](../docs/design/model-data-boundary.md)。

程序负责身份映射、摘录定位与来源校验，模型负责语义判断。**减轻模型的智能负担并节省 tokens 是硬性设计要求。**

- 严禁把数据库主键、UUID、长随机ID、内容哈希、指纹、版本摘要、缓存键及无关运行元数据直接放进模型的业务提示、工具正文或要求模型回写。该规则覆盖 Writer、Tracker 各模式、MVU、Card Author、脚本嵌套请求，不能只修一个默认提示词。
- 先删掉任务不需要的字段；确需引用时用请求/操作内的短编号，由 Runtime 维护映射和生命周期。真实ID、原文摘录、指纹、版本及新增持久ID均由程序回填/生成。不得让模型算哈希、重建长ID、机械抄写引文以完成程序本可确定的匹配。
- 模型只判断内容、关系、变化和应选择哪项依据；程序负责数据定位、校验、机械转换和提交。JSON Patch 的必要语义路径可以保留；路径中的不透明键仍用短编号恢复。替换父对象不能丢失被隐藏的内部字段或把短编号写进存档。
- 不能为了省 tokens 截掉必需正文、删除用户源文件里的实际语义内容或降低分支/来源/事务校验。对必须编辑的代码或数据，采用可逆视图，应用修改前由程序恢复；指纹只在程序侧核对。
- 工具结果、错误消息、多次工具续答与复核都要守同一边界。先投影，再完整返回；禁止原始ID经错误信息或完整对象回传泄漏。传输协议必需的工具调用关联由适配器维护，不得作为需要模型抄写的业务字段。
- 验证必须检查最终业务 messages 及工具续答正文，而不只是提示词常量；用含真实形态长ID/哈希的隔离夹具验证“出站无机械字段、入站可正确恢复、持久数据不变、无效短编号拒绝”。新请求路线必须同时说明模型真正需要哪些字段。
