# 召回、上下文窗口与请求缓存

本文件约束世界书检索、上下文编译、窗口与 compact、记忆覆盖、token 计数和模型请求编排。当前实现见 [上下文生命周期](../docs/design/context-lifecycle.md)、[记忆一致性](../docs/design/memory-consistency.md)、[计数口径](../docs/guides/token-counting.md) 和 [缓存控制](../docs/design/cache-control.md)。

## 召回与准入

- 世界书检索坚持宁缺毋滥；合法零命中应保持为空。通过检索与规则选中的每个条目必须完整注入，不因长度或总 token 预算而遗漏。
- 关键词、BM25、向量及递归候选统一准入；排名融合不等于相关性置信度。
- 递归不能绕过拒绝结论，旧冻结条目不能持续扩展；通道失败不降低门槛或补满弱匹配。
- 上下文编译只消费已准入结果，保留注入证据和过滤原因；超长只记录提示，不做内容降级。
- 检索改动检查最终模型请求中的注入结果，相关时考虑困难负例、零命中、递归拒绝与通道降级。

## 窗口与记忆覆盖

- Half Agent 本地滚动窗口中，中途世界书与剧情共同计入窗口，按完整交流边界退出；保留最近两次交流与当前输入。用户选择云端 compact 时改用完整交流压缩，当前输入及当轮锚定资料保持原文。
- Half Agent 本地退出剧情前必须验证记忆覆盖，云端 compact 只代替 Writer 窗口裁剪、不代替 Tracker 记忆，切回本地也须补齐必要覆盖。云端压缩、已整理范围与本地已退出范围独立，世界书设定不能被归档为已发生事实。
- 周期记忆失败且无需裁剪时可继续正文，但须显著提示；必须裁剪而覆盖不足时阻止正文请求。

## Token 计数与单位

- 正文、后台记忆、配方块、窗口压力和最终请求检查统一使用分词器 token 计数，计入相应消息与工具开销。
- 估算 tokens 与服务商实际 tokens 分开；未知模型的参考分词器必须明示，不得以字节或字符冒充 tokens。
- 字符限额、BM25 词元、消息条数、磁盘字节各自标明单位；预算应计算宏展开后的实际内容。
- 预览保持只读并说明不完整性；正常对话不隐式下载、加载或无限重试神经模型。

## 模型请求与缓存

- 修改模型请求编排时，重视缓存命中率，尤其是 prefix cache；优先保持规则、角色资料、常驻世界书和工具定义等请求前缀稳定。
- 检查每轮变化的消息与工具说明在实际请求中的位置，并用编译后的消息顺序验证调整。
